13Term rewriting, e-graphs and lambda calculus

tinygrad's optimizer is a pattern-matching rewrite engine over a graph IR (UOps and PatternMatcher); e-graphs are the principled version of that idea. Lambda calculus gives you the formal vocabulary for substitution, binding and evaluation order that rewriting depends on.

about 25–40 h · difficulty ●●●●○

After this module you can

  • After this module you can implement a term-rewriting engine with pattern matching and confluence-aware rule sets.
  • After this module you can build an e-graph with hash-consing, union-find, rebuilding and equality saturation.
  • After this module you can extract optimal terms from an e-graph with a cost model.
  • After this module you can relate tinygrad's pattern matcher and graph rewrites to these formal foundations.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Stanford Encyclopedia of Philosophy: The Lambda Calculus, sections 1-2

    Read sections 1-2 for syntax, alpha/beta reduction and free variables. Skip the logic-heavy later sections.

  2. Do

    Write a lambda calculus interpreter with capture-avoiding substitution

    In Python, implement terms, substitution and normal-order reduction; encode Church numerals and verify 2+3=5.

  3. Watch

    egg: Fast and Extensible Equality Saturation (POPL 2021 talk)

    Watch for the core ideas: e-classes, rebuilding, equality saturation, extraction.

  4. Read

    egg paper: Fast and Extensible Equality Saturation

    Read sections 1-3 and 5; skim the case studies. Note how rewrite ordering problems disappear.

  5. Do

    egg tutorial (Rust docs) -- or reproduce in Python

    Follow the tutorials, or implement a tiny e-graph in Python (union-find, hashcons, rebuild) for arithmetic with rules like x*2 -> x<<1.

  6. Read

    tinygrad PatternMatcher / UOps docs

    Read how tinygrad represents programs as UOps and rewrites them with UPat patterns; this is the target design for your compiler.

  7. Do

    Write a pattern-rewrite engine for an expression DAG

    Study the UPat/PatternMatcher classes, then implement your own: patterns with wildcards, a fixed-point graph_rewrite, and rules for constant folding and algebraic simplification.

  8. Build

    Compare greedy rewriting vs equality saturation

    Run the same rule set through your greedy rewriter and your e-graph on 10 expressions; record where greedy gets stuck in a worse local optimum.

Build

A Python rewrite toolkit with (1) a PatternMatcher-style greedy rewriter over a hash-consed expression DAG and (2) a mini e-graph with equality saturation and cost-based extraction, both applied to arithmetic/tensor-index expressions, with a report showing cases where saturation finds better results than greedy rewriting.

Portfolio project: Equality-saturation optimizer for tensor expressions

Build an e-graph optimizer for a small tensor algebra (matmul, add, transpose, reshape, elementwise ops) with rewrite rules such as transpose fusion, matmul associativity and distributivity. Use a FLOP/memory cost model for extraction and show it finds better orders for matrix-chain and attention-like expressions than a naive left-to-right evaluator.

Deliverables

  • repo with e-graph core (union-find, hashcons, rebuild), 15+ rules, and cost-based extraction
  • README with plots of e-graph size vs iterations and FLOP reductions on 10 test expressions, with numerical-equivalence checks in NumPy
  • a 600–1200 word write-up explaining equality saturation, rule explosion control, and extraction tradeoffs

Rubric

Solid
Finds the optimal matrix-chain order on all test cases with verified numerical equivalence; saturates or hits limits gracefully.
Exceptional
ILP or DP-based extraction compared with greedy, a comparison against egg on the same rules, and a rewrite rule correctness checker (random testing or SMT).

References: egg: Fast and extensible equality saturation, egg source

If you get stuck

  • Rewrite loops (a+b -> b+a forever) mean you need either a termination ordering or an e-graph instead of destructive rewriting.
  • E-graph blowup: set node/iteration limits and inspect which rule explodes (associativity + commutativity together is the usual culprit).
  • Forgetting to rebuild (restore congruence) after unions gives wrong results; follow the egg paper's deferred rebuilding.
  • Greedy extraction is not optimal with shared subterms; know this before trusting results.
  • Lambda calculus substitution bugs are almost always variable capture: use de Bruijn indices or fresh-name generation.

Ready to move on when

  • Your substitution correctly avoids capture in (\x.\y.x) y
  • Church numeral addition and multiplication reduce to the right normal forms
  • Your e-graph proves (a*2)/2 == a with rules a*2=a<<1, (a*b)/c=a*(b/c), b/b=1, a*1=a
  • graph_rewrite reaches a fixed point and does not loop on commutativity rules

Going deeper (optional)

  • egglog — Datalog + e-graphs; the newer system behind several tensor compiler projects.
  • Term Rewriting and All That (Baader & Nipkow) — Theory of confluence and termination.
