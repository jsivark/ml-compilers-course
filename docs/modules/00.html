00Orientation and toolkit

Every later module assumes you can use a terminal, version your work with git, debug C, rebuild a Python environment and read papers efficiently. Set this up once here so it does not slow you down later. The repo you create holds every module's work.

about 10–15 h · difficulty ●○○○○

After this module you can

  • Write shell pipelines and small bash scripts, locally and over ssh.
  • Use git branches and tags, and recover from a bad merge with git reflog.
  • Compile C with -g and -fsanitize=address and find a crash with gdb or lldb.
  • Rebuild your Python environment from a lockfile.
  • Read a paper with Keshav's three-pass method and write a five-sentence summary.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    Missing Semester 2020, Lecture 1: Course overview + the shell

    Windows users: install WSL2 first (next step) and work inside it. Do the exercises at the bottom of the page.

  2. Do

    Install WSL2 (Windows only)

    Run `wsl --install`, then keep your course files inside the Linux filesystem (~/), not /mnt/c, or builds will be slow. macOS users: install Xcode Command Line Tools and Homebrew instead.

  3. Watch

    Missing Semester 2020, Lecture 2: Shell Tools and Scripting

    Focus on pipes, find, grep and writing a small bash script with set -euo pipefail. Later modules use scripts like this for benchmark sweeps.

  4. Watch

    Missing Semester 2020, Lecture 3: Editors (Vim)

    You do not need to switch to Vim. Learn enough to edit files over ssh on a remote machine, and set up your main editor with clangd and a Python language server.

  5. Watch

    Missing Semester 2020, Lecture 6: Version Control (Git)

    Understand the data model (blobs, trees, commits, refs) rather than memorizing commands.

  6. Do

    Learn Git Branching: Main tab Introduction Sequence, Remote tab first two levels

    Interactive drills for commit, branch, merge, rebase and remotes. Then use one branch per module and tag each finished module.

  7. Read

    Pro Git, ch. 2 Git Basics, ch. 3 Git Branching, sections 7.3 Stashing and 7.10 Debugging with Git

    Use as a reference when something goes wrong. Learn git log --oneline --graph, git stash and git bisect.

  8. Watch

    Missing Semester 2020, Lecture 7: Debugging and Profiling

    Covers printf debugging, gdb and pdb, perf and flame graphs. Modules 1-3 use all of these.

  9. Do

    C toolchain + debugger: GDB docs or the LLDB tutorial

    Install clang (or gcc) and make. Compile a buggy program with -g -O0 -fsanitize=address, then set a breakpoint, step, print a variable and get a backtrace. Linux users can use gdb instead (https://www.gnu.org/software/gdb/documentation/).

  10. Do

    Python environment with uv (or venv)

    Create one project environment with numpy, matplotlib, pytest and torch (the CPU build is enough). Commit uv.lock or requirements.txt.

  11. Read

    S. Keshav, How to Read a Paper

    A short paper. Use the three-pass method on each paper in this course and keep a one-paragraph summary per paper in your repo.

  12. Read

    Julia Evans, How to ask good questions

    Before asking anyone for help, write down what you tried, the exact error and a minimal reproduction.

  13. Do

    Join the GPU MODE community

    A Discord server for GPU kernel and ML systems work; its talks are also on YouTube. Read the pinned messages before posting.

  14. Do

    Start a learning log (Julia Evans, Get your work recognized: write a brag document)

    Keep LOG.md in your repo with one dated entry per session: what you did, what confused you, what you will do next. Write a short public post at the end of each module.

Build

A public GitHub repo `ml-compilers-log` with a README (goals, schedule, hardware), LOG.md, a modules/ directory, a Makefile target that compiles and runs a sanitized C hello-world, a pytest that passes, and a GitHub Actions CI workflow that runs both on every push.

Portfolio project: Public course repo + first blog post

Set up the repository that will hold every module's work and portfolio project for the whole course, with CI from day one. Publish a first blog post (GitHub Pages, a personal site, or similar) titled something like 'Why I'm building an ML compiler from scratch', stating your goals, your starting point, and a dated plan for the course.

Deliverables

  • repo with README, LOG.md, Makefile, a sanitized C test and a pytest, all green in GitHub Actions
  • a short CONTRIBUTING-style note to yourself: branch-per-module, commit message conventions, how to tag a finished module
  • a 600–1000 word blog post on your goals and plan, linked from the README

Rubric

Solid
CI passes on push; README states the plan; LOG.md has at least 3 dated entries; blog post is published and linked.
Exceptional
Reproducible environment (uv.lock or a devcontainer) that CI builds from scratch, and a `make bench` target that writes timings to CSV for use in later modules.

References: Missing Semester 2020, Lecture 6: Version Control (Git)

If you get stuck

  • WSL slow or files missing: keep the repo under ~/ in Linux, not /mnt/c; open it with `code .` from WSL.
  • macOS 'gdb' won't run: use lldb, which ships with the Xcode Command Line Tools; the commands map almost one to one (lldb's GDB-to-LLDB command map helps).
  • git 'detached HEAD' or a messy merge: run `git status` and `git log --oneline --graph --all` before anything else; `git reflog` can recover almost anything.
  • Limit tooling setup (dotfiles, themes) to two evenings, then start Module 1.
  • Pip and conda in the same env cause mysterious import errors: pick one tool (uv recommended) and one env per project.

Ready to move on when

  • Write a one-line shell pipeline that prints the 5 largest files under a directory.
  • Explain the difference between a commit, a branch and a tag in git's data model.
  • Use gdb or lldb to find the line of a segfault in a 20-line C program without adding printfs.
  • Recreate your Python environment from scratch on a clean machine (or container) from your lockfile alone.
  • Summarize a paper after Keshav's first pass in five sentences (the five Cs).
