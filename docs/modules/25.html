25GPU backend

GPUs reward a different mapping: GLOBAL/LOCAL axes onto grids and blocks, shared memory and barriers. Elementwise and reduce kernels must hit memory bandwidth, which is what most of a real model's kernels are bound by.

about 35–50 h · difficulty ●●●●○

After this module you can

  • After this module you can generate CUDA kernels from your IR and compile them with NVRTC.
  • After this module you can map loop nests to grids and blocks, and use shared memory with barriers correctly.
  • After this module you can write bandwidth-bound kernels that reach a high fraction of DRAM peak.
  • After this module you can profile kernels with Nsight Compute and read the key metrics.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    CUDA Programming Guide ch. 'Programming Model' and 'Performance Guidelines' (memory)

    Thread hierarchy, shared memory, __syncthreads, coalescing.

  2. Watch

    GPU MODE Lecture 8: CUDA Performance Checklist

    Coalescing, occupancy, memory-bound vs compute-bound.

  3. Implement

    CUDA renderer + NVRTC via cuda-python

    Map GLOBAL to blockIdx, LOCAL to threadIdx, addrspace=LOCAL to __shared__, barrier to __syncthreads(). Use https://nvidia.github.io/cuda-python/ for NVRTC and launch.

  4. Read

    tinygrad CUDARenderer and gpudims

    CUDARenderer, then group_gpudims (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/codegen/gpudims.py#L44) for folding ranges into grid dims.

  5. Test

    All earlier tests on GPU

    Run weeks 1-7 through the CUDA backend; diff against C.

  6. Watch

    GPU MODE Lecture 9: Reductions

    Tree reductions, warp shuffles, avoiding divergence.

  7. Read

    Mark Harris, Optimizing Parallel Reduction in CUDA (kernels 1-7)

    Each of the 7 reduction versions; generate kernel 4-6 style code.

  8. Read

    Maharshi, Optimizing softmax in CUDA: kernels 1 to final

    Naive, online softmax, shared-memory reduction, warp-shuffle; reproduce each rung, then make your compiler emit the fastest.

  9. Implement

    Reduce/elementwise schedules for GPU

    Vectorized loads (float4), grid-stride, warp shuffle reduce emitted from your IR.

  10. Measure

    Bandwidth with Nsight Compute

    Report achieved DRAM throughput % for elementwise and reduce; target >= 70%.

  11. Test

    10 own tests

    Non-multiple-of-block sizes, barrier correctness, reduce of odd lengths.

Build

A CUDA backend via NVRTC with grid/block mapping, shared memory, barriers, and bandwidth-bound elementwise/reduce kernels.

Portfolio project: GPU kernel lab: bandwidth and reduction kernels near hardware peak

Make your compiler's generated elementwise, reduce and softmax kernels approach the GPU's memory roofline, with every step justified by an Nsight Compute metric. Publish a step-by-step optimization log in the style of a public kernel blog post, with the generated code at each step.

Deliverables

  • repo with the kernel generator flags for each optimization step and an ncu-driven benchmark script
  • README with achieved GB/s vs peak for each kernel and step, plus ncu screenshots or exported metrics
  • comparison against PyTorch's kernels for the same ops and sizes
  • a 600–1200 word write-up explaining each step's bottleneck and the metric that revealed it

Rubric

Solid
Elementwise and reduce reach 80%+ of measured DRAM bandwidth; softmax correct and within 1.5x of PyTorch.
Exceptional
Reaches 90%+ of bandwidth; fused softmax beats PyTorch at some sizes; the write-up is good enough that you would publish it as a blog post.

References: Nsight Compute Profiling Guide, Simon Boehm, How to Optimize a CUDA Matmul Kernel

If you get stuck

  • Wrong results only at large sizes: grid-stride or bounds check missing for the last partial block.
  • Race conditions: __syncthreads() missing between shared-memory write and read, or placed inside divergent code.
  • Low bandwidth: uncoalesced access. Make consecutive threads touch consecutive addresses; check the ncu memory workload section.
  • Reductions wrong: tree reduction assumes power-of-two block size, or warp shuffles use the wrong mask.
  • Timing includes NVRTC compile or host copies: time with CUDA events around the launch only, after warm-up.

Ready to move on when

  • All earlier tests pass on the GPU
  • Elementwise and reduce >= 70% of memory bandwidth in Nsight Compute
  • Softmax ladder reproduced and the fastest variant generated by your compiler
  • 10+ new tests
