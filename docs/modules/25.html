25GPU backend

GPUs need a different mapping: GLOBAL/LOCAL axes onto grids and blocks, plus shared memory and barriers. Elementwise and reduce kernels are memory-bound, so the target is a fraction of DRAM bandwidth.

about 35–50 h · difficulty ●●●●○

After this module you can

  • Generate CUDA C from your IR and compile and launch it with NVRTC through cuda-python.
  • Map GLOBAL axes to blockIdx and LOCAL axes to threadIdx, with __shared__ buffers and __syncthreads() placed correctly.
  • Get elementwise and reduce kernels to >= 70% of DRAM bandwidth, as reported by Nsight Compute.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    CUDA Programming Guide §2.3 Writing SIMT Kernels (2.3.2-2.3.4)

    2.3.2 Thread Hierarchy (incl. block synchronization), 2.3.3 memory spaces (shared memory), 2.3.4 Memory Performance (coalescing, shared-memory access patterns).

  2. Watch

    GPU MODE Lecture 8: CUDA Performance Checklist

    Speaker Mark Saroufim. Run the repo's coalesce.cu, occupancy.cu, divergence.cu, tiling.cu and coarsening.cu and note each timing.

  3. Implement

    CUDA renderer + NVRTC via cuda-python

    Map GLOBAL to blockIdx, LOCAL to threadIdx, addrspace=LOCAL to __shared__, barrier to __syncthreads(). Use https://nvidia.github.io/cuda-python/ for NVRTC and launch.

  4. Read

    tinygrad CUDARenderer and gpudims

    CUDARenderer, then group_gpudims (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/codegen/gpudims.py#L44) for folding ranges into grid dims.

  5. Test

    All earlier tests on GPU

    Run weeks 1-7 through the CUDA backend; diff against C.

  6. Watch

    GPU MODE Lecture 9: Reductions

    Speaker Mark Saroufim. Read simple_reduce.cu, control_divergence_reduce.cu, shared_reduce.cu and reduce_coarsening.cu in order.

  7. Read

    Mark Harris, Optimizing Parallel Reduction in CUDA (kernels 1-7)

    The PDF's 7 reduction kernels; make your compiler generate code in the style of kernels 4-6.

  8. Read

    Maharshi, Learning CUDA by optimizing softmax: A worklog

    Worklog on a GTX 1050Ti for a 1024x32768 fp32 softmax, starting from a PyTorch baseline. Reproduce each kernel, then make your compiler emit the fastest one.

  9. Implement

    Reduce/elementwise schedules for GPU

    float4 loads, grid-stride loops and warp-shuffle reduction, emitted from your IR.

  10. Measure

    Bandwidth with Nsight Compute

    Report achieved DRAM throughput (% of peak) in ncu for elementwise and reduce; target >= 70%.

  11. Test

    10 own tests

    Non-multiple-of-block sizes, barrier correctness, reduce of odd lengths.

Build

A CUDA backend via NVRTC with grid/block mapping, shared memory, barriers, and bandwidth-bound elementwise/reduce kernels.

Portfolio project: GPU kernel lab: bandwidth and reduction kernels near hardware peak

Take three compiler-generated kernels, fp32 elementwise add on 2^28 elements, sum-reduce on 2^28 elements, and row softmax on 1024x32768, from the naive version toward the DRAM roofline. Justify each optimization step with an Nsight Compute metric and keep the generated code for every step.

Deliverables

  • repo with generator flags for each optimization step and an ncu-driven benchmark script
  • README with achieved GB/s vs measured peak for each kernel and step, with exported ncu metrics
  • comparison against torch.add, torch.sum and torch.softmax at the same sizes
  • a 600-1200 word write-up naming each step's bottleneck and the metric that showed it

Rubric

Solid
Elementwise and reduce reach 80% of measured DRAM bandwidth; softmax correct and within 1.5x of torch.softmax.
Exceptional
90% of bandwidth on elementwise and reduce; softmax matches or beats torch.softmax at 1024x32768.

References: Nsight Compute Profiling Guide, Simon Boehm, How to Optimize a CUDA Matmul Kernel

If you get stuck

  • Wrong results only at large sizes: grid-stride or bounds check missing for the last partial block.
  • Race conditions: __syncthreads() missing between shared-memory write and read, or placed inside divergent code.
  • Low bandwidth: uncoalesced access. Make consecutive threads touch consecutive addresses; check the ncu memory workload section.
  • Reductions wrong: tree reduction assumes power-of-two block size, or warp shuffles use the wrong mask.
  • Timing includes NVRTC compile or host copies: time with CUDA events around the launch only, after warm-up.

Ready to move on when

  • All earlier tests pass on the GPU
  • Elementwise and reduce >= 70% of memory bandwidth in Nsight Compute
  • Softmax ladder reproduced and the fastest variant generated by your compiler
  • 10+ new tests
