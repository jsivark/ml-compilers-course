27Multiple GPUs, sharding

Sharding is a type on buffers and collectives are just ops your compiler inserts. Data and tensor parallelism fall out of propagating that annotation.

about 30–45 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Add shard annotations to buffers and propagate them through elementwise, reduce and movement ops.
  • Insert all-reduce and all-gather automatically and match single-device outputs.
  • Run data-parallel MNIST and a Megatron-style tensor-parallel MLP, and report speedup and communication fraction on 2 GPUs.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Scaling Book: Sharded Matrices and How to Multiply Them

    The sharding notation, then Case 1-4 of sharded matmul and the collective each case needs.

  2. Read

    Scaling Book: How to Parallelize a Transformer for Training

    Data parallelism, FSDP and tensor parallelism; note which collective each needs.

  3. Implement

    shard annotation and propagation

    Add shard=axis to buffers; propagate through elementwise, reduce and movement ops.

  4. Read

    tinygrad multi.py: alu_multi, reduce_multi, reshape_multi

    How sharding propagates per op (alu_multi at line 90); reduce_multi (line 107) emits allreduce when a sharded axis is reduced.

  5. Implement

    Collective insertion pass

    Insert all-reduce after reductions over a sharded axis and all-gather when an unsharded consumer needs the full tensor.

  6. Read

    NCCL user guide: Collective Operations

    AllReduce, AllGather and ReduceScatter semantics; call NCCL via ctypes.

  7. Implement

    Data-parallel MNIST on 2+ GPUs

    Shard the batch, all-reduce gradients, match single-GPU loss curve.

  8. Read

    Megatron-LM §3 Model Parallel Transformers

    Column-parallel then row-parallel MLP with one all-reduce in the forward pass.

  9. Implement

    Tensor-parallel matmul

    Shard weights column/row-wise; check vs single GPU.

  10. Implement

    LLM Training Puzzles

    8 puzzles on distributed training primitives in a Colab notebook; do them all.

  11. Measure

    Scaling efficiency

    Report speedup on 2 GPUs vs 1 and comms time fraction.

Build

A shard annotation, a collective insertion pass, data-parallel MNIST and a tensor-parallel matmul.

Portfolio project: Sharding planner with a communication cost model

Skill project

For a 4-layer MLP (hidden 4096) and one stories15M-shaped transformer block, have your compiler search over data, tensor and mixed shardings on 2-4 devices using a cost model of FLOPs and collective bytes. Run the chosen plan and compare predicted vs measured step time. Use simulated CPU ranks if you have one GPU.

Deliverables

  • repo with the planner, cost model and a multi-process runner (multi-GPU or simulated)
  • README with predicted vs measured step time per plan and scaling efficiency from 1 to N devices
  • measured collective bandwidth (nccl-tests or your own) feeding the cost model
  • a 600-1200 word write-up on when tensor parallel beats data parallel for these two models

Rubric

Solid
Planner picks the measured-best plan for both models; outputs match single-device; scaling efficiency reported.
Exceptional
Cost model within 15% of measured step time; overlapping communication with compute gives a measured speedup.

References: Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism, nccl-tests

Help

If you get stuck

  • Sharded result is off by a factor of N: you all-reduced a value that was already replicated, or averaged instead of summed.
  • Hangs: ranks issue collectives in different orders. Make collective order deterministic from the graph.
  • No speedup: communication dominates. Measure bus bandwidth with nccl-tests and compare to your step time.
  • Only 1 GPU available: simulate ranks with processes on CPU (gloo-style) so the pass is still testable.

Ready to move on when

  • Data-parallel MNIST on >= 2 GPUs with compiler-inserted all-reduce
  • Tensor-parallel matmul matches single GPU
  • Scaling numbers reported
  • All earlier tests pass
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • tinygrad beautiful_mnist_multigpu.py (Data-parallel MNIST on 2+ GPUs)
    Data-parallel MNIST on tinygrad's shard API, the direct counterpart of the data-parallel lab.
  • huggingface/picotron (Tensor-parallel matmul; Sharding planner project)
    Minimal educational 4D parallelism (data, tensor, pipeline, context) in a few short files, written alongside the Ultrascale Playbook.
  • NVIDIA Megatron-LM (Tensor-parallel matmul)
    The reference column/row-parallel linear layers; compare with your tensor-parallel matmul and collective placement.
  • pytorch/torchtitan (Sharding planner project)
    PyTorch-native FSDP2, TP and pipeline parallel composed on a DeviceMesh, readable end to end.

Go deeper (optional)

Talks, papers, code and writing (18)

Lectures

  • JAX: Manual parallelism with shard_map · JAX team
    Per-device programs with explicit collectives; use it to check your inserted collectives against JAX on the same matmul.
  • Tensor Parallelism (UvA DL notebooks, Part 4.1) · Phillip Lippe
    Implements tensor parallelism for linear layers from first principles in JAX shard_map with runnable code; do it as the manual counterpart to compiler sharding.

Talks

  • Shardy: An MLIR-based Tensor Partitioning System (LLVM Dev Meeting 2024 slides) · Bart Chrzaszcz, Zixuan Jiang
    How the GSPMD and PartIR teams merged into an axis-based sharding representation with priority-driven propagation; compare with GSPMD's attribute propagation.

Papers

  • GSPMD: General and Scalable Parallelization for ML Computation Graphs · Xu et al.
    Sharding annotations plus propagation in XLA, the production version of your pass; read the propagation rules section.
  • Alpa: Automating Inter- and Intra-Operator Parallelism · Zheng et al.
    Formulates sharding choice as an ILP over a cost model, a direct template for the project's planner.
  • Mesh-TensorFlow: Deep Learning for Supercomputers · Shazeer et al.
    Early named-dimension sharding over a device mesh; read the layout and communication sections.
  • GPipe: Efficient Training of Giant Neural Networks using Pipeline Parallelism · Huang et al.
    Micro-batch pipeline parallelism and its bubble cost; adds a third axis to your planner.
  • PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel · Zhao et al.
    Engineering details of FSDP in production: prefetching, overlap and memory; read the system design section.
  • Demystifying NCCL: An In-depth Analysis of GPU Communication Protocols and Algorithms · Zhiyi Hu et al.
    Explains NCCL's Simple, LL and LL128 protocols and its ring and tree collectives at the primitive level; read the ring AllReduce section before writing your own allreduce.
  • SimpleFSDP: Simpler Fully Sharded Data Parallel with torch.compile · Ruisi Zhang et al.
    FSDP expressed as DTensor redistributes so the compiler sees the full compute plus communication graph; focus on the bucketing and reordering passes in Inductor.
  • AutoParallel: Composable, PyTorch-Native Automatic Parallelism for Production Training · Sanket Purandare et al.
    Recent compiler-side work that searches per-operator sharding placements, generalizing SimpleFSDP; read for how the search space and cost model are set up.
  • PartIR: Composing SPMD Partitioning Strategies for Machine Learning · Sami Alabed et al.
    PartIR's tactic-based partitioning and automatic search; read alongside Alpa as a different take on automating sharding.

Books

  • How to Scale Your Model: How to Think About GPUs · Austin et al. (Google DeepMind)
    GPU networking (NVLink, InfiniBand) and collective costs; use its bandwidth numbers in your cost model.

Blogs and articles

  • How to Train Really Large Models on Many GPUs? · Lilian Weng
    Survey of data, pipeline, tensor and expert parallelism with references; good map before reading primary papers.

Code to read

  • stas00/ml-engineering · Stas Bekman
    Practical notes from training large models; read the network and debugging chapters for multi-GPU failure modes.
  • DualPipe · DeepSeek
    Bidirectional pipeline schedule that overlaps compute and communication from DeepSeek-V3; read the schedule diagram in the README.

More reading

  • Ultra-Scale Playbook — Practical DP/TP/PP/ZeRO with measurements.
  • ZeRO — Optimizer state sharding.
