Part II · Bridge

11Compiling to machine code

Turning an AST into real assembly shows what every ML compiler ultimately emits. Nora Sandler's incremental blog series plus the test suite for her book give a tight loop: one language feature at a time, each checked by a few dozen tests.

about 40–60 h (10 blog parts at 3-5 h each, plus porting from 32-bit to x86-64) · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Lower a C-subset AST to x86-64 assembly that assembles, links and runs.
  • Implement the System V x86-64 calling convention, including stack arguments and 16-byte alignment.
  • Use the book test suite's stage flags to localize a failure to the lexer, parser, validator or code generator.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    x86 Assembly Guide (UVA CS216)

    The guide covers 32-bit x86 registers and mov/push/pop/call/ret; the test suite needs x86-64, so also compile tiny C programs on Compiler Explorer with x86-64 gcc -O0 and read the output.

  2. Do

    Install the test suite and run --check-setup

    Clone nlsandler/writing-a-c-compiler-tests and run './test_compiler --check-setup'. The suite follows the book's chapters, not the blog: it needs an x86-64 toolchain (native on Intel/AMD Linux and in WSL; Rosetta on Apple Silicon Macs; an x86-64 VM or container on ARM Linux), 'int main(void)', and the gcc-like driver plus --lex/--parse/--validate/--tacky/--codegen stage flags described in the README.

  3. Do

    Sandler Part 1: Integers -> run './test_compiler ./mycc --chapter 1'

    Lexer, parser and code emission for 'int main(void){return 2;}'. The blog emits 32-bit x86; Part 1 itself recommends adapting to 64-bit, and the suite requires it. Use --latest-only while iterating, then rerun without it to catch regressions.

  4. Do

    Sandler Part 2: Unary Operators -> run './test_compiler ./mycc --chapter 2'

    Add negation, bitwise complement and logical not. Each AST node maps to a short instruction template.

  5. Do

    Sandler Part 3: Binary Operators -> run './test_compiler ./mycc --chapter 3'

    Add + - * /. The blog rewrites the grammar into exp/term/factor levels; the chapter 3 tests also include % (mod.c). Intermediate values live on the stack (push/pop).

  6. Do

    Sandler Part 4: Even More Binary Operators -> run './test_compiler ./mycc --chapter 4'

    Add relational and short-circuiting && and ||, using labels and conditional jumps.

  7. Do

    Sandler Part 5: Local Variables -> run './test_compiler ./mycc --chapter 5'

    Introduce stack frames, base-pointer-relative variable slots and a variable map; reject undeclared and redeclared variables.

  8. Do

    Sandler Part 6: Conditionals -> run './test_compiler ./mycc --chapter 6'

    if statements and the ternary operator.

  9. Do

    Sandler Part 7: Compound Statements -> run './test_compiler ./mycc --chapter 7'

    Block scoping and shadowing; free stack space when a scope closes.

  10. Do

    Sandler Part 8: Loops -> run './test_compiler ./mycc --chapter 8'

    for, while and do loops plus break and continue; track the current loop's labels.

  11. Do

    Sandler Part 9: Functions -> run './test_compiler ./mycc --chapter 9'

    The blog uses the 32-bit cdecl convention; implement the x86-64 System V convention instead (first six integer arguments in registers, 16-byte stack alignment at call). The chapter 9 tests include 'libraries' cases that link your code with gcc-compiled C.

  12. Do

    Sandler Part 10: Global Variables (optional; chapter 10 tests need static/extern)

    File-scope variables in .data/.bss. The suite's chapter 10 tests also require static and extern, which the blog does not cover; treat chapter 10 as optional.

Build

mycc: a Python C-subset compiler (int returns, unary/binary/relational/logical ops including %, locals, if/ternary, blocks, loops with break/continue, functions) emitting x86-64 assembly and passing './test_compiler ./mycc --chapter 9', plus a README mapping each blog part to commit hashes.

Portfolio project: mycc, stage 1: Three-address IR and peephole pass for mycc, measured against naive codegen

Skill project

Insert a TACKY-style three-address IR between the AST and assembly, give each temporary a stack slot, and add a peephole pass (drop push/pop pairs, redundant movs, jumps to the next label). Measure static instruction counts of the emitted assembly on the suite's chapter 1-9 valid programs before and after.

Deliverables

  • repo with mycc, the IR stage, the peephole pass, and a script that counts emitted instructions per test program
  • README table: instructions per program for naive codegen, IR codegen, IR plus peephole, and gcc -O0
  • a 600–1200 word write-up on the IR design and which peephole rules paid off

Rubric

Solid
All chapter 1-9 tests still pass and total emitted instructions drop by at least 25% versus the naive stack codegen.
Exceptional
Also passes with --bitwise --compound, and comes within 1.2x of gcc -O0 instruction count on the chapter 9 valid programs.

References: writing-a-c-compiler-tests, QBE compiler backend (a small reference backend)

Help

If you get stuck

  • Segfault on call: rsp must be 16-byte aligned at the call instruction (System V ABI).
  • Values clobbered after a call: caller-saved registers (rax, rcx, rdx, rsi, rdi, r8-r11) are not preserved.
  • Blog examples use int main() and 32-bit registers; the suite expects int main(void) and x86-64.
  • The suite refuses native arm64. On Apple Silicon Macs run it and gcc under Rosetta ('arch -x86_64 zsh'), and remember Mach-O symbols need a leading underscore. On ARM Linux use an x86-64 VM or container. Intel/AMD Linux and WSL work as is.

Ready to move on when

  • './test_compiler ./mycc --chapter 9' passes with zero failures
  • The chapter 9 'libraries' tests pass, so mycc functions link with gcc-compiled C in both directions
  • You can draw the stack frame of a call with 8 int arguments and say which arguments are in registers and which are on the stack
  • Invalid programs (undeclared variable, break outside a loop) exit nonzero and write no assembly file
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • nqcc2 (reference compiler for the book) (chapters 1-9 against writing-a-c-compiler-tests)
    Nora Sandler's OCaml reference implementation for Writing a C Compiler, tagged per chapter and built against the same test suite and stage flags.
  • nqcc (blog-era compiler) (blog Parts 1-10)
    The original OCaml compiler that accompanies the 2017-2019 blog series, useful for checking the 32-bit codegen templates per part.
  • chibicc (Parts 2-9, especially System V calls)
    Rui Ueyama's C compiler with one small commit per feature emitting x86-64; walk its early history to compare how each operator, local and function call is lowered.
  • 8cc (Part 9 calling convention)
    Rui Ueyama's earlier self-hosting C compiler; gen.c shows a complete x86-64 System V argument-passing implementation.

Lectures

    Instruction selection, scheduling and graph-coloring register allocation in one deck.

Courses

  • Code Generation for Data Processing (WS 2025/26) · Alexis Engelke, TUM
    Recent lecture slides plus a script covering LLVM-IR, instruction selection, register allocation, JIT and vectorization; the register allocation and JIT lectures fit this module best.

Talks

  • CppCon 2017: Matt Godbolt "What Has My Compiler Done for Me Lately? Unbolting the Compiler's Lid" · CppCon
    Shows what gcc and clang actually emit for common C patterns at -O0 vs -O2; watch it before comparing mycc output to gcc.

Papers

  • An Incremental Approach to Compiler Construction · Abdulaziz Ghuloum
    The Scheme Workshop 2006 paper whose one-feature-at-a-time x86 method inspired Sandler's series; read the step list in section 2.

Books

  • Essentials of Compilation · Jeremy Siek
    An incremental compiler to x86-64 in Racket or Python with register allocation by graph coloring; chapters 2-4 extend what you built here.
  • Compiler Book (low-level programming with a C compiler) · Rui Ueyama
    The book that accompanies chibicc's step-by-step history (Japanese); the code samples are readable even with machine translation.
  • Optimization manuals · Agner Fog
    Manual 2 (optimizing assembly) and the instruction tables tell you what your emitted instructions cost on real CPUs.

Blogs and articles

  • Stack frame layout on x86-64 · Eli Bendersky
    Diagrams of the red zone, register arguments and spilled arguments, exactly what the 8-argument check question asks.
  • Linear scan register allocation on SSA · Max Bernstein
    A 2025 worked tutorial of Wimmer-Franz linear scan over SSA live ranges; use it when your compiler moves past stack-only codegen to real register allocation.
  • Cranelift, Part 1: Instruction Selection · Chris Fallin
    How a production backend lowers IR to machine instructions by tree matching; read it after you have a naive codegen to see what the next step looks like.
  • A New Backend for Cranelift, Part 1: Instruction Selection · Chris Fallin
    How a production code generator lowers IR to machine instructions by tree matching; read after Sandler part 9.
  • How the Optimizing Compiler Works: Back-End · wazero
    A clear tour of lowering, linear-scan register allocation and finalization in a real compiler; good preparation for the register allocator project.

Code to read

  • x86-64 System V psABI · x86-psABIs group
    The normative calling-convention document; read section 3.2 on stack frames and parameter classification.
  • x86 and amd64 instruction reference · Felix Cloutier
    Searchable HTML of the Intel manual; look up idiv, cqo, setcc and movzx as you emit them.
  • QBE compiler backend · Quentin Carbonneaux
    A small SSA backend (about 10% of LLVM's scope) you can target instead of raw assembly; read its IL docs.
  • cproc · Michael Forney
    A C11 compiler that emits QBE IL; shows how a compact front end separates from codegen.

More reading

  • Writing a C Compiler (book, No Starch) — The book adds a TACKY three-address IR from ch. 2, types in Part II, and TACKY optimizations and register allocation in Part III (ch. 19-20); the same test suite covers all of it. (nostarch.com blocks scripted fetches; check the TOC in a browser.)
  • Compiler Explorer — Compare your output to gcc -O0 and -O2 for each feature.
Stretch project

Add a register allocator (linear scan or graph coloring with coalescing) and a TACKY-style three-address IR to mycc, then pass the book suite through chapter 20. Measure runtime and instruction count against your stack-machine output and gcc -O0/-O1 on 5 compute-heavy C programs.
