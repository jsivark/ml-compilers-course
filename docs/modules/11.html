11Compiling to machine code

Turning an AST into real assembly demystifies what every ML compiler ultimately emits. Nora Sandler's incremental series plus her test suite gives a tight loop: one language feature at a time, each verified by hundreds of tests.

about 40–60 h · difficulty ●●●●○

After this module you can

  • After this module you can lower a typed AST to three-address code and then to x86-64 or ARM64 assembly that links and runs.
  • After this module you can implement a calling convention (System V or AAPCS64) including stack frames and callee-saved registers.
  • After this module you can build a liveness-based register allocator (graph coloring or linear scan) with spilling.
  • After this module you can debug generated assembly with gdb/lldb and objdump.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    CS:APP-style refresher: x86-64 assembly guide (or Beej/asm_book)

    Skim registers, mov/push/pop/call/ret and calling conventions; then compile tiny C programs on Compiler Explorer with -O0 to see what your compiler must produce.

  2. Do

    Install the test suite and run --check-setup

    Clone nlsandler/writing-a-c-compiler-tests and run './test_compiler --check-setup'. The suite is organized by the book's chapters, which match the blog parts 1-10 closely; your compiler must accept the gcc-like driver interface described in the README.

  3. Do

    Sandler Part 1: Integers -> run './test_compiler ./mycc --chapter 1'

    Lexer, parser and code emission for 'int main(){return 2;}'. Use Python for the compiler, emit x86-64 (or AArch64 with the README flags) assembly, assemble with gcc. Then run the suite for chapter 1 (use --latest-only while iterating, then without it to catch regressions).

  4. Do

    Sandler Part 2: Unary Operators -> run './test_compiler ./mycc --chapter 2'

    Add negation, bitwise complement and logical not. Note how each AST node maps to a short instruction template. Then run the suite for chapter 2 (use --latest-only while iterating, then without it to catch regressions).

  5. Do

    Sandler Part 3: Binary Operators -> run './test_compiler ./mycc --chapter 3'

    Add + - * / with precedence climbing; use the stack to hold intermediate values. This is a naive stack-machine codegen you will improve in Module 12. Then run the suite for chapter 3 (use --latest-only while iterating, then without it to catch regressions).

  6. Do

    Sandler Part 4: Even More Binary Operators -> run './test_compiler ./mycc --chapter 4'

    Add relational and short-circuiting logical operators; learn labels and conditional jumps. Then run the suite for chapter 4 (use --latest-only while iterating, then without it to catch regressions).

  7. Do

    Sandler Part 5: Local Variables -> run './test_compiler ./mycc --chapter 5'

    Introduce stack frames, rbp-relative variable slots and a variable map; reject undeclared and redeclared variables. Then run the suite for chapter 5 (use --latest-only while iterating, then without it to catch regressions).

  8. Do

    Sandler Part 6: Conditionals -> run './test_compiler ./mycc --chapter 6'

    if statements and the ternary operator. Then run the suite for chapter 6 (use --latest-only while iterating, then without it to catch regressions).

  9. Do

    Sandler Part 7: Compound Statements -> run './test_compiler ./mycc --chapter 7'

    Block scoping and shadowing; manage stack space when scopes close. Then run the suite for chapter 7 (use --latest-only while iterating, then without it to catch regressions).

  10. Do

    Sandler Part 8: Loops -> run './test_compiler ./mycc --chapter 8'

    for/while/do, break and continue; track loop labels. Then run the suite for chapter 8 (use --latest-only while iterating, then without it to catch regressions).

  11. Do

    Sandler Part 9: Functions -> run './test_compiler ./mycc --chapter 9'

    Function calls and the System V calling convention; call your compiled functions from a C driver to prove ABI compatibility. Then run the suite for chapter 9 (use --latest-only while iterating, then without it to catch regressions).

  12. Do

    Sandler Part 10: Global Variables -> run './test_compiler ./mycc --chapter 10'

    File-scope variables in .data/.bss; this completes the series. Then run the suite for chapter 10 (use --latest-only while iterating, then without it to catch regressions).

Build

mycc: a Python C-subset compiler (ints, unary/binary/logical ops, locals, if/ternary, blocks, loops with break/continue, functions, globals) emitting x86-64 assembly, passing './test_compiler ./mycc --chapter 10' for all valid and invalid programs, plus a README mapping each blog part to commit hashes.

Portfolio project: Register allocator shoot-out in your own compiler

Implement two register allocators for your backend: linear scan and Chaitin-Briggs graph coloring with coalescing. Build a benchmark suite of 15+ programs and compare spill counts, instruction counts, compile time and runtime. Validate correctness with differential testing against your interpreter.

Deliverables

  • repo with a compiler that emits native assembly and two pluggable register allocators
  • README with plots: spills and runtime per benchmark for each allocator, plus gcc -O0/-O1 as baselines
  • a 600–1200 word write-up explaining interference graphs, coalescing, spill heuristics, and where linear scan loses

Rubric

Solid
Both allocators pass all tests with registers limited to 4 and to the full set; measurable spill reduction from coalescing reported.
Exceptional
Within 1.5x of gcc -O1 runtime on most benchmarks, SSA-based allocation or a provably-correct allocation checker, and a clear analysis of compile-time vs code-quality tradeoff.

References: CMU 15-411 Compiler Design course page, QBE compiler backend (a small reference backend)

If you get stuck

  • Segfault on call: the stack must be 16-byte aligned at the call instruction (System V ABI); check rsp before every call.
  • Clobbered values after calls usually mean you forgot caller-saved registers are not preserved.
  • Register allocator bugs hide until spilling: force a tiny register count (e.g. 3) in tests to exercise spills.
  • Write a tiny test harness that compiles, assembles, runs, and diffs against the interpreter from module 10 for every test program.
  • On Apple Silicon, symbol names need a leading underscore and you must target arm64, not x86-64.

Ready to move on when

  • './test_compiler ./mycc --chapter 10' passes with zero failures
  • A function compiled by mycc can be called from gcc-compiled C and vice versa
  • You can hand-trace the stack frame of a 3-argument call and say where each argument lives
  • Invalid programs (undeclared variable, break outside loop) exit with a nonzero code instead of emitting assembly

Going deeper (optional)

  • Writing a C Compiler (book, No Starch) — Book version adds a TACKY IR, register allocation and types (ch. 11-20); the same test suite covers it.
  • Compiler Explorer — Compare your output to gcc -O0 and -O2 for each feature.
