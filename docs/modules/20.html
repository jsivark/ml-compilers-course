20Loops, floats, runtime; matmul and conv

Ranges turn straight-line code into loop nests, and placing each computation in the innermost loop it depends on is the first real scheduling decision. Floats arrive, so correctness becomes a tolerance.

about 30–40 h · difficulty ●●●●○

After this module you can

  • After this module you can lower range/end UOps into correct C loop nests.
  • After this module you can handle float32 semantics (recip, NaN/inf, rounding) consistently across interpreter and backend.
  • After this module you can express GEMM and convolution as loop-nest IR and verify them against NumPy.
  • After this module you can measure GFLOP/s and compare a kernel against a theoretical peak.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    10-411 syllabus: Week 3

    RANGE/END/RECIP, the ranges and ended_ranges properties, and the note that you now need rewrites to order ranges.

  2. Implement

    range/end/recip/f32 in parser, types and bounds

    range has bounds [0, n-1]; recip is f32 only; float literals contain '.'. Pass rejected_recip_int, rejected_range_index_oob.

  3. Implement

    Compute a ranges property per node

    For each node, the set of open ranges it depends on (union of sources minus ended ones). This decides loop placement.

  4. Implement

    Render ranges as nested for loops

    Emit each node inside the innermost loop among its ranges; close loops at end. Pass range_fill, range_square, nested_ranges_2x3, float_recip.

  5. Read

    Goldberg: sections 'Rounding Error' and 'Relative Error and Ulps'

    Just enough to justify comparing with 1e-4 tolerance and why summation order changes results.

  6. Implement

    Float comparison in assert and runtime

    Compare f32 results with a tolerance; make sure C uses float, not double, and that recip renders as 1.0f/x.

  7. Implement

    Hand-write gemm_256.uir

    Three ranges M,N,K with an accumulator buffer; check against NumPy within 1e-4 via a small harness script.

  8. Read

    CS231n conv notes: 'Implementation as Matrix Multiplication'

    The im2col section; understand the six-loop direct conv first.

  9. Read

    tinygrad-notes: convolution

    How conv becomes indexing over ranges; preview for Module 22.

  10. Implement

    Hand-write conv3x3.uir

    Direct 3x3 conv2d (e.g. 1 channel, 32x32) as nested ranges; check against NumPy within 1e-4.

  11. Measure

    Time gemm_256 in C

    Record GFLOPS of your naive loop nest now; it is the baseline you beat in Module 24.

  12. Test

    10 own tests

    E.g. loop-invariant hoisting correctness, range of size 1, index safe only because of range bounds, recip of negative.

Build

Loop nests from range/end, f32 and recip, plus hand-written GEMM and conv UIR checked against NumPy.

Portfolio project: Roofline-annotated benchmark dashboard

Build a benchmark harness that runs every kernel your compiler emits (elementwise, reduce, GEMM, conv) over a sweep of sizes, computes arithmetic intensity from the IR itself, and plots each kernel on a roofline of your machine (measured peak FLOP/s and STREAM-style bandwidth). This dashboard becomes the scoreboard for every later module.

Deliverables

  • repo with a bench CLI that writes JSON results keyed by git commit
  • a generated HTML or notebook dashboard: roofline plot, GFLOP/s vs size, history across commits
  • measured machine ceilings (peak FLOP/s, memory bandwidth) with the microbenchmarks that produced them
  • a 600–1200 word write-up explaining which kernels are compute- vs memory-bound and why

Rubric

Solid
All kernel types on one roofline with correctly computed intensity; results reproducible within 5% across runs; NumPy/BLAS shown as reference points.
Exceptional
Intensity computed automatically from the IR (not hand-entered); dashboard tracks regressions per commit and flags >5% slowdowns in CI; includes cache-level rooflines (L1/L2/DRAM).

References: How to Scale Your Model: All About Rooflines, Simon Boehm, Fast Multidimensional Matrix Multiplication on CPU from Scratch

If you get stuck

  • Off-by-one in loop bounds or wrong nesting order: print the generated C and run a 2x3 example by hand.
  • Conv mismatches only at borders: padding/stride indexing. Test with stride 2, pad 1, non-square kernels.
  • Float compare fails at large K: accumulation order differs from NumPy. Use rtol scaled by sqrt(K), or accumulate in float64 in the oracle.
  • Timings are noisy: warm up, run many repetitions, report median, and pin to one core.
  • Recip vs divide: x*recip(y) is not bit-identical to x/y; decide where you allow it.
