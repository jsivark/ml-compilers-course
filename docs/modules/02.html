Part I · Foundations

02C++ for C programmers

PyTorch, LLVM, MLIR, CUDA and CUTLASS are written in C++, and later modules ask you to write an LLVM pass, a C++/CUDA array backend and templated GPU kernels. This module teaches the parts of modern C++ those tools use: RAII, move semantics, templates, lambdas, CMake and Python bindings. kiln itself stays in C.

about 35–50 h · difficulty ●●●○○

StepsBuildProjectHelpGo deeper

After this module you can

  • Write C++20 classes that own resources through RAII, following the rule of zero or the rule of five.
  • Use move semantics and std::unique_ptr to transfer ownership without copies, and prove it with tests.
  • Write function and class templates over a dtype and a compile-time size.
  • Build a C++ library with CMake, test it with GoogleTest and call it from Python through nanobind.
  • Build and run an out-of-tree LLVM pass plugin.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    learncpp.com: Introduction to classes, Destructors

    Read the classes chapter through constructors, then the destructors lesson (introduction-to-destructors). Compare each class with the C struct plus init/free functions you wrote for tcore.

  2. Watch

    Back to Basics: RAII and the Rule of Zero (Arthur O'Dwyer, CppCon 2019)

    The core idea of C++ resource management. Pause at each class he writes and list which of the five special member functions it needs.

  3. Read

    learncpp.com: Introduction to smart pointers and move semantics, Move constructors and move assignment, std::unique_ptr

    Then read move-constructors-and-move-assignment and stdunique_ptr from the same chapter. Type out every example and predict which constructor runs before you run it.

  4. Watch

    Back to Basics: Move Semantics, part 1 (Klaus Iglberger, CppCon 2019)

    Lvalues, rvalues, std::move and the moved-from state. Watch part 2 if forwarding references are still unclear.

  5. Read

    learncpp.com: Function templates, Class templates, Non-type template parameters

    Then class-templates and non-type-template-parameters. Templates over a dtype and a compile-time size are exactly how CUTLASS and CuTe describe tiles in Module 34.

  6. Read

    learncpp.com: Introduction to lambdas, Lambda captures

    Then lambda-captures. You will pass lambdas as the elementwise op in the project.

  7. Read

    Stanford CS106L: Standard C++ Programming, lecture slides

    Read the slides on templates, RAII and smart pointers, and move semantics. They show the modern idioms (C++20 and later) in fewer pages than a book.

  8. Read

    C++ Core Guidelines: R (Resource management), C.20 and C.21, F.15 to F.18 (parameter passing)

    Read these sections only; the document is a reference. Use the rules as a review checklist for your project code.

  9. Read

    An Introduction to Modern CMake: Introduction to the basics, Adding features, Testing

    Learn targets, target_link_libraries with PUBLIC/PRIVATE, and FetchContent. Every C++ project from here on (LLVM passes, MLIR, nanobind) builds with CMake.

  10. Read

    GoogleTest Primer

    Assertions, test fixtures and TEST_F. Pull GoogleTest into your build with FetchContent.

  11. Read

    nanobind: Installation, Setting up a build system, The nb::ndarray class

    Bind one function first, then read the ndarray page: it shows how to share a buffer with NumPy and PyTorch without copying.

  12. Do

    llvm-tutor: build HelloWorld and OpcodeCounter

    Build out of tree against an installed LLVM and run both passes with opt -load-pass-plugin. On macOS the plugin ends in .dylib, not .so. This is the setup the LLVM pass in Module 13 uses.

Build

  1. A Buffer<T> class template that owns a heap array: rule of five written by hand, then replaced by std::unique_ptr<T[]> with the rule of zero, plus GoogleTest tests that count allocations to prove a move never copies.
  2. Extend llvm-tutor's HelloWorld pass to print, for each function, its basic-block count and instruction count, and test it on a C file of your own with opt.

Portfolio project: tcore++: a modern C++ tensor wrapper with Python bindings

Skill project

Wrap your kiln v0.1 C core in a header-only C++20 library. Tensor<T> owns its storage through RAII, is movable but not implicitly copyable, supports strided views that share storage, and applies elementwise ops passed as lambdas, with add and mul that call into tcore for float. Build it with CMake, test it with GoogleTest, benchmark it with Google Benchmark against the raw C calls, and expose it to Python with nanobind so NumPy can read a tensor without copying. The goal is to show that the abstractions cost nothing at runtime.

Deliverables

  • repo with a CMake build, include/tcorepp/tensor.hpp, GoogleTest tests run under ASan and UBSan, and a nanobind module with a pytest file comparing results against NumPy
  • README with a Google Benchmark table comparing the C++ wrapper with direct tcore calls at three tensor sizes, plus one annotated Compiler Explorer snippet
  • a 600–1200 word write-up explaining your ownership rules, why views share storage, and which C++ features had no runtime cost and which did

Rubric

Solid
Tests pass under sanitizers; moves proven copy-free by tests; the wrapper is within 5% of direct C calls at every size; Python can create, view and read tensors without copying.
Exceptional
C++20 concepts constrain the element type, a std::span-based API covers raw buffers, CI builds and tests on Linux and macOS, and the write-up explains the one place you measured a real abstraction cost and how you removed it.

References: nanobind documentation, Google Benchmark user guide

Help

If you get stuck

  • Linker error undefined reference for a template: the template body is in a .cpp file. Move it to the header.
  • A double free after copying your class: you wrote a destructor but not the copy constructor and copy assignment. Delete them or follow the rule of zero.
  • Calling C from C++ fails to link: wrap the C header's declarations in extern "C" { ... }.
  • CMake cannot find LLVM: pass -DLT_LLVM_INSTALL_DIR=$(llvm-config --prefix) (or your Homebrew LLVM path) and use the same LLVM version that llvm-tutor targets.
  • Template error messages run for pages: read the first error only, and add a C++20 requires clause so the error names the broken constraint.

Ready to move on when

  • Name the five special member functions and say which ones the compiler generates for a class holding a std::unique_ptr member.
  • Explain what std::move does at runtime, and what state a moved-from std::vector is in.
  • Explain why a class template's member functions are usually defined in the header.
  • Show the assembly on Compiler Explorer for a templated add<float> and a hand-written C add_f32, and explain why they match.
  • Your Buffer<T> tests pass under -fsanitize=address,undefined.
Reference implementations (2)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • wjakob/nanobind_example (Project: nanobind module)
    The nanobind author's minimal project: CMake plus scikit-build-core packaging. Copy its layout for the Python module.
  • banach-space/llvm-tutor (Build (2): extend the HelloWorld pass)
    Each pass comes with LIT tests; read OpcodeCounter's source for how to walk functions, blocks and instructions.

Go deeper (optional)

Talks, papers, code and writing (6)

Talks

  • CppCon 2014: Herb Sutter "Back to the Basics! Essentials of Modern C++ Style" · Herb Sutter (CppCon)
    Default habits for parameter passing, smart pointers and auto; the reasoning behind the Core Guidelines you read.
  • Back to Basics: Move Semantics (Nicolai Josuttis, CppCon 2021) · Nicolai Josuttis (CppCon)
    A second explanation of move semantics from the author of the standard reference on the topic.

Books

  • A Tour of C++, third edition · Bjarne Stroustrup
    The whole language in about 300 pages, from its designer; read it after this module to fill gaps.
  • Optimizing software in C++ · Agner Fog
    Which C++ features cost cycles and which do not; read the chapters on classes, templates and virtual functions.

More reading

  • cppreference.com — The reference for the standard library and language; look things up here, not on forums.
  • Compiler Explorer — Check what each abstraction compiles to; the C++ habit that matters most for kernel work.
