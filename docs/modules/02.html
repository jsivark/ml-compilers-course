02How machines run code

Bits, two's complement, IEEE floats, x86-64 and the stack: the first half of CMU 15-213. You need to read the machine code your compiler's output becomes.

about 40–55 h · difficulty ●●●○○

After this module you can

  • Read compiler-generated x86-64 assembly and write the C it came from.
  • Predict the result of signed/unsigned casts, integer overflow and float rounding cases.
  • Name the System V AMD64 argument, return and callee-saved registers, and inspect them in gdb.
  • Describe the steps from source file to running process: compile, link, load, exec.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    CMU 15-213 F15 Lectures 2-3: Bits, Bytes and Integers

    Videos are in the 15-213 F15 Panopto folder (see extras). Focus on two's complement, casting and overflow.

  2. Read

    Dive into Systems ch. 4: Binary and Data Representation

    Do the inline exercises, especially signed/unsigned conversion.

  3. Do

    CS:APP Data Lab: all puzzles

    Get datalab-handout from the labs page. Solve every bit and float puzzle within the op limits; run ./btest and ./dlc until both pass.

  4. Watch

    CMU 15-213 F15 Lecture 4: Floating Point

    Sign, exponent and fraction fields, denormals, rounding, and why float addition is not associative. Module 3 and the reduction kernels later depend on the last point.

  5. Watch

    CMU 15-213 F15 Lectures 5-6: Machine-Level Programming I-II (Basics, Control)

    Then 06-machine-control.pdf. Registers, mov, lea, condition codes, jumps, loops.

  6. Read

    Dive into Systems ch. 7: x86-64 Assembly, sections 7.1-7.6

    Read 7.1 Assembly Basics through 7.6 Recursion and paste each example into Compiler Explorer.

  7. Watch

    CMU 15-213 F15 Lectures 7-9: Procedures, Data, Advanced

    Then 08-machine-data.pdf and 09-machine-advanced.pdf. Stack frames, calling convention, arrays/structs layout, buffer overflow.

  8. Do

    Compiler Explorer: compile your Module 1 functions

    Compare -O0 and -O2 for a sum loop, a struct field access and a recursive function. Annotate the -O2 asm by hand.

  9. Do

    CS:APP Bomb Lab: phases 1-6

    Use gdb (break, stepi, x/s, info registers) and objdump -d. For each phase, note which C construct it encodes (comparison, loop, switch, recursion, linked list).

  10. Read

    cpu.land ch. 1-5: The Basics through The Translator in Your Computer

    Chapters 1 The Basics, 2 Slice Dat Time, 3 How to Run a Program, 4 Becoming an Elf-Lord, 5 The Translator in Your Computer: syscalls, interrupts, exec, ELF and paging.

Build

Defuse all six Bomb Lab phases (plus the secret phase if you find it). Then write half a page explaining the System V AMD64 calling convention: argument registers, return value, caller- vs callee-saved registers, stack alignment, red zone, illustrated with godbolt output of a 7-argument function.

Portfolio project: Compiler Explorer study: what -O2 does to tensor loops

Pick five small kernels you will meet later (axpy, dot product, a strided gather, a reduction with a float accumulator, a 3x3 conv inner loop). For each, compile with clang and gcc at -O0/-O2/-O3 (and -ffast-math for the reductions), read the assembly, and document which optimizations happened: vectorization, unrolling, strength reduction, and why the float reduction does not vectorize without fast-math. Time each variant.

Deliverables

  • repo with the kernels, a script that regenerates annotated assembly and timings
  • README with a table of cycles/element per kernel, compiler and flag, plus annotated asm snippets
  • a 600–1200 word write-up explaining floating-point associativity, aliasing (restrict) and their effect on vectorization

Rubric

Solid
All 5 kernels x 2 compilers x 3+ flag sets timed with repeated runs; each asm snippet annotated with what each block does.
Exceptional
Uses `perf stat` or llvm-mca to explain throughput from instruction counts and port pressure, demonstrates a measurable speedup from adding `restrict` or reassociation, and predicts the speedup before measuring it.

References: Compiler Explorer, Algorithms for Modern Hardware (Sergey Slotin)

If you get stuck

  • Bomb Lab: do not guess. Disassemble with `objdump -d` and use gdb `break explode_bomb` first so a wrong answer never detonates.
  • AT&T vs Intel syntax confusion (operand order is reversed): pick one, and set Compiler Explorer and gdb (`set disassembly-flavor intel`) to match.
  • Data Lab op-count limits: build masks with shifts and ~, and check each step's bit pattern in a scratch C program before using it.
  • Floating point: 0.1 cannot be represented exactly; work through the rounding examples in Lecture 4 by hand rather than trusting intuition.
  • At -O0 the asm is verbose and stack-heavy; compare -O0 vs -O2 in Compiler Explorer to see what the optimizer actually does.

Ready to move on when

  • Data Lab: btest passes every puzzle and dlc reports no op-count violations.
  • Bomb Lab: all 6 phases defused without an explosion (phases 1-4 are worth 10 points each, 5-6 are worth 15).
  • Explain why (int)(unsigned)-1 and -1 > 0u behave as they do.
  • Explain why 0.1+0.2 != 0.3 and why summing floats in a different order changes the result.
  • Given a 10-line asm function, write the C that produced it.

Going deeper (optional)

  • nand2tetris, projects 1-5 — Gates to CPU.
  • Pete Kivolowitz, Assembly Language Programming for ARM64 — If you are on Apple Silicon.
