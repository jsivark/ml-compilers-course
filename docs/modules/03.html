03Memory and caches

Cache lines, locality and TLBs explain why loop order changes runtime. Tiling, fusion and vectorization decisions later in the course depend on this module.

about 35–50 h · difficulty ●●●○○

StepsBuildProjectHelpGo deeper

After this module you can

  • Compute expected cache misses per inner-loop iteration for a loop nest, given the cache geometry.
  • Speed up a memory-bound kernel with loop reordering and tiling, and measure the speedup.
  • Read your machine's L1, L2 and L3 sizes off a measured latency plot.
  • Use perf stat cache-miss counters to confirm or reject a performance hypothesis.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    CMU 15-213 F15 Lecture 11: The Memory Hierarchy

    Locality, the latency pyramid, why caches work.

  2. Watch

    CMU 15-213 F15 Lecture 12: Cache Memories

    Sets, ways and lines, miss classification, and the matmul loop-order analysis at the end. This is the core lecture of the module.

  3. Read

    Dive into Systems ch. 11: Storage and the Memory Hierarchy, sections 11.3-11.5

    Read 11.3 Locality, 11.4 Caching and 11.5 Cache Analysis and Cachegrind; do the cache-mapping exercises.

  4. Do

    Igor Ostrovsky, Gallery of Processor Cache Effects: all 7 examples

    Reproduce each in C on your machine and plot it. Mark where your L1, L2 and L3 sizes appear.

  5. Read

    Drepper, What Every Programmer Should Know About Memory, §3 CPU Caches and §6.2 Cache Access

    Skip §2 (DRAM hardware) and §4-5. §6.2 has the tiled matmul with measured speedups.

  6. Do

    CS:APP Cache Lab Part A: cache simulator

    Write csim.c that replays valgrind traces with LRU; match csim-ref on all test traces.

  7. Do

    CS:APP Cache Lab Part B: optimized transpose

    Blocked transpose for 32x32 (<300 misses), 64x64 (<1300) and 61x67 (<2000). This is your first hand-written schedule.

  8. Watch

    CMU 15-213 F15 Lecture 17: Virtual Memory Concepts

    Pages, page tables and the TLB; why large strides cause TLB misses.

  9. Read

    Algorithms for Modern Hardware: RAM & CPU Caches chapter

    Read Memory Bandwidth, Memory Latency, Cache Lines, Cache Associativity and AoS and SoA; run two of the benchmarks.

Build

Reproduce Ostrovsky's seven effects with plots. Then time naive C matmul at N=1024 in all six loop orders (ijk, ikj, jik, jki, kij, kji) at -O2, plot GFLOP/s, and write a page explaining the ranking with per-iteration miss counts (as in Lecture 12). Add a tiled version and report its speedup.

Project

No separate project here. The naive and tiled matmul from this module's Build is stage 1 of the matmul worklog you finish in Module 16, so keep your code and numbers. Go to Module 16.

Help

If you get stuck

  • Timings are noisy: warm up, repeat, report the median, pin to a core, and do not run with a browser open on a laptop on battery.
  • Cache Lab 64x64 transpose: 8x8 blocking, which works for 32x32, gets conflict misses here because rows 4 apart map to the same sets. Split each 8x8 block into 4x4 sub-blocks.
  • No perf on your machine: perf runs on Linux (and inside WSL with limits). On macOS use Instruments' CPU Counters template; on Windows use Intel VTune or AMD uProf, or measure on a Linux cloud VM. The concepts transfer.
  • The compiler may optimize your benchmark away; consume the result (print a checksum) and check the asm.
  • Bandwidth-bound vs latency-bound: a sequential scan is limited by bandwidth, a pointer chase by latency. Ostrovsky's Example 1 and Example 4 separate the two.

Ready to move on when

  • Explain why ikj beats ijk, with misses-per-inner-iteration arithmetic.
  • Cache Lab: test-csim gives full marks, and transpose has fewer than 300 misses on 32x32, 1300 on 64x64 and 2000 on 61x67.
  • Given a 32 KB 8-way cache with 64 B lines, compute sets and the address bits for tag/index/offset.
  • Explain conflict misses and why padding a 4096-wide array can help.
  • Point to your L1/L2/L3 transitions on the Ostrovsky array-size plot.
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • Exely/CSAPP-Labs (Cache Lab) (Cache Lab Parts A and B)
    Contains a csim.c LRU simulator and blocked transpose solutions for the 32x32, 64x64 and 61x67 cases with miss counts.
  • flame/how-to-optimize-gemm (Project: single-core CPU SGEMM)
    The BLIS group's step-by-step GEMM tutorial: each file adds one optimization (4x4 micro-kernel, SSE, packing) with plots.
  • flame/blislab (Project: register blocking and packing steps)
    A teaching framework for BLIS-style GEMM with packing and a register micro-kernel in C; shows the five-loop structure of a fast SGEMM.
  • Seterplus/CSAPP (Cache Lab) (Cache Lab Part B)
    An alternate Cache Lab solution to compare transpose blocking strategies, especially the 64x64 case.
