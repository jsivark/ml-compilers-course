03Memory and caches

Cache lines, locality and TLBs decide why loop order matters. Every tiling, fusion and vectorization decision later in the course rests on this module.

about 35–50 h · difficulty ●●●○○

After this module you can

  • After this module you can predict cache misses for a loop nest from its access pattern and the cache geometry.
  • After this module you can speed up a memory-bound kernel through loop reordering and tiling, and measure the gain.
  • After this module you can explain the memory hierarchy (registers, L1/L2/L3, DRAM, TLB) with real latency and bandwidth numbers.
  • After this module you can use hardware counters (perf) to confirm or refute a performance hypothesis.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    CMU 15-213 F15 Lecture 11: The Memory Hierarchy

    Locality, the latency pyramid, why caches work.

  2. Watch

    CMU 15-213 F15 Lecture 12: Cache Memories

    Sets/ways/lines, miss classification, and the matmul loop-order analysis at the end; this is the core of the module.

  3. Read

    Dive into Systems ch. 11: Storage and the Memory Hierarchy

    Read 11.3-11.5 (locality, CPU caches); do the cache-mapping exercises.

  4. Do

    Igor Ostrovsky, Gallery of Processor Cache Effects: all 7 examples

    Reproduce each in C on your machine and plot; note where your L1/L2/L3 sizes show up.

  5. Read

    Drepper, What Every Programmer Should Know About Memory, §3 CPU Caches and §6.2 Cache Access

    Skip §2 DRAM hardware details and §4-5. §6.2 has the tiled matmul with measured speedups.

  6. Do

    CS:APP Cache Lab Part A: cache simulator

    Write csim.c that replays valgrind traces with LRU; match csim-ref on all test traces.

  7. Do

    CS:APP Cache Lab Part B: optimized transpose

    Blocked transpose for 32x32, 64x64, 61x67 under the miss limits. This is your first hand-written schedule.

  8. Watch

    CMU 15-213 F15 Lecture 17: Virtual Memory Concepts

    Pages, page tables, TLB; why huge strides cost TLB misses.

  9. Read

    Algorithms for Modern Hardware: RAM & CPU Caches chapter

    Read the bandwidth, latency, cache lines and AoS vs SoA sections; run a couple of the benchmarks.

Build

Reproduce Ostrovsky's seven effects with plots. Then time naive C matmul at N=1024 in all six loop orders (ijk, ikj, jik, jki, kij, kji) at -O2, plot GFLOP/s, and write a page explaining the ranking with per-iteration miss counts (as in Lecture 12). Add a tiled version and report its speedup.

Portfolio project: Single-core CPU SGEMM: from naive to a large fraction of peak

Starting from your naive C matmul, optimize single-threaded float32 GEMM step by step: loop order, cache tiling, register blocking with a micro-kernel, SIMD (AVX2/NEON intrinsics or auto-vectorization) and packing. Compute the theoretical peak of your core and plot each version's GFLOP/s as a fraction of it, alongside OpenBLAS or Accelerate on the same machine.

Deliverables

  • repo with each optimization step as its own function or commit, a correctness test against a reference, and a benchmark script
  • README with a GFLOP/s vs N plot for all versions and the BLAS baseline, and your peak-FLOPs calculation
  • a 600–1200 word write-up explaining which step removed which bottleneck, backed by cache-miss counts or a roofline argument

Rubric

Solid
At least 5 versions, each correct; best version reaches at least 30% of single-core peak; all numbers are medians with the CPU model stated.
Exceptional
Best version reaches at least 60–70% of peak or within 2x of OpenBLAS single-threaded, includes a roofline plot, and the write-up attributes each speedup quantitatively (miss counts from perf, or FLOPs per byte).

References: Simon Boehm, Fast Multidimensional Matrix Multiplication on CPU from Scratch, Algorithms for Modern Hardware: Matrix Multiplication

If you get stuck

  • Timings are noisy: warm up, repeat, report the median, pin to a core, and do not run with a browser open on a laptop on battery.
  • Cache Lab transpose 64x64: the 8x8 blocking that works for 32x32 suffers conflict misses; split into 4x4 sub-blocks (Lecture 12 and the lab writeup hint at this).
  • Apple Silicon and some laptops lack perf: use Instruments or measure on a Linux box/cloud VM; the concepts transfer.
  • The compiler may optimize your benchmark away; consume the result (print a checksum) and check the asm.
  • Confusing bandwidth-bound and latency-bound: a sequential scan is bandwidth-bound, a pointer chase latency-bound; Drepper §3 and Ostrovsky's examples separate the two.

Ready to move on when

  • Explain why ikj beats ijk, with misses-per-inner-iteration arithmetic.
  • Cache Lab: test-csim gives full marks and transpose meets the 32x32 and 64x64 miss limits.
  • Given a 32 KB 8-way cache with 64 B lines, compute sets and the address bits for tag/index/offset.
  • Explain conflict misses and why padding a 4096-wide array can help.
  • Point to your L1/L2/L3 transitions on the Ostrovsky array-size plot.
