Part III · The Course · 10-411 week 3

21Loops, floats, runtime; matmul and conv

range and end turn straight-line code into loop nests, and placing each computation in the innermost loop it depends on is the first scheduling decision. f32 arrives, so correctness becomes a tolerance.

about 25-35 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Lower range/end into C for loops with each node in the innermost loop it depends on.
  • Compare f32 results within a stated tolerance and explain why accumulation order changes them.
  • Hand-write GEMM (256^3) and a 3x3 conv in UIR, verify them against NumPy, and report a GFLOP/s baseline.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    geohot's 10-411 syllabus: week 3 (loops, floats, runtime)

    RANGE/END/RECIP, the ranges and ended_ranges properties, and the note that this is likely the first week you need a rewrite engine to order the ranges.

  2. Implement

    Parse and type the new range, end, recip and f32 ops

    range n has bounds [0, n-1]; recip takes f32 only; float literals contain '.'. REJECT rejected_recip_int and rejected_range_index_oob.

  3. Implement

    Compute a ranges property per node

    For each node, the set of open ranges it depends on: the union over its sources, minus ranges closed by end. This decides loop placement.

  4. Implement

    Render ranges as nested for loops

    Emit each node inside the innermost loop among its ranges; close loops at end, innermost first. Pass range_fill, range_square, nested_ranges_2x3, float_recip.

  5. Read

    Goldberg, What Every Computer Scientist Should Know About Floating-Point Arithmetic: the rounding error sections

    Enough to justify a 1e-4 relative tolerance and to see why summation order changes a float result.

  6. Implement

    Float comparison in assert and runtime

    Compare f32 results with a tolerance; emit float, not double, and render recip x as 1.0f/x.

  7. Implement

    Hand-write gemm_256.uir

    M=N=K=256 with three ranges and an accumulator buffer. Check against NumPy (A @ B in float32) within 1e-4 with a small harness script.

  8. Read

    Stanford CS231n notes: convolution as a matrix multiply

    The im2col paragraph in the Convolutional Layer section. Write the six-loop direct conv on paper first.

  9. Read

    How tinygrad builds convolution from movement ops (tinygrad notes, preview of Module 23)

    tinygrad builds conv from _pool, which is expand, permute and shrink. Preview for Module 23; the note uses an older tinygrad API.

  10. Implement

    Hand-write conv3x3.uir

    Direct 3x3 conv2d, 1 channel, 32x32 input, no padding (30x30 output), as nested ranges. Check against a NumPy loop or scipy.signal.correlate2d(mode='valid') within 1e-4.

  11. Measure

    Time gemm_256 in C

    Report GFLOP/s (2*256^3 flops / median time over 10+ runs after a warmup) for your naive loop nest. Module 25 tries to beat this number.

  12. Test

    Write 10 tests of your own

    E.g. a range of size 1, an index that is safe only because of range bounds, recip of a negative, an expression that should be placed outside the inner loop.

Build

Loop nests from range/end, f32 and recip, plus hand-written GEMM and conv UIR checked against NumPy.

Portfolio project: kiln v1.2: Roofline benchmark harness for your compiler

kiln, the main project · v1.2 adds a roofline benchmark harness that every later version reports into · builds on v1.1 · next: v1.3

Grow your Module 0 kbench tool into a harness that runs the kernels your compiler can emit now (elementwise add over 2^20 f32, gemm at 64/128/256/512, conv3x3 at 32/64/128) over a size sweep, computes arithmetic intensity (flops / bytes of buffers) from the IR, and plots each on a roofline of your machine using a measured peak FLOP/s and a STREAM-style copy bandwidth. Later modules add their kernels to it.

Deliverables

  • repo with a bench CLI that writes JSON results keyed by git commit
  • a generated HTML or notebook page: roofline plot, GFLOP/s vs size, history across commits
  • the two microbenchmarks (peak FLOP/s, memory bandwidth) and their measured numbers
  • a 600-1200 word write-up on which kernels are compute- or memory-bound and why

Rubric

Solid
All listed kernels on one roofline with intensity computed from the IR, not hand-entered; repeated runs agree within 5%; NumPy float32 matmul shown as a reference point.
Exceptional
CI flags any kernel that slows down by more than 5% between commits; adds an L1/L2 bandwidth ceiling and explains which gemm sizes fall out of cache.

References: How to Scale Your Model: All About Rooflines, Simon Boehm, Fast Multidimensional Matrix Multiplication on CPU from Scratch

Help

If you get stuck

  • Wrong loop nesting or off-by-one bounds: print the generated C for nested_ranges_2x3 and trace it by hand.
  • conv3x3 wrong only at the edges: output size for a valid 3x3 on 32x32 is 30x30. Check your index ranges against that.
  • gemm_256 fails the tolerance: the oracle used float64. Compute the NumPy reference in float32, or compare with a relative tolerance.
  • Timings vary run to run: warm up once, time 10+ runs and report the median.

Ready to move on when

  • python3 run_tests.py 1, 2 and 3 all pass
  • gemm_256.uir matches NumPy float32 matmul within 1e-4
  • conv3x3.uir matches a NumPy 3x3 valid correlation within 1e-4
  • In the generated C, a node that depends only on the outer range is emitted outside the inner loop
Reference implementations (5)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • darknet's im2col in C (Hand-write conv3x3.uir)
    The classic im2col loop in about 40 lines, to compare with your direct conv indexing.
  • darknet's convolution layer in C (Hand-write conv3x3.uir)
    Shows im2col followed by gemm as a full conv forward pass.
  • The matmul function in llama2.c (Hand-write gemm_256.uir)
    A minimal float32 matmul loop with an accumulator, the reference shape for gemm_256.
  • tinygrad's tests for loop generation (Render ranges as nested for loops)
    Tests of range placement and loop structure in tinygrad's linearizer, useful as test ideas for your ranges property.
  • how-to-optimize-gemm (Hand-write gemm_256.uir)
    Step-by-step C versions of gemm from naive to blocked, each a small diff.

Talks, papers, code and writing (12)

Lectures

  • Convolution (DL System Design and Optimization, Week 4) · Rice University
    Compact 2026 slides comparing direct conv, im2col+GEMM and Winograd with their memory and accuracy costs; use it to pick which conv form your compiler emits.

Courses

  • CS 6120: The Self-Guided Course · Adrian Sampson
    The loop optimization lesson covers loop-invariant code motion, which is what your innermost-placement rule does.
  • LAFF-On Programming for High Performance, Week 2: vector registers and instructions · Robert van de Geijn (UT Austin)
    Free course unit that builds the register-blocked micro-kernel with exercises; do the micro-kernel exercises before tuning your generated loops.

Papers

  • Anatomy of High-Performance Matrix Multiplication · Kazushige Goto, Robert van de Geijn
    The packing and blocking design behind every fast CPU gemm; read sections 3-4 after your naive loop works.
  • Anatomy of High-Performance Deep Learning Convolutions on SIMD Architectures · Georganas et al. (Intel, SC18)
    Shows JIT-generated direct convolution near peak on x86 without im2col; read the loop-blocking section for the case against im2col copies.

Books

  • Optimizing software in C++ · Agner Fog
    Floating-point and loop chapters show why float vs double and summation order change speed and results.

Blogs and articles

  • Making Deep Learning Go Brrrr From First Principles · Horace He
    Compute, memory and overhead bound regimes; use it to predict how slow your naive gemm should be.
  • GPU Glossary · Modal
    Look up arithmetic intensity and roofline terms before Part IV moves these loops to the GPU.
  • GEMM on CPU: multi-threaded FP32 matmul in pure C · salykova
    Step-by-step FMA3/AVX2 matmul in C that competes with OpenBLAS; focus on the micro-kernel and packing sections when writing your C renderer's matmul target.
  • GEMM: From Pure C to SSE Optimized Micro Kernels · Michael Lehn (Ulm)
    Walks from naive C to blocked C to SSE micro-kernels with benchmarks at each step; useful for seeing which transformation gives which speedup.

Code to read

  • Halide · Halide team
    Its tutorials lessons 5 and 8 show loop nests and compute placement as a schedule, the generalization of your ranges placement.

More reading
