28SOTA inference and training

Production inference is memory-bandwidth bound decoding; KV caches, batching, quantization and speculative decoding are how real stacks win. You also commit to a final project.

about 40–55 h · difficulty ●●●●●

After this module you can

  • Implement a KV cache and batched decoding whose tokens match no-cache decoding.
  • Quantize weights to int8 with per-channel scales and measure the perplexity cost.
  • Implement speculative decoding and compare measured speedup with the speedup predicted from acceptance rate.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Scaling Book: All About Transformer Inference

    Prefill vs generation, why decode is bandwidth bound, and the KV cache size math in 'What about memory?'.

  2. Measure

    Baseline tokens/sec

    stories15M and stories110M on your compiler vs run.c, same prompt and token count.

  3. Implement

    KV cache

    Store K/V per layer in a buffer, decode one token per step; tokens must match the no-cache version.

  4. Read

    Andrew Chan, Fast LLM Inference From Scratch

    Sections 2 (CPU: multithreading, quantization and SIMD) and 3 (GPU: matmuls, fusion, attention); compare their gains with yours.

  5. Implement

    Batching

    Static batching of multiple sequences; report throughput vs batch size 1-32.

  6. Read

    LLM.int8() §3.1 Vector-wise Quantization

    Row/column-wise scaling; you only need per-output-channel weight scales, not the mixed-precision decomposition of §3.2.

  7. Implement

    int8 weights

    Dequantize inside the matmul kernel; report perplexity change on the TinyStories validation split.

  8. Read

    Leviathan et al., Speculative Decoding §2.3 and §3.1

    §2.3 Speculative Sampling (Algorithm 1, the accept/reject rule) and §3.1 for the expected number of tokens per step.

  9. Implement

    Speculative decoding

    stories15M drafts for stories110M (same tokenizer); report acceptance rate and speedup vs target-only decoding.

  10. Read

    Accelerating Generative AI with PyTorch II: GPT, Fast

    Llama-7B on A100: 25.5 tok/s baseline, 107.0 with torch.compile and static KV cache, then int8, speculative decoding and int4 up to 244.7 tok/s. Note what each step attacks.

  11. Measure

    Tokens/sec table vs llama2.c

    One row per optimization, with run.c as the baseline; compare your relative gains with the gpt-fast post's.

  12. Implement

    Write the one-page project proposal

    Goal, baseline, metric, plan (see Modules 29-31).

Build

KV cache, batching, int8 weights and speculative decoding for llama2.c models, benchmarked against run.c, plus a project proposal.

Portfolio project: Small inference server for llama2.c models on your compiler

Serve stories110M with continuous batching, a paged KV cache, int8 weights and stories15M as a speculative draft. Publish a latency/throughput study at several request rates against run.c and PyTorch eager running the same weights on the same hardware.

Deliverables

  • repo with the server, a load generator and reproducible benchmark scripts
  • README with throughput vs p50/p99 latency curves, and TinyStories validation perplexity for fp32 vs int8
  • an ablation table: each feature on/off and its contribution
  • a 600-1200 word write-up deriving the bandwidth bound on decode tokens/s for your GPU and how close you got

Rubric

Solid
Server handles concurrent requests with correct outputs; int8 within 1% perplexity of fp32; faster than PyTorch eager at batch 1.
Exceptional
Batch-1 decode reaches 50% of the bandwidth bound; paged KV cache shows a measured capacity gain; speculative speedup within 15% of the analytical prediction.

References: Efficient Memory Management for LLM Serving with PagedAttention, Fast Inference from Transformers via Speculative Decoding, gpt-fast (PyTorch Labs), llama2.c

If you get stuck

  • KV cache gives different tokens than no-cache: position indexing (RoPE offset) is wrong for the cached step.
  • Batching slows single-request latency: report both throughput and p50/p99 latency, they trade off.
  • int8 quality collapse: per-tensor scales are too coarse; use per-channel or group-wise scales and check perplexity.
  • Speculative decoding gives no speedup: draft too slow or acceptance too low; measure both and compute the expected speedup.
  • Unfair benchmarks: match batch size, dtype, prompt length and warm-up across systems.

Ready to move on when

  • KV cache tokens identical to no-cache decoding
  • int8 perplexity change reported on TinyStories validation
  • Speculative decoding output distribution preserved (greedy: identical tokens) with acceptance rate and speedup reported
  • Tokens/sec table vs run.c for each optimization
  • One-page proposal written

Going deeper (optional)

  • PagedAttention / vLLM — Paging the KV cache.
  • nano-vllm — Small readable serving engine.
  • Lilian Weng: inference optimization — Survey.
