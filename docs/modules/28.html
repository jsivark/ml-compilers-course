28SOTA inference and training

Production inference is memory-bandwidth bound decoding; KV caches, batching, quantization and speculative decoding are how real stacks win. You also commit to a final project.

about 40–55 h · difficulty ●●●●●

After this module you can

  • After this module you can implement a KV cache and continuous batching for LLM decoding.
  • After this module you can quantize weights to int8 and measure the accuracy cost.
  • After this module you can implement speculative decoding and analyze its acceptance rate.
  • After this module you can benchmark an inference stack against llama2.c and gpt-fast fairly.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Scaling Book: All About Transformer Inference

    Prefill vs decode, why decode is bandwidth bound, KV cache size math.

  2. Measure

    Baseline tokens/sec

    stories15M (or larger llama2.c model) on your compiler vs run.c.

  3. Implement

    KV cache

    Store K/V per layer in a buffer, decode one token per step; tokens must match the no-cache version.

  4. Read

    yalm: Fast LLM inference from scratch

    Each optimization step with its tokens/sec gain; compare to yours.

  5. Implement

    Batching

    Batch multiple sequences; report throughput vs batch size.

  6. Read

    LLM.int8() §3 (vector-wise quantization)

    Then quantize weights to int8 with per-channel scales.

  7. Implement

    int8 weights

    Dequantize in the matmul kernel; check perplexity/tokens drift.

  8. Read

    Leviathan et al., Speculative Decoding §2-3 (Algorithm 1)

    The accept/reject rule that preserves the target distribution.

  9. Implement

    Speculative decoding

    Small draft model + target; report acceptance rate and speedup.

  10. Read

    gpt-fast blog

    Their sequence of optimizations as a comparison table.

  11. Measure

    Report vs llama2.c and gpt-fast

    Tokens/sec table for each optimization.

  12. Implement

    Write the one-page project proposal

    Goal, baseline, metric, plan (see Modules 29-31).

Build

KV cache, batching, int8 weights and speculative decoding for your LLM, benchmarked against llama2.c and gpt-fast, plus a project proposal.

Portfolio project: Mini inference server on your compiler

Wrap your LLM in a small server with continuous batching, a paged KV cache, int8 weights and speculative decoding, then publish a latency/throughput study against gpt-fast and llama2.c on the same hardware. This is the project inference teams will ask you about.

Deliverables

  • repo with the server, a load generator and reproducible benchmark scripts
  • README with throughput vs latency curves at several request rates, and perplexity for fp16 vs int8
  • an ablation table: each feature on/off and its contribution
  • a 600–1200 word write-up on the memory-bandwidth argument for why decoding speed is what it is

Rubric

Solid
Server handles concurrent requests correctly; int8 within 1% perplexity of fp16; tokens/s within 2x of gpt-fast at batch 1.
Exceptional
Matches or beats gpt-fast at batch 1 on your GPU; paged KV cache shows a measured capacity gain; speculative decoding speedup matches the analytical prediction from acceptance rate.

References: Efficient Memory Management for LLM Serving with PagedAttention, Fast Inference from Transformers via Speculative Decoding, gpt-fast (PyTorch Labs)

If you get stuck

  • KV cache gives different tokens than no-cache: position indexing (RoPE offset) is wrong for the cached step.
  • Batching slows single-request latency: report both throughput and p50/p99 latency, they trade off.
  • int8 quality collapse: per-tensor scales are too coarse; use per-channel or group-wise scales and check perplexity.
  • Speculative decoding gives no speedup: draft too slow or acceptance too low; measure both and compute the expected speedup.
  • Unfair benchmarks: match batch size, dtype, prompt length and warm-up across systems.

Ready to move on when

  • KV cache, batching, int8 and speculative decoding all work with correct outputs
  • Tokens/sec reported vs llama2.c and gpt-fast
  • One-page proposal written

Going deeper (optional)

  • PagedAttention / vLLM — Paging the KV cache.
  • nano-vllm — Small readable serving engine.
  • Lilian Weng: inference optimization — Survey.
