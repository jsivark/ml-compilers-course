28SOTA inference and training

Production inference is memory-bandwidth bound decoding; KV caches, batching, quantization and speculative decoding are how real stacks win. You also commit to a final project.

about 40–55 h · difficulty ●●●●●

StepsBuildProjectHelpGo deeper

After this module you can

  • Implement a KV cache and batched decoding whose tokens match no-cache decoding.
  • Quantize weights to int8 with per-channel scales and measure the perplexity cost.
  • Implement speculative decoding and compare measured speedup with the speedup predicted from acceptance rate.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Scaling Book: All About Transformer Inference

    Prefill vs generation, why decode is bandwidth bound, and the KV cache size math in 'What about memory?'.

  2. Measure

    Baseline tokens/sec

    stories15M and stories110M on your compiler vs run.c, same prompt and token count.

  3. Implement

    KV cache

    Store K/V per layer in a buffer, decode one token per step; tokens must match the no-cache version.

  4. Read

    Andrew Chan, Fast LLM Inference From Scratch

    Sections 2 (CPU: multithreading, quantization and SIMD) and 3 (GPU: matmuls, fusion, attention); compare their gains with yours.

  5. Implement

    Batching

    Static batching of multiple sequences; report throughput vs batch size 1-32.

  6. Read

    LLM.int8() §3.1 Vector-wise Quantization

    Row/column-wise scaling; you only need per-output-channel weight scales, not the mixed-precision decomposition of §3.2.

  7. Implement

    int8 weights

    Dequantize inside the matmul kernel; report perplexity change on the TinyStories validation split.

  8. Read

    Leviathan et al., Speculative Decoding §2.3 and §3.1

    §2.3 Speculative Sampling (Algorithm 1, the accept/reject rule) and §3.1 for the expected number of tokens per step.

  9. Implement

    Speculative decoding

    stories15M drafts for stories110M (same tokenizer); report acceptance rate and speedup vs target-only decoding.

  10. Read

    Accelerating Generative AI with PyTorch II: GPT, Fast

    Llama-7B on A100: 25.5 tok/s baseline, 107.0 with torch.compile and static KV cache, then int8, speculative decoding and int4 up to 244.7 tok/s. Note what each step attacks.

  11. Measure

    Tokens/sec table vs llama2.c

    One row per optimization, with run.c as the baseline; compare your relative gains with the gpt-fast post's.

  12. Implement

    Write the one-page project proposal

    Goal, baseline, metric, plan (see Modules 29-31).

Build

KV cache, batching, int8 weights and speculative decoding for llama2.c models, benchmarked against run.c, plus a project proposal.

Portfolio project: kiln v2.0: an inference server for llama2.c models

kiln, the main project · v2.0 adds an inference server for small LLMs · builds on v1.7 · next: v2.1

Serve stories110M with continuous batching, a paged KV cache, int8 weights and stories15M as a speculative draft. Publish a latency/throughput study at several request rates against run.c and PyTorch eager running the same weights on the same hardware.

Deliverables

  • repo with the server, a load generator and reproducible benchmark scripts
  • README with throughput vs p50/p99 latency curves, and TinyStories validation perplexity for fp32 vs int8
  • an ablation table: each feature on/off and its contribution
  • a 600-1200 word write-up deriving the bandwidth bound on decode tokens/s for your GPU and how close you got

Rubric

Solid
Server handles concurrent requests with correct outputs; int8 within 1% perplexity of fp32; faster than PyTorch eager at batch 1.
Exceptional
Batch-1 decode reaches 50% of the bandwidth bound; paged KV cache shows a measured capacity gain; speculative speedup within 15% of the analytical prediction.

References: Efficient Memory Management for LLM Serving with PagedAttention, Fast Inference from Transformers via Speculative Decoding, gpt-fast (PyTorch Labs), llama2.c

Help

If you get stuck

  • KV cache gives different tokens than no-cache: position indexing (RoPE offset) is wrong for the cached step.
  • Batching slows single-request latency: report both throughput and p50/p99 latency, they trade off.
  • int8 quality collapse: per-tensor scales are too coarse; use per-channel or group-wise scales and check perplexity.
  • Speculative decoding gives no speedup: draft too slow or acceptance too low; measure both and compute the expected speedup.
  • Unfair benchmarks: match batch size, dtype, prompt length and warm-up across systems.

Ready to move on when

  • KV cache tokens identical to no-cache decoding
  • int8 perplexity change reported on TinyStories validation
  • Speculative decoding output distribution preserved (greedy: identical tokens) with acceptance rate and speedup reported
  • Tokens/sec table vs run.c for each optimization
  • One-page proposal written
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • andrewkchan/yalm (KV cache; int8 weights; batching)
    Code for the Fast LLM Inference From Scratch post: CPU and CUDA inference with quantization and fused kernels.
  • gpt-fast generate.py (Speculative decoding)
    Speculative decoding with draft model accept/reject in a few dozen lines, plus the KV-cache decode loop.
  • tinygrad examples/llama.py (KV cache on your compiler)
    LLaMA inference on tinygrad with KV cache and JIT, showing how a tensor compiler runs decode.
  • llama.cpp (int8 weights)
    Production quantized inference; ggml's Q8_0 format and its dot kernels are a reference for your int8 path.

Go deeper (optional)

Talks, papers, code and writing (20)

Lectures

  • CMSC 828G Lecture 15: Inference · University of Maryland
    Compact slide deck tying together KV caching, batching and parallelism for LLM inference; use it as a map before reading the vLLM and SGLang papers.

Talks

  • Unlocking GPU Performance with CUDA Tile · NVIDIA Developer
    NVIDIA's tile-based programming model aimed at kernels like these; useful context for where kernel compilers are heading.

Papers

  • Orca: A Distributed Serving System for Transformer-Based Generative Models · Yu et al. (OSDI 22)
    Introduced iteration-level (continuous) batching; read the scheduling section before building the project's server.
  • SGLang: Efficient Execution of Structured Language Model Programs · Zheng et al.
    RadixAttention for prefix KV reuse; read the radix tree cache section for an extension to your paged cache.
  • GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers · Frantar et al.
    Second-order 4-bit weight quantization; the step past your per-channel int8.
  • AWQ: Activation-aware Weight Quantization · Lin et al.
    Shows scaling salient channels by activation statistics preserves accuracy at 4 bits; read section 3.
  • SmoothQuant · Xiao et al.
    Moves activation outliers into weights to enable int8 activations too; needed if you quantize activations.
  • EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty · Li et al.
    Feature-level drafting with higher acceptance than a separate small model; compare its acceptance rates with your stories15M draft.
  • DistServe: Disaggregating Prefill and Decoding · Zhong et al.
    Separates prefill and decode onto different GPUs to meet latency SLOs; read the goodput definition for your latency study.
  • FlashInfer: Efficient and Customizable Attention Engine for LLM Inference Serving · Ye et al.
    Block-sparse format unifying paged KV and prefix sharing with JIT-generated kernels, close to what your compiler would emit.
  • Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving · Moonshot AI
    Production report on separating prefill and decode clusters around a shared KV cache pool; focus on the scheduler and the overload rejection policy.

Blogs and articles

  • Flash-Decoding for long-context inference · Tri Dao, Daniel Haziza, Francisco Massa, Grigory Sizov
    Splits the KV sequence across blocks for decode-time attention; implement it once batch size is small and context long.
  • Inside vLLM: Anatomy of a High-Throughput LLM Inference System · Aleksa Gordic
    Long 2025 walkthrough of the vLLM V1 engine: scheduler, paged KV cache, chunked prefill, prefix caching and speculative decoding; read the engine core sections first.
  • Look Ma, No Bubbles! Designing a Low-Latency Megakernel for Llama-1B · Hazy Research
    Fusing a whole Llama forward pass into one persistent kernel to remove launch bubbles in batch-1 decode; a good extreme of the fusion ideas from this course.

Code to read

  • vLLM · vLLM project
    The production PagedAttention server; read its scheduler to compare preemption and batching policies.
  • SGLang · SGLang project
    Fast serving runtime; its benchmark scripts give a standard load generator for your server.
  • modded-nanogpt (NanoGPT speedrun) · Keller Jordan et al.
    Record log of GPT-2 training speedups (Muon, FlexAttention, FP8); read the record history for the training side of SOTA.

More reading

  • PagedAttention / vLLM — Paging the KV cache.
  • nano-vllm — Small readable serving engine.
  • Lilian Weng: inference optimization — Survey.
