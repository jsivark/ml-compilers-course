17Parallelism and GPUs

Modern ML compilers target GPUs, so you must understand SIMT execution, the memory hierarchy, and why tiling and fusion matter. CS149 gives the conceptual model, GPU Puzzles builds intuition, and writing real CUDA kernels prepares you to emit them.

about 45–70 h · difficulty ●●●●●

After this module you can

  • After this module you can write CUDA (or Metal/OpenCL) kernels using the thread/block/warp model correctly.
  • After this module you can optimize a GPU matmul with shared-memory tiling, coalescing, register tiling and vectorized loads.
  • After this module you can profile with Nsight Compute and explain occupancy, bank conflicts and memory-bound vs compute-bound behavior.
  • After this module you can implement parallel primitives (reduction, scan, softmax) efficiently.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    Stanford CS149 Lecture 1-2: Why parallelism, modern multi-core processors

    Watch for the core abstractions: multi-core, SIMD, hardware multithreading, latency vs bandwidth.

  2. Do

    CS149 Assignment 1: Programs 1-6 (mandelbrot threads, SIMD intrinsics, ISPC, sqrt, saxpy, kmeans)

    Program 1 threads, Program 2 vectorizing with fake intrinsics, Program 3 ISPC, Program 4 sqrt, Program 5 BLAS saxpy, Program 6 k-means; write the analysis for each.

  3. Watch

    CS149 Lectures on GPU architecture and CUDA programming

    Focus on the CUDA programming model, warps, shared memory.

  4. Do

    GPU Puzzles 1-14 (Map, Zip, Guards, Map 2D, Broadcast, Blocks, Blocks 2D, Shared, Pooling, Dot Product, 1D Convolution, Prefix Sum, Axis Sum, Matrix Multiply)

    Do in Colab: Map, Zip, Guards, Map 2D, Broadcast, Blocks, Blocks 2D, Shared, Pooling, Dot Product, 1D Conv, Prefix Sum, Axis Sum, Matrix Multiply.

  5. Do

    CS149 Assignment 3: A Simple CUDA Renderer

    Part 1 saxpy, Part 2 parallel prefix-sum and find_repeats, Part 3 circle renderer.

  6. Read

    NVIDIA CUDA C++ Programming Guide: Programming Model and Performance Guidelines

    Read the Programming Model chapter and the memory-coalescing/shared memory parts of Performance Guidelines.

  7. Do

    How to Optimize a CUDA Matmul Kernel (Simon Boehm): kernels 1-6

    Reproduce naive -> coalesced -> shared-memory tiling -> 1D blocktiling -> 2D blocktiling -> vectorized; compare against cuBLAS.

  8. Read

    Making Deep Learning Go Brrrr From First Principles (Horace He)

    Compute-, memory- and overhead-bound regimes; why fusion is the compiler's main lever.

  9. Build

    Generate CUDA from your IR

    Read tinygrad's C-style renderer, then emit CUDA source from your rewrite-IR for elementwise and reduce kernels, compile with NVRTC or nvcc, and run.

Build

A CUDA backend for your tensor library: hand-written tiled SGEMM reaching >50% of cuBLAS, plus a code generator that turns fused elementwise+reduce graphs from your IR into CUDA kernels, validated against numpy and benchmarked against unfused execution.

Portfolio project: GPU kernel suite: matmul and fused softmax vs cuBLAS

Write a GPU SGEMM through progressive optimizations and a fused, numerically stable online-softmax kernel. Benchmark against cuBLAS (or MPS on Apple) and explain the gap with profiler evidence. Integrate the kernels as a backend for your module-15 framework.

Deliverables

  • repo with each kernel version, correctness tests vs a reference, and a benchmark script
  • README with GFLOP/s and GB/s plots vs size, percentage of cuBLAS, and Nsight Compute screenshots or metrics tables
  • a 600–1200 word write-up explaining tiling, coalescing, occupancy trade-offs and the online-softmax algorithm

Rubric

Solid
SGEMM reaches 50%+ of cuBLAS on 4096x4096; softmax kernel within 2x of memory bandwidth bound; all tests pass.
Exceptional
SGEMM 80%+ of cuBLAS with warp-tiling/double buffering, softmax near bandwidth peak, profiler-backed analysis, and kernels training a model in your framework.

References: Simon Boehm: How to Optimize a CUDA Matmul Kernel, CUDA C++ Programming Guide

If you get stuck

  • Uncoalesced global loads are the most common slowdown: check access patterns per warp, then confirm in Nsight's memory section.
  • Missing __syncthreads() gives racy, intermittently wrong results; run compute-sanitizer.
  • Shared-memory bank conflicts: pad the tile (e.g. 32x33) and measure.
  • Higher occupancy isn't always faster; register tiling often wins with lower occupancy.
  • No NVIDIA GPU? Use a cloud/Colab GPU or Metal on Apple Silicon; the concepts transfer.

Ready to move on when

  • All 14 GPU Puzzles pass
  • CS149 asst1 Program 1 analysis explains the non-linear speedup from spatial imbalance
  • Your matmul reports achieved memory bandwidth and FLOP/s and you can say which bound applies
  • A fused kernel for relu(x*w+b).sum() is faster than three separate kernels
