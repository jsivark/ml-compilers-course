17Parallelism and GPUs

ML compilers target GPUs, so you need the SIMT execution model, the memory hierarchy, and the reasons tiling and fusion matter. CS149 gives the model, GPU Puzzles drills indexing, and real CUDA kernels prepare you to emit them.

about 55–75 h · difficulty ●●●●●

After this module you can

  • Write CUDA kernels with correct thread, block and warp indexing and bounds guards.
  • Optimize a GPU SGEMM through coalescing, shared-memory tiling, register blocktiling and vectorized loads.
  • Use Nsight Compute to state whether a kernel is memory-bound or compute-bound, with numbers.
  • Implement a parallel exclusive scan and a numerically stable softmax on the GPU.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Stanford CS149 slides, Lectures 1-3: Why Parallelism? Why Efficiency?, A Modern Multi-Core Processor, Multi-Core Architecture Part II + ISPC

    Multi-core, SIMD, hardware multithreading, latency vs bandwidth. The page at this URL is labeled the Fall 2022 offering.

  2. Do

    CS149 Assignment 1: Programs 1-6 (fractal with threads, SIMD intrinsics, ISPC, sqrt, saxpy, k-means)

    Program 1 threads, 2 SIMD intrinsics, 3 ISPC (including tasks), 4 iterative sqrt, 5 BLAS saxpy, 6 k-means. Write the analysis each program asks for.

  3. Read

    CS149 slides, Lecture 7: GPU Architecture and CUDA Programming

    CUDA abstractions and how they map to hardware: threads, blocks, warps, shared memory.

  4. Do

    GPU Puzzles 1-14 (Map, Zip, Guards, Map 2D, Broadcast, Blocks, Blocks 2D, Shared, Pooling, Dot Product, 1D Convolution, Prefix Sum, Axis Sum, Matrix Multiply)

    Run in Colab with Numba's CUDA simulator. Puzzles 1-14.

  5. Do

    CS149 Assignment 3: A Simple CUDA Renderer

    Part 1 SAXPY, Part 2 exclusive prefix sum and find_repeats, Part 3 circle renderer (85 of 100 points).

  6. Read

    NVIDIA CUDA Programming Guide: 1.2 Programming Model and 2.3 Writing SIMT Kernels

    Read the programming model, then the SIMT kernel chapter for memory spaces, shared memory and coalescing.

  7. Do

    How to Optimize a CUDA Matmul Kernel (Simon Boehm): kernels 1-6

    Reproduce Kernel 1 naive, 2 global memory coalescing, 3 shared memory cache-blocking, 4 1D blocktiling, 5 2D blocktiling, 6 vectorized SMEM and GMEM access. Compare each against cuBLAS.

  8. Read

    Making Deep Learning Go Brrrr From First Principles (Horace He)

    Compute, memory-bandwidth and overhead as the three costs, and why fusing memory-bound ops helps.

  9. Build

    Generate CUDA from your IR

    Read tinygrad's C-style renderer, then emit CUDA source from your rewrite-IR for elementwise and reduce kernels, compile with NVRTC or nvcc, and run.

Build

A CUDA backend for your tensor library: hand-written tiled SGEMM reaching >50% of cuBLAS, plus a code generator that turns fused elementwise+reduce graphs from your IR into CUDA kernels, validated against numpy and benchmarked against unfused execution.

Portfolio project: GPU kernel suite: matmul and fused softmax vs cuBLAS

Write a GPU SGEMM through progressive optimizations and a fused, numerically stable online-softmax kernel. Benchmark against cuBLAS (or MPS on Apple) and explain the gap with profiler evidence. Integrate the kernels as a backend for your module-15 framework.

Deliverables

  • repo with each kernel version, correctness tests vs a reference, and a benchmark script
  • README with GFLOP/s and GB/s plots vs size, percentage of cuBLAS, and Nsight Compute screenshots or metrics tables
  • a 600–1200 word write-up explaining tiling, coalescing, occupancy trade-offs and the online-softmax algorithm

Rubric

Solid
SGEMM reaches 50%+ of cuBLAS on 4096x4096; softmax kernel within 2x of memory bandwidth bound; all tests pass.
Exceptional
SGEMM 80%+ of cuBLAS with warp-tiling/double buffering, softmax near bandwidth peak, profiler-backed analysis, and kernels training a model in your framework.

References: Simon Boehm: How to Optimize a CUDA Matmul Kernel, CUDA C++ Programming Guide

If you get stuck

  • Uncoalesced global loads are the most common slowdown; check the per-warp access pattern, then confirm in Nsight Compute's memory section.
  • A missing __syncthreads() gives intermittently wrong results; run compute-sanitizer --tool racecheck.
  • Shared-memory bank conflicts: pad the tile (for example 32x33) and measure.
  • Higher occupancy is not always faster; register tiling often wins at lower occupancy.
  • No NVIDIA GPU: GPU Puzzles run in Colab; for asst3 and SGEMM use a cloud or Colab GPU.

Ready to move on when

  • All 14 GPU Puzzles pass
  • CS149 asst1 Program 1 analysis explains why speedup is not linear in thread count (uneven work across image regions)
  • Your matmul reports achieved memory bandwidth and FLOP/s and you can say which bound applies
  • A fused kernel for relu(x*w+b).sum() is faster than three separate kernels

Going deeper (optional)

  • Programming Massively Parallel Processors (Hwu, Kirk, El Hajj) — Textbook for CUDA.
  • Triton tutorials — Block-level DSL compiler; compare to your codegen.
  • GPU MODE lectures — Community lecture series on kernels.
