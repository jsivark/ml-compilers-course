Before compiling tensor programs you need to build a tensor library: strides, broadcasting, autograd on tensors, and fast kernels. MiniTorch and CMU DLSys walk you through exactly that, in pieces small enough to finish.

about 45–70 h · difficulty ●●●●○

After this module you can

  • After this module you can build a small deep-learning framework with lazy tensors, an op set, and pluggable backends.
  • After this module you can implement strided ndarray views (reshape, permute, expand) without copying.
  • After this module you can explain kernel fusion, memory planning and how frameworks like tinygrad and PyTorch schedule work.
  • After this module you can train a CNN or small transformer end-to-end on your own framework.

  3. Do

    Tensor data with strides and indexing, broadcasting, tensor operations, tensor autodiff, training. Strides are the key concept for tinygrad's ShapeTracker/views.

  4. Do

  5. Do

Build

A tinygrad-like tensor library in Python: strided Tensor with views (reshape/permute/expand without copy), broadcasting, reverse-mode autograd, a CPU backend in C via ctypes with tiled matmul, and an MNIST MLP training to >97% accuracy.

Portfolio project: Lazy-evaluating mini-framework with fusion and a benchmark against PyTorch CPU

Turn your framework lazy: build an op graph, fuse elementwise chains and reductions into single kernels (generated C or NumPy expressions), and plan buffer reuse. Train a small transformer (character-level) and report speed and memory versus eager mode and versus PyTorch CPU.

Deliverables

  • repo with lazy graph, fusion pass, codegen backend, memory planner, and a char-level transformer training script
  • README with kernel-count, peak-memory and tokens/sec comparisons (eager vs fused vs PyTorch CPU) and loss curves
  • a 600–1200 word write-up explaining the fusion rules, where fusion is illegal, and the memory planner design

Rubric

Solid
Fused mode reduces kernel launches 3x+ and matches eager numerics (1e-5); transformer loss converges.
Exceptional
Within 2x of PyTorch CPU tokens/sec, a liveness-based memory planner with measured savings, and a visualization of the scheduled graph.

References: CMU 10-414/714 Deep Learning Systems, tinygrad

If you get stuck

  • Stride bugs: write an exhaustive test comparing your view ops to NumPy on random shapes before building on them.
  • Non-contiguous tensors break naive kernels; decide where you call contiguous() and test both paths.
  • Numerical instability in softmax/log-softmax: subtract the max.
  • Training that doesn't learn is usually a gradient bug: overfit a single batch first.
  • Read tinygrad source in small pieces (tensor.py, then ops) rather than all at once.

Ready to move on when

  • permute/expand/reshape produce views (no data copy) verified by shared storage
  • All MiniTorch Module 2 tests pass
  • Your tiled matmul is at least 5x faster than the naive triple loop at 1024x1024
  • MNIST trains to >97% test accuracy with your library
