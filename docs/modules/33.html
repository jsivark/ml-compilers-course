33CUTLASS, CuTe and Hopper/Blackwell features

The fastest kernels on H100/B200 (FlashAttention-3, cuBLAS-class GEMMs) use TMA, wgmma and warp specialization, which Triton only partly exposes. Teams writing inference kernels expect you to read and write CuTe layouts.

about 60–90 h · difficulty ●●●●●

After this module you can

  • After this module you can read and write CuTe layouts and layout algebra
  • After this module you can build a TMA+wgmma pipelined GEMM on Hopper
  • After this module you can explain FlashAttention-3's scheduling and reproduce part of it
  • After this module you can choose between Triton, ThunderKittens and CUTLASS for a given kernel

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Simon Boehm, How to Optimize a CUDA Matmul Kernel

    Re-derive kernels 1-10 quickly as a warm-up; this is the baseline vocabulary for the rest.

  2. Read

    CuTe quickstart (CUTLASS docs)

    Then read 01_layout, 02_layout_algebra, 03_tensor, 0x_gemm_tutorial in the same folder.

  3. Practice

    CuTe docs folder: layout algebra exercises

    Hand-compute composition, complement and logical_divide on 2-3 layouts; check with cute::print.

  4. Read

    Colfax: CUTLASS tutorial, design of a GEMM kernel

    Mainloop/epilogue split, pipelining stages, how CUTLASS composes collectives.

  5. Read

    Colfax: Mastering the NVIDIA Tensor Memory Accelerator (TMA)

    TMA descriptors, multicast, mbarrier synchronization.

  6. Read

    Colfax: Fast matrix multiplication using wgmma

    Warpgroup MMA, smem layout requirements, async fences.

  7. Read

    PTX ISA: wgmma and cp.async.bulk sections

    Look up wgmma.mma_async and cp.async.bulk.tensor; see exactly what CuTe emits.

  8. Read

    FlashAttention-3

    Sections 3.1-3.3: producer/consumer warp specialization, ping-pong scheduling, FP8 incoherent processing.

  9. Read

    ThunderKittens paper

    Tile primitives as a middle ground between Triton and CUTLASS; compare abstractions.

  10. Implement

    ThunderKittens: build and run an example kernel

    Run the H100 GEMM/attention example; profile with Nsight Compute and identify the pipeline.

  11. Implement

    Write a Hopper GEMM in CuTe

    TMA load -> smem -> wgmma, 2-4 stage pipeline, then add warp specialization. No GPU with sm90? Rent one by the hour.

Build

A from-scratch CuTe GEMM for H100 progressing from SIMT to wgmma+TMA+warp-specialized, each step benchmarked.

Portfolio project: FP8 or bf16 attention/GEMM on Hopper with a public benchmark

Implement a warp-specialized Hopper kernel for a real workload: either a grouped GEMM for MoE layers or a decode-time attention kernel (paged KV). Benchmark against cuBLAS/FlashAttention-3/FlashInfer across shapes taken from Llama or DeepSeek configs, and document every optimization with profiler evidence.

Deliverables

  • repo with the kernel, a PyTorch extension binding and correctness tests
  • README with TFLOPS tables vs. baselines across >=6 real shapes
  • a 600–1200 word write-up walking through the pipeline, layouts and the remaining gap

Rubric

Solid
>=60% of the best public baseline on all shapes, correct to fp tolerance, profiler screenshots
Exceptional
Matches or beats the baseline on some shapes (e.g. small-batch decode) and explains why with occupancy/pipeline analysis; upstreamable quality

References: FlashAttention-3, ThunderKittens

If you get stuck

  • Template error walls: compile tiny examples first and use cute::print/print_latex to inspect layouts
  • wgmma hangs or garbage: missing fence/commit/wait or wrong smem swizzle; compare with the Colfax wgmma post line by line
  • No Hopper GPU: do the layout and SIMT parts locally, then rent an H100 for a few hours with a script ready
  • TMA descriptor errors: global tensor must be 16-byte aligned and strides multiples of 16 bytes
  • Lost in CUTLASS 3 collectives: read the Colfax GEMM design post before the source

Ready to move on when

  • Final GEMM reaches >=70% of cuBLAS bf16 at 8192^2 on H100
  • You can draw the CuTe layout (shape:stride) of an smem tile with swizzle
  • You can explain why warp specialization helps when TMA is async
  • Nsight Compute report shows tensor-core utilization per version
