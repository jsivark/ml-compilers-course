22Movement ops

reshape, permute, pad, shrink and expand never copy: they are index arithmetic plus validity masks. Simplifying the resulting div/mod expressions with bounds is what makes the generated code fast.

about 25–35 h · difficulty ●●●●○

After this module you can

  • After this module you can represent views as shape+strides+offset+mask and compose them.
  • After this module you can lower reshape, permute, expand, pad and shrink to index arithmetic without copies.
  • After this module you can simplify div/mod index expressions using value bounds.
  • After this module you can tell when a view chain cannot be merged and a copy is required.

Rubric

10k+ random chains pass; every simplification rule z3-proven; measurable reduction in index op count.
Exceptional

References: Hypothesis documentation (property-based testing), Z3 theorem prover (Python bindings via z3-solver)

If you get stuck

  • Reshape after permute is not always a view: strides become non-mergeable. Detect it and fall back to a realized buffer.
  • Padding mask applied to the wrong axis or not propagated through later views: test pad then permute then shrink.
  • Index expressions explode in size: you are not simplifying (x//a)*a + x%a. Add the rule plus bounds-based folding.
  • Negative strides or flips break bounds: compute vmin/vmax with sign awareness.
