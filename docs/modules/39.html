39Research, open source and career

Hiring managers and grad committees look for evidence: merged PRs in real compilers, a reproduced paper, leaderboard results and clear writing. This module produces that evidence.

about 60–120 h (spread over weeks) · difficulty ●●●●●

StepsBuildProjectHelpGo deeper

After this module you can

  • Reproduce a systems paper's headline result and report where it differs
  • Get a change reviewed and merged in a large open-source compiler or runtime

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Karpathy, A Recipe for Training Neural Networks

    Apply its process to reproductions: inspect the data, overfit a small case first, and verify each step before scaling.

  2. Read

    Simon Peyton Jones, How to Write a Great Research Paper

    Seven concrete suggestions; apply them to your reproduction write-up.

  3. Practice

    Pick and reproduce a recent paper

    For example KernelBench (linked), a FlashAttention variant or one of the quantization papers from Module 36. Match one headline number, then run ablations.

  4. Practice

    KernelBench

    Solve Level 1 (single-kernel operators) and Level 2 (fusion patterns) problems by hand and track speedup over PyTorch; read how the benchmark scores LLM-written kernels.

  5. Practice

    GPU MODE

    Community site for the GPU MODE kernel leaderboards and lectures; find a currently open competition.

  6. Practice

    GPU MODE reference kernels

    Problem definitions and reference implementations used by the leaderboards; submit a solution to one.

  7. Implement

    Land a PR in tinygrad

    Read the README's Contributing section: no code golf, docs and whitespace PRs closed, claimed speedups must be benchmarked, large diffs not reviewed, and PRs that look AI-written from new contributors are closed. Start from a bounty or a bug with a failing test.

  8. Implement

    Or land a PR in PyTorch

    Look for 'good first issue' labels in Inductor and Dynamo; follow the CLA and test instructions.

  9. Implement

    Or Triton / vLLM

    Small backend fixes or performance issues; vLLM kernels are at github.com/vllm-project/vllm.

  10. Implement

    Portfolio and interview prep

    Pin 4-6 project repos. Practice, in 45 minutes each: a tiled matmul, a reduction, roofline math, a fusion pass and a sharding cost estimate.

Build

One reproduced paper with a public report, at least one merged PR in a major ML compiler/runtime, a leaderboard submission and a polished portfolio.

Project

Not a second capstone. This is the research track of the capstone (Modules 29 to 31): choose it there if you want your capstone to be a research contribution. Go to Module 29.

Help

If you get stuck

  • PR stalls: pick issues maintainers asked for, keep diffs small, include benchmarks, reply quickly
  • Reproduction does not match: check hardware and library versions, then email the authors one precise question
  • Too many goals: one paper, one PR, one leaderboard entry
  • Interview nerves: practice out loud with a timer and explain tradeoffs as you code

Ready to move on when

  • A merged (not only opened) PR in tinygrad, PyTorch, Triton, vLLM, JAX/XLA or MLIR
  • Reproduction matches a headline number within the paper's reported variance
  • A ranked GPU MODE leaderboard submission or a KernelBench result with a write-up
  • In a timed mock interview you derive roofline numbers and write a correct tiled kernel
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • ThunderKittens (Capstone: kernel paper ported to new GPU/precision)
    Readable, fast attention and GEMM kernels with benchmarks, a good base for porting a kernel paper to a new GPU.
  • gpt-fast (Paper reproduction and upstream contribution)
    Small, well-documented PyTorch inference stack with int8/int4 and speculative decoding; easy to reproduce and extend.
  • BackendBench (KernelBench and leaderboard step)
    Correctness and performance harness for PyTorch operator kernels; shows how benchmark tooling is written.
  • DeepGEMM (Reproduce a recent paper)
    Clean FP8 GEMM kernels for Hopper from DeepSeek with JIT compilation; a reproduction target.

Stretch project

Pick an open problem on a GPU MODE leaderboard or KernelBench Level 3, reach a top-10 ranking or a 1.5x speedup over the torch.compile baseline, and publish the kernel, a profile-driven write-up and an upstream PR that ships it in a library such as torchao, vLLM or tinygrad.
