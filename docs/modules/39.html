39Research, open source and career

Hiring managers and grad committees judge evidence: merged PRs in real compilers, a reproduced paper, leaderboard results and clear writing. This module turns your skills into that evidence.

about 60–120 h (spread over weeks) · difficulty ●●●●●

After this module you can

  • After this module you can reproduce and extend a systems paper end to end
  • After this module you can work effectively in a large open-source compiler codebase and get changes merged
  • After this module you can present your work in writing and interviews at a top-lab bar
  • After this module you can pick a research direction and justify it with evidence

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Karpathy, A Recipe for Training Neural Networks

    The mindset for reproductions: become one with the data, overfit first, verify every step.

  2. Read

    Simon Peyton Jones, How to Write a Great Research Paper

    Apply to your reproduction write-up.

  3. Practice

    Pick and reproduce a recent paper

    E.g. KernelBench (linked), a FlashAttention variant or a quantization paper. Match a headline number, then ablate.

  4. Practice

    KernelBench

    Solve level-1/2 problems by hand and track speedup; know how LLM kernel agents are evaluated.

  5. Practice

    GPU MODE community and leaderboards

    Submit to an active kernel competition; join the Discord reading groups.

  6. Practice

    GPU MODE reference kernels

    Problem definitions used by the leaderboards.

  7. Implement

    Land a PR in tinygrad

    Read the contributing rules (line count, tests, bounties); start with a bounty or a bug with a failing test.

  8. Implement

    Or land a PR in PyTorch

    Inductor/Dynamo 'good first issue' labels; follow the CLA and test instructions.

  9. Implement

    Or Triton / vLLM

    Small backend fixes or perf issues; vLLM kernels at github.com/vllm-project/vllm.

  10. Implement

    Portfolio and interview prep

    Pin 4-6 project repos; prepare to whiteboard a tiled matmul, a reduction, roofline math, a fusion pass and a sharding cost estimate in 45 minutes each.

Build

One reproduced paper with a public report, at least one merged PR in a major ML compiler/runtime, a leaderboard submission and a polished portfolio.

Portfolio project: Capstone: a research-grade contribution

Combine a reproduction with a new idea: e.g. extend a kernel paper to a new hardware or precision, or a scheduling result to a new compiler, and upstream the useful part. Present it as a short paper plus a talk.

Deliverables

  • repo with code, scripts and data to reproduce every figure
  • README with headline results and links to merged PRs
  • a 4-6 page workshop-style paper and a 15-minute recorded talk

Rubric

Solid
Reproduction matches, one merged PR, paper with clear claims and ablations
Exceptional
A novel result accepted at a workshop (e.g. MLSys, NeurIPS workshop) or a feature merged upstream that maintainers use, plus a talk at GPU MODE or a reading group

References: KernelBench, GPU MODE

If you get stuck

  • PR stalls: pick issues maintainers asked for, keep diffs small, include benchmarks, respond fast
  • Reproduction doesn't match: email the authors early with a precise question; check hardware and versions
  • Overwhelmed by scope: one paper, one PR, one leaderboard; depth beats breadth
  • Interview anxiety: practice out loud with a timer; explain tradeoffs, not just code

Ready to move on when

  • A merged (not just opened) PR in tinygrad, PyTorch, Triton, vLLM, JAX/XLA or MLIR
  • Reproduction repo matches a headline number within the paper's reported variance
  • A ranked leaderboard submission (GPU MODE or KernelBench-style) with writeup
  • Mock interview: you can derive roofline numbers and write a correct tiled kernel live
