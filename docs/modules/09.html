09Transformers

The transformer is the workload that ML compilers are tuned for today: matmuls, softmax, layernorm and attention. Building one end to end shows you exactly which ops a compiler must fuse and schedule.

about 35–55 h · difficulty ●●●●○

After this module you can

  • After this module you can implement a GPT-style forward pass from scratch and load pretrained GPT-2 weights into it.
  • After this module you can compute attention shapes, FLOPs per token and KV cache size for a given transformer config.
  • After this module you can train a small character-level language model with nanoGPT and read its loss curves.
  • After this module you can explain prefill vs decode and why batch-1 decode is memory-bound.

  7. Read

Build

A GPT-2 124M forward pass in NumPy, written by you along the lines of picoGPT, that loads the OpenAI weights and produces the same greedy tokens as picoGPT. Then train nanoGPT shakespeare_char to val loss below 1.5, and annotate llama2.c's run.c forward() line by line in your own notes.

Portfolio project: A C inference engine for GPT-2 with KV cache, benchmarked

Write a single-file C (or C with OpenMP) inference engine for GPT-2 124M that loads the weights you exported from NumPy, implements a KV cache, and generates text matching your NumPy reference token for token. Measure prefill and decode throughput, compare decode tokens/s against the memory-bandwidth bound you compute from model size, and add int8 weight-only quantization with a perplexity comparison.

Deliverables

  • repo with the C engine, a weight-export script, and a test that greedy output matches the NumPy reference exactly
  • README with tokens/s for prefill and decode, with and without KV cache, fp32 vs int8, against the computed bandwidth roofline
  • a 600–1200 word write-up explaining why decode is memory-bound, what the KV cache saves, and the accuracy cost of quantization

Rubric

Solid
Greedy output matches the reference for 100+ tokens; KV cache gives a measured speedup that grows with sequence length; numbers reported with the hardware stated.
Exceptional
Decode reaches at least 50% of the memory-bandwidth bound, int8 perplexity on a held-out text stays within 1–2% of fp32, and the code is clean enough to compare favourably with llama2.c's run.c.

References: karpathy/llama2.c, kipply, Transformer Inference Arithmetic

If you get stuck

  • Output differs from picoGPT: check the GELU variant (tanh approximation), the layernorm eps, and weight orientation. Hugging Face GPT-2 uses Conv1D, which stores weights as (in, out), so use x @ W.
  • Mask applied after softmax, or with 0 instead of -inf: apply it to the scores before softmax.
  • Head reshape bugs: (B,T,C) to (B,H,T,d) is a reshape then a transpose. Print shapes at every step.
  • No GPU: the README's small CPU config for shakespeare_char reaches about 1.88, not 1.5. Use --device=mps on Apple Silicon, or a GPU, for the default config.
  • FLOP counting: a (m,k) x (k,n) matmul is 2mkn FLOPs.

Ready to move on when

  • Write the attention tensor shapes for batch B, sequence T, heads H and head dim d at every step.
  • Explain why the causal mask is applied before softmax and why scores are divided by sqrt(d).
  • Count FLOPs per token for GPT-2 124M and estimate whether batch-1 decoding is memory-bound on your hardware.
  • Your NumPy GPT-2 output matches picoGPT token for token.
  • State what the KV cache saves and compute its size in bytes for GPT-2 124M at 1024 tokens.

Reference implementations

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • jaymody/picoGPT gpt2.py (Build: NumPy GPT-2 124M forward)
    The reference NumPy GPT-2 forward pass your build must match token for token.
  • nanoGPT model.py (Let's build GPT; nanoGPT shakespeare_char)
    Karpathy's PyTorch GPT with from_pretrained loading GPT-2 weights, including the Conv1D transpose handling.
  • llm.c train_gpt2.py (Project: weight export script)
    Writes GPT-2 weights to a flat binary that train_gpt2.c reads; the same export plan your C engine needs.
  • karpathy/llama2.c run.c (Project: C inference engine with KV cache and int8)
    Single-file C inference with KV cache, matmul with OpenMP and an int8 runq.c variant in the same repo.
  • gpt-fast (Project: int8 weight-only quantization)
    Under 1000 lines of PyTorch with int8 and int4 weight-only quantization and measured tokens/s; compare your quantization error and speed.

Going deeper

Optional. The best talks, papers, code and writing on this module topic, from people who shaped the field.

Courses

  • Stanford CS336: Language Modeling from Scratch · Percy Liang, Tatsunori Hashimoto
    Assignment 2 (systems) has you write a Triton FlashAttention and profile; lectures on GPUs and kernels follow this module.

Videos

  • Let's reproduce GPT-2 (124M) · Andrej Karpathy
    Four hours from model code to a trained GPT-2; the second hour on TF32, bf16, torch.compile and flash attention shows where speed comes from.

Papers

  • FlashAttention · Dao, Fu, Ermon, Rudra, Re
    Tiled, IO-aware exact attention with online softmax; read section 3.1 to see why the naive attention you wrote is memory-bound.
  • A Mathematical Framework for Transformer Circuits · Elhage, Nanda, Olsson et al. (Anthropic)
    Views attention as QK and OV circuits writing to a residual stream; read the zero- and one-layer sections.
  • Fast Transformer Decoding: One Write-Head is All You Need (MQA) · Noam Shazeer
    Shows decode is bound by KV cache reads and cuts them by sharing K and V across heads.
  • Efficient Memory Management for LLM Serving with PagedAttention (vLLM) · Kwon et al.
    Paged KV cache allocation; read section 4 after your engine's contiguous KV cache works.

Books

  • How to Scale Your Model · Austin, Douglas, Frostig, Levskaya et al. (Google DeepMind)
    Read the roofline chapter, then 'All the Transformer Math' for FLOP and parameter counting.
  • How to Scale Your Model: All About Transformer Inference · Google DeepMind
    Prefill vs decode, KV cache size and the memory-bandwidth bound on decode, worked numerically; matches the project's benchmark.

Blogs and articles

  • Making Deep Learning Go Brrrr From First Principles · Horace He
    Compute, memory bandwidth and overhead as the three regimes; apply it to classify each op in your GPT-2.
  • Modal GPU Glossary · Modal
    Short linked definitions of SMs, warps, tensor cores, HBM and roofline; keep it open when reading GPU performance material.
  • Inside vLLM: Anatomy of a High-Throughput LLM Inference System · Aleksa Gordic
    2025 code-level walk through vLLM's engine core, paged attention, continuous batching, prefix caching and speculative decoding; read parts 1-2 for the scheduler and KV cache manager.
  • Defeating Nondeterminism in LLM Inference · Horace He and Thinking Machines Lab
    Explains why inference output changes with batch size (non batch-invariant matmul, RMSNorm and attention kernels) and how to write batch-invariant kernels.

Code to read

  • flash-attention-minimal · Peter Kim
    FlashAttention forward in about 100 lines of CUDA; read it after the paper to see the tiling as code.
  • llama.cpp · Georgi Gerganov and contributors
    Production CPU and GPU inference with k-quant formats; read ggml-quants.c to compare with your int8 scheme.
  • modded-nanogpt · Keller Jordan and contributors
    The nanoGPT speedrun record log; each entry is a measured trick (Muon, rotary, FlexAttention) on the 124M model.
  • nanochat · Andrej Karpathy
    A full tokenizer-to-chat-UI LLM pipeline in one small repo; read the inference engine for a KV-cached decode loop.
  • LLMs-from-scratch · Sebastian Raschka
    Chapter notebooks building a GPT in PyTorch; the bonus folders on KV cache, GQA and MLA are the parts most relevant to inference kernels.

More reading
