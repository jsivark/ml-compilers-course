Part I · Foundations

09Deep learning core

MLPs, CNNs, initialization, normalization and optimizers. These are the models your compiler must train correctly and fast.

about 50–70 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • After this module you can implement a tensor-level autograd with broadcasting-aware gradients and train MNIST on it.
  • After this module you can read activation and gradient histograms and fix training with initialization, normalization or optimizer changes.
  • After this module you can write backward passes for batchnorm, cross-entropy and convolution by hand.
  • After this module you can implement SGD with momentum and Adam and state their update rules.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    Karpathy, makemore part 1: a bigram language model

    Counting vs neural bigram model. Watch for the keepdim broadcasting bug Karpathy points out.

  2. Watch

    Karpathy, makemore part 2: an MLP language model

    Embeddings, minibatches, learning-rate search, train/dev/test splits. Type the code yourself.

  3. Read

    CS231n notes: neural network architecture

    Activation functions and representational power.

  4. Watch

    Karpathy, makemore part 3: activations, gradients and BatchNorm

    Kaiming init, saturated tanh, BatchNorm. Reproduce the activation and gradient histograms.

  5. Read

    CS231n notes: data, initialization, regularization and training

    Then neural-networks-3/ for gradient checks, SGD with momentum and Adam.

  6. Watch

    Karpathy, makemore part 4: write backprop by hand

    Do the notebook's 4 exercises: manual backward through the whole network, cross-entropy in one step, BatchNorm in one step, then all together. The cmp() helper checks each gradient against PyTorch.

  7. Watch

    Karpathy, makemore part 5: build a WaveNet

    torch.nn-style module structure and shape debugging.

  8. Read

    CS231n notes: convolutional neural networks

    Conv layer output-size arithmetic and the "implementation as matrix multiplication" (im2col) part of the Convolutional Layer section.

  9. Do

    CS231n assignment 1: classifiers and fully connected nets from scratch

    Vectorize every loss and gradient. The fully vectorized versions are the point.

  10. Do

    CS231n assignment 2: BatchNorm, dropout, CNNs and PyTorch on CIFAR-10

    Optional. Do at least Q3 (ConvolutionalNetworks.ipynb); the naive conv forward and backward are the loops a compiler later rewrites.

Build

Extend your Module 8 engine (or your Module 7 NDArray) into a tensor-level autograd with matmul, broadcast ops, sum, log-softmax and cross-entropy, plus SGD-momentum and Adam. Train a 2-layer MLP on MNIST to >97% test accuracy, and compare loss curves with an identical PyTorch model.

Portfolio project: kiln v0.5: train a CNN and profile where time goes

kiln, the main project · v0.5 adds enough layers and tooling to train a CNN · builds on v0.4 · next: v0.5.1

Grow kiln into a small framework with Conv2d (via im2col), MaxPool, BatchNorm, Dropout, a DataLoader and a module system, and train a small CNN on CIFAR-10 to at least 60% test accuracy. Profile one training step, break the time down by op, then speed up the slowest op (for example a vectorized im2col or a C extension) and report the gain.

Deliverables

  • repo with the framework, gradient tests against PyTorch for every op, and the training script
  • README with loss and accuracy curves vs an identical PyTorch model, plus a per-op time breakdown before and after optimization
  • a 600–1200 word write-up on what dominated training time and why, linking it to the arithmetic intensity of each op

Rubric

Solid
Every op gradient-checked against PyTorch; CIFAR-10 at least 60% test accuracy; profile breakdown and one optimization with measured speedup.
Exceptional
At least 70% on CIFAR-10, the training curve tracks PyTorch's within noise given the same seed and init, and the write-up uses FLOP and byte counts to predict which ops are compute-bound vs memory-bound.

References: Horace He, Making Deep Learning Go Brrrr From First Principles

Help

If you get stuck

  • Broadcast-add gradient has the wrong shape: sum the upstream gradient over the broadcast axes so it matches the input shape.
  • makemore Part 4 BatchNorm backward: derive it on paper with shapes first. Karpathy's notebook uses Bessel's correction (n-1) in the variance, which changes the gradient.
  • MNIST stuck near 10% accuracy: check input normalization, label alignment, and that softmax runs over the class axis.
  • Adam does not match PyTorch: check bias correction and that eps is added after the sqrt.

Ready to move on when

  • makemore Part 4 notebook: every cmp() line reports exact or approximate True.
  • Explain why Kaiming init scales weights by gain/sqrt(fan_in) and what happens to tanh activations without it.
  • Explain BatchNorm train vs eval behaviour and its backward pass in one paragraph.
  • Compute output shape and parameter count of a conv layer from input size, kernel, stride and padding.
  • CS231n A1 two_layer_net.ipynb and FullyConnectedNets.ipynb complete with their gradient checks passing.

Talks, papers, code and writing (22)

Lectures

  • UW CSEP 590A lecture 3 slides: optimization for deep learning · University of Washington
    Initialization schemes, batch, layer and group normalization, and optimizers in one deck; use it as a checklist when your CNN stops training.

Courses

  • MIT 6.7960 Deep Learning (videos, notes, problem sets) · MIT OpenCourseWare
    A full graduate deep learning course with videos and problem sets; use its problem sets to test yourself after CS231n Assignment 2.
  • MIT 6.S191 Introduction to Deep Learning · MIT
    Short recorded lectures with labs; a quick refresher on the overall landscape before the CNN project.
  • Stanford CS312 lecture slides: hyperparameters, scaling laws, optimizers, µP and Muon · Stanford CS312 (Hashimoto, Kotha)
    Optional. Slides only, no recordings yet. Lectures 2-4 match the Muon and tuning-playbook readings above.

Papers

  • Batch Normalization · Ioffe, Szegedy
    Section 3 gives the training and inference transforms and the backward pass you implement.
  • Delving Deep into Rectifiers (the Kaiming init paper) · He, Zhang, Ren, Sun
    Section 2.2 derives the sqrt(2/fan_in) initialization from variance propagation.
  • Adam: A Method for Stochastic Optimization · Kingma, Ba
    Algorithm 1 on page 2 is the exact update with bias correction; implement it from this box.
  • Deep Residual Learning (the ResNet paper) · He, Zhang, Ren, Sun
    Residual connections, the architecture your CNN project should try once plain conv stacks plateau.
  • 94% on CIFAR-10 in 3.29 Seconds on a Single GPU · Keller Jordan
    Ablations of each speedrun trick, a model for how to report the speedup in your project.

Blogs and articles

  • Why Momentum Really Works · Gabriel Goh (Distill)
    Interactive analysis of momentum on quadratics; play with the step size and momentum sliders to see divergence.
  • Muon: An optimizer for hidden layers · Keller Jordan
    A recent optimizer that orthogonalizes updates via Newton-Schulz; implement it as a third optimizer after SGD and Adam.
  • Deriving Muon · Jeremy Bernstein
    Derives Muon as steepest descent under an operator norm; read it after the Muon post to see why orthogonalizing the update is principled.
  • What really matters in matrix-whitening optimizers? · Kevin Frans
    Controlled comparison of Shampoo, SOAP and Muon style optimizers; focus on the finding that variance adaptation matters beyond spectral normalization.

Code to read

  • Deep Learning Tuning Playbook · Google Research (Godbole, Dahl, Gilmer, Shallue, Nado)
    A systematic procedure for tuning learning rate, batch size and schedules; read the incremental tuning section.
  • cifar10-airbench: very fast CIFAR-10 training · Keller Jordan
    94% on CIFAR-10 in a few seconds on one A100; read airbench94.py to see which tricks matter for speed.
