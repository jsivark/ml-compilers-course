09Transformers

The transformer is the workload that ML compilers are tuned for today: matmuls, softmax, layernorm and attention. Building one end to end shows you exactly which ops a compiler must fuse and schedule.

about 45–65 h · difficulty ●●●●○

After this module you can

  • After this module you can implement a GPT-style transformer forward pass from scratch and load real pretrained weights into it.
  • After this module you can write attention shapes, FLOPs and memory per token for any transformer configuration.
  • After this module you can train a small language model and interpret its loss curves.
  • After this module you can explain the inference loop (prefill vs decode, KV cache) and why decode is memory-bound.

Build

GPT-2 124M forward pass in about 60 lines of NumPy that loads the OpenAI weights and generates the same greedy text as the reference picoGPT. Then train nanoGPT shakespeare_char to val loss <1.5, and annotate llama2.c's run.c forward() line by line in your own notes.

Portfolio project: A C inference engine for GPT-2 with KV cache, benchmarked

Write a single-file C (or C with OpenMP) inference engine for GPT-2 124M that loads the weights you exported from NumPy, implements a KV cache, and generates text matching your NumPy reference token for token. Measure prefill and decode throughput, compare decode tokens/s against the memory-bandwidth bound you compute from model size, and add int8 weight-only quantization with a perplexity comparison.

Deliverables

  • repo with the C engine, a weight-export script, and a test that greedy output matches the NumPy reference exactly
  • README with tokens/s for prefill and decode, with and without KV cache, fp32 vs int8, against the computed bandwidth roofline
  • a 600–1200 word write-up explaining why decode is memory-bound, what the KV cache saves, and the accuracy cost of quantization

Rubric

Solid
Greedy output matches the reference for 100+ tokens; KV cache gives a measured speedup that grows with sequence length; numbers reported with the hardware stated.
Exceptional
Decode reaches at least 50% of the memory-bandwidth bound, int8 perplexity on a held-out text stays within 1–2% of fp32, and the code is clean enough to compare favourably with llama2.c's run.c.

References: karpathy/llama2.c, kipply, Transformer Inference Arithmetic

If you get stuck

  • Outputs differ from the reference: check GELU variant (tanh approximation), layernorm eps, and whether the weights are stored transposed (GPT-2 uses Conv1D, so the matrices are transposed).
  • Causal mask applied after softmax, or with 0 instead of -inf: apply it to the scores before softmax.
  • Head reshape bugs: (B,T,C) to (B,H,T,d) needs a reshape then a transpose; print shapes at every step.
  • nanoGPT on CPU or a Mac: use the small shakespeare_char config with device=cpu or mps and expect higher loss; a free Colab GPU is enough for the target.
  • FLOP counting: a matmul of (m,k)x(k,n) is 2mkn FLOPs; kipply's post shows the per-token totals.

Ready to move on when

  • Write out attention shapes for batch B, seq T, heads H, head dim d at every step.
  • Explain why the causal mask is applied before softmax and why scores are divided by sqrt(d).
  • Count FLOPs per token for GPT-2 124M and estimate whether batch-1 decoding is memory-bound.
  • Your NumPy GPT-2 output matches picoGPT token for token.
  • Explain what the KV cache saves and its memory cost.
