18UOps, rewrites, bounds

Everything later in the course is a rewrite on one hash-consed graph of (op, src, arg) nodes, so this module sets the data structure you will live in for 14 modules. Getting interning, cached properties and interval bounds right now prevents compounding slop later.

about 25–35 h · difficulty ●●●○○

After this module you can

  • After this module you can represent a program as a typed UOp DAG and validate it against a spec.
  • After this module you can write pattern-matching rewrite rules and run them to a fixed point.
  • After this module you can compute integer value bounds (vmin/vmax) through ALU ops and use them to fold code.
  • After this module you can explain why a rewrite is sound and when it is not (overflow, division semantics).

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Handout page 1: the format and grammar

    Read page 1 only: tokens (DEF, REF, INT, BOOL, OP, ATTR, brackets), the 4-line grammar, filename prefixes and immediate limits. Write the grammar on paper before coding.

  2. Implement

    Tokenizer and parser

    Turn a .uir file into a list of bindings (name, op, atoms, attrs); handle comments, hex, leading zeros, %x= vs %x =, and [ ] sugar. Make comments_and_spacing, xor_hex, leading_zeros, stack_sugar_same parse; REJECT rejected_undefined_ref, rejected_redefined, rejected_unknown_op, rejected_int_literal_range.

  3. Read

    tinygrad-notes: UOp is a singleton

    How a metaclass cache makes structural equality equal object identity; then glance at UOpMetaClass in ops.py (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/uop/ops.py#L181).

  4. Implement

    Interned UOp(op, src, arg)

    Build nodes through one constructor keyed by (op, src, arg) so equal triples return the same object. Pass hashcons_same_node.uir and make the node/edge counter that overbudget_many_nodes needs.

  5. Implement

    Lazy dtype and shape + validator

    Cache dtype/shape per node; reject dtype mismatches, ALU on vectors, free params, missing args, unreachable nodes, missing/used assert. Targets: all rejected_* except the index/limits ones (add_dtype_mismatch, alu_on_vector, stack_mixed, where_cond_int, div_bool, free_param, no_assert, assert_used, unreachable, vector_return, two_params_one_slot, missing_arg, arg_dtype).

  6. Read

    Handout page 2: the operation reference table

    Read the Bounds and Cost columns row by row: wrapping widens to I, div/mod endpoint rules, xor exact-only-for-singletons, shl hull, cmplt/where.

  7. Read

    tinygrad UOp._min_max (vmin/vmax)

    Read _min_max after drafting your own: note how each op derives bounds from source bounds, then skim test/null/test_uop_vmin_vmax.py (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/test/null/test_uop_vmin_vmax.py).

  8. Implement

    Bounds and index/limit safety

    Implement interval bounds per the table and use them to prove index and call-argument safety across all calls. Pass index_param_safe, index_mod_bounds_safe, index_stack and rejected_index_oob, rejected_index_const_oob, rejected_index_unbounded, rejected_arg_outside_limits, rejected_limits_reversed.

  9. Implement

    Cost and budgets

    Cost per node once (call = 1 + C(body) each time), then the three budget checks in the right order (bytes before parse, nodes/edges after parse, cost after validation). Pass overbudget_file_size, overbudget_many_nodes, overbudget_static_cost, cost_under_budget.

  10. Implement

    Evaluator

    Interpret the graph with exact i32 wrap, floor div/mod with the divide-by-zero conventions, shl mod 32, bool add/mul semantics, and call/param substitution. Pass every MATCH and mismatch_* file: run python3 run_tests.py 1.

  11. Read

    tinygrad-notes: pattern matcher, then UPat/PatternMatcher source

    Read the note, then UPat (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/uop/ops.py#L1429), PatternMatcher (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/uop/ops.py#L1572) and graph_rewrite (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/uop/ops.py#L1877).

  12. Implement

    UPat + PatternMatcher + graph_rewrite to fixed point

    Write a matcher over (op, src patterns, named captures) and a bottom-up rewrite loop that reaches a fixed point; check yourself against test/null/test_pattern_matcher.py (https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/test/null/test_pattern_matcher.py).

  13. Implement

    Constant folding and identities

    Rules: fold all-constant ALU via your evaluator, x+0, x*1, x*0, x^x, max(x,x), where(true,a,b). Verify every MATCH test folds to assert c c; compare to symbolic_simple in https://github.com/tinygrad/tinygrad/blob/b91fe2773cbc1a33c38c90b55c835e26be42a335/tinygrad/uop/symbolic.py#L123.

  14. Test

    Write 10 tests of your own

    Target obvious-but-wrong compilers: wrap at INT_MIN, div/mod by negative, index bounds that only fail on the second call, shared vs distinct cost. Check each with the oracle (only after passing 65/65).

Build

./compile parses, validates, bounds-checks, costs, evaluates and constant-folds Week 1 UIR files.

Portfolio project: Proved-correct symbolic simplifier with a rewrite visualizer

Turn your rewrite engine into a verified simplifier: encode every integer rewrite rule as a z3 query over bitvectors (int32 wraparound included) and refuse to load rules that are not proven equivalent under their stated preconditions. Add a tracer that records each rule firing and renders before/after DAGs per pass, so you can show exactly how an index expression collapses.

Deliverables

  • repo with a rule file, a z3 checker CLI (check_rules) and CI that fails on any unproven rule
  • an HTML or Graphviz trace viewer showing each rewrite step on 3+ real index expressions from later modules
  • README with a table: rules count, proven/rejected, node-count reduction on a benchmark set of 200+ expressions
  • a 600–1200 word write-up on one rule z3 rejected, why it was wrong, and the corrected precondition

Rubric

Solid
30+ rules all z3-proven at 32-bit width; simplifier reduces node count on the benchmark set by a measured amount; trace viewer works on any UIR file.
Exceptional
Finds and documents at least one real unsound rule (yours or in a published compiler) with a counterexample; uses bounds as z3 assumptions so conditional rules are proven too; compares against an egg-style e-graph on the same set.

References: Z3 theorem prover (Python bindings via z3-solver), egg: Fast and Extensible Equality Saturation, Graphviz

If you get stuck

  • Rewrites that never terminate: usually two rules undo each other (a+b -> b+a). Canonicalize operand order instead of swapping.
  • Bounds wrong for division/modulo with negatives: C truncates toward zero, Python floors. Pick one semantics and test negative operands explicitly.
  • Constant folding changed results: you folded in Python ints but the target is int32. Wrap to the dtype width when folding.
  • Validator passes but evaluator crashes: check every src arity/dtype in the validator, not only the op name.
  • Rewrites applied to a node but children unchanged: rewrite bottom-up and rebuild parents when any child changes (hash-cons nodes).
