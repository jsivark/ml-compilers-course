18UOps, rewrites, bounds

Every later week is a rewrite on one hash-consed graph of (op, src, arg) nodes. This module builds that graph, its cached dtype/shape/bounds/cost properties, and the rewrite engine you will reuse through Module 31.

about 25-35 h · difficulty ●●●○○

StepsBuildProjectHelpGo deeper

After this module you can

  • Parse UIR into an interned UOp DAG where equal (op, src, arg) triples are one object.
  • Compute dtype, shape, interval bounds and cost per node, and use bounds to accept or reject every index and call.
  • Write UPat rules and run graph_rewrite to a fixed point to fold every Week 1 MATCH test to assert c c.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Handout page 1: the format and grammar

    Page 1 only: the token table (DEF, REF, INT, BOOL, OP, ATTR, brackets, EOF), the 4-line grammar, the filename-prefix table and the immediate limits (bytes > 4096; nodes >= 100 or edges >= 300; cost >= 1,000,000). Write the grammar down before coding.

  2. Implement

    Tokenizer and parser

    Turn a .uir file into a list of bindings (name, op, atoms, attrs); handle comments, hex, leading zeros, %x= vs %x =, and [ ] sugar. Make comments_and_spacing, xor_hex, leading_zeros, stack_sugar_same parse; REJECT rejected_undefined_ref, rejected_redefined, rejected_unknown_op, rejected_int_literal_range.

  3. Read

    tinygrad-notes: UOp is a singleton

    UOpMetaClass keeps a cache keyed by (op, dtype, src, arg), so building the same triple twice returns the same object. Then read UOpMetaClass at the pinned commit: tinygrad · ops.py#L181 on GitHub. The note is from Jan 2025 and the code has moved since, so trust the source.

  4. Implement

    Interned UOp(op, src, arg)

    Build nodes through one constructor keyed by (op, src, arg) so equal triples return the same object. hashcons_node_budget.uir (120 copies of add 2 4) only passes if equal triples are shared. Count distinct nodes and source edges here; overbudget_many_nodes needs the count.

  5. Implement

    Lazy dtype and shape + validator

    Cache dtype/shape per node and reject: rejected_add_dtype_mismatch, alu_on_vector, stack_mixed, where_cond_int, div_bool, free_param, no_assert, assert_used, assert_dtype_mismatch, unreachable, vector_return, two_params_one_slot, missing_arg, arg_dtype (all with the rejected_ prefix).

  6. Read

    Handout page 2: the operation reference table

    Read the Bounds and Cost columns row by row: overflowing i32 bounds widen to I; div uses endpoint quotients only for a fixed y; mod has three cases (variable y, zero, fixed nonzero y); xor is exact only for two singletons; shl is a hull over possible k; then the two worked boxes (index safety, shared vs distinct cost).

  7. Read

    tinygrad UOp._min_max (vmin/vmax)

    Read _min_max after drafting your own and note how each op derives bounds from source bounds. Then skim the tests in tinygrad · test_uop_vmin_vmax.py on GitHub.

  8. Implement

    Bounds and index/limit safety

    Interval bounds per the page 2 table, used to prove index and call-argument safety across all calls. Pass index_param_safe, index_mod_bounds_safe, index_stack, and REJECT rejected_index_oob, rejected_index_const_oob, rejected_index_unbounded, rejected_arg_outside_limits, rejected_limits_reversed.

  9. Implement

    Cost and budgets

    Charge each node once (a call costs 1 + C(body) each time it appears). Check budgets in the handout's order: bytes before parsing, nodes/edges right after parsing, cost after validation. Pass overbudget_file_size, overbudget_many_nodes, overbudget_static_cost, cost_under_budget.

  10. Implement

    Evaluator

    Interpret the graph with i32 wrap, floor div/mod (div by 0 gives -1, mod by 0 gives x), shl by y mod 32, bool add as OR and mul as AND, and call/param substitution. Pass every MATCH and mismatch_ file in python3 run_tests.py 1.

  11. Read

    tinygrad-notes: Pattern matcher, then UPat/PatternMatcher source

    Read the note (written against an older tinygrad), then the pinned source: UPat (tinygrad · ops.py#L1429 on GitHub), PatternMatcher (tinygrad · ops.py#L1572 on GitHub) and graph_rewrite (tinygrad · ops.py#L1877 on GitHub).

  12. Implement

    UPat + PatternMatcher + graph_rewrite to fixed point

    A matcher over (op, src patterns, named captures) and a bottom-up rewrite loop that stops when nothing changes. Port 5 cases from tinygrad · test_pattern_matcher.py on GitHub as your own unit tests.

  13. Implement

    Constant folding and identities

    Rules: fold all-constant ALU through your evaluator, x+0, x*1, x*0, x^x, max(x,x), where(true,a,b). Every MATCH test must fold to assert c c. Compare with symbolic_simple: tinygrad · symbolic.py#L123 on GitHub.

  14. Test

    Write 10 tests of your own

    Cases an obvious-but-wrong compiler gets wrong: add at INT_MIN/INT_MAX, div/mod by a negative divisor, an index that is only out of range on the second call, shared vs distinct cost. Work out each expected result by hand from the page 2 table.

Build

./compile parses, validates, bounds-checks, costs, evaluates and constant-folds Week 1 UIR files.

Portfolio project: kiln v1.0: the 10-411 compiler as kiln's backend, with a z3-checked simplifier

kiln, the main project · v1.0 adds the 10-411 compiler as kiln's backend, starting with a checked simplifier · builds on v0.8 · next: v1.1

From here on, your 10-411 compiler lives inside kiln as its backend (for example kiln/compiler), and the course test suites run against it. Turn your v0.6 rewrite engine into a checked simplifier. Encode each integer rule as a z3 query over 32-bit bitvectors (wraparound included) and refuse to load any rule that z3 cannot prove under its stated preconditions. Add a tracer that records each rule firing and renders before/after graphs.

Deliverables

  • repo with a rule file, a check_rules CLI that runs z3 on every rule, and CI that fails on an unproven rule
  • a Graphviz or HTML trace of each rewrite step on 3 index expressions taken from your Week 5 (Module 22) output
  • README table: rule count, proven/rejected, and node-count reduction on 200+ expressions (the week01-05 tests plus cases ported from tinygrad's test_uop_symbolic.py)
  • a 600-1200 word write-up on one rule z3 rejected, its counterexample, and the corrected precondition

Rubric

Solid
30+ rules, all z3-proven at 32-bit width; measured node-count reduction on the 200+ expression set; trace works on any UIR file.
Exceptional
Uses interval bounds as z3 assumptions so conditional rules (e.g. x%n -> x when 0<=x<n) are proven too; documents at least one unsound rule you wrote first, with its counterexample.

References: Z3 theorem prover (Python bindings via z3-solver), egg: Fast and Extensible Equality Saturation (POPL 2021), Graphviz

Help

If you get stuck

  • Rewrites never terminate: two rules undo each other (a+b -> b+a). Canonicalize operand order once instead of swapping.
  • div/mod with negatives disagree: the spec is floor division (Python //), not C truncation. Test div_floor_negative and mod_negative_divisor first.
  • Folding changes results: you folded with Python ints. Wrap to 32 bits after every folded add, mul and shl.
  • Validator passes but evaluator crashes: check src count and dtype per op in the validator, not only the op name.
  • A rewritten child does not show up in the parent: rebuild the parent through the interning constructor when any source changes.

Ready to move on when

  • python3 run_tests.py 1 prints 66/66 passed
  • hashcons_node_budget.uir and hashcons_cost_shared_call.uir pass, which only happens if identical nodes are shared
  • Every MATCH test rewrites to assert c c through your PatternMatcher
  • 10+ own tests in tests/week01 with hand-derived expected outcomes
Reference implementations (5)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • tinygrad uop/uir.py: parse_uir (Tokenizer and parser)
    tinygrad's own reader for the UIR text format, which its docstring says also parses studentgrad's hand-written %names, nested (op ...) and [stacks]; compare tokenizing, literal handling and how each line becomes a hash-consed UOp.
  • tinygrad test/null/test_uir_render.py (Interned UOp(op, src, arg))
    Round-trip tests asserting parse_uir(render_uir(x)) is x, a ready-made test pattern for your parser and interning.
  • tinygrad uop/spec.py: type_verify and spec_shared (Lazy dtype and shape + validator)
    How tinygrad expresses dtype and structure rules as a PatternMatcher and rejects graphs that match none; compare with your validator's reject list.
  • tinygrad uop/validate.py: validate_index_with_z3 (Bounds and index safety)
    Translates UOps to z3 with bounded variables to prove an index in range, the exact check your bounds give you cheaply; useful for differential-testing your vmin/vmax.
  • tinygrad uop/upat.py: upat_compile (Rewrite engine)
    Compiles UPat patterns into straight Python source for speed; read after your interpreted rewrite engine works.

Talks, papers, code and writing (21)

Talks

  • Lean-MLIR: a workbench for formally verifying peephole optimizations for MLIR (slides) · Keizer, Bhat (LLVM Dev Meeting 2024)
    Shows Alive-style proofs of peephole rewrites in Lean; skim the section on verifying LLVM peepholes for how a rewrite rule is stated as a theorem.

Papers

  • Provably Correct Peephole Optimizations with Alive · Nuno Lopes, David Menendez, Santosh Nagarakatte, John Regehr
    Sections 2-3 show how to state a rewrite rule with preconditions and check it with an SMT solver, the discipline your symbolic rules need.
  • Abstract Interpretation: A Unified Lattice Model for Static Analysis of Programs · Patrick Cousot, Radhia Cousot
    The founding paper; read the interval example and the widening section to see why overflowing bounds become I.
  • Type-Safe Modular Hash-Consing · Jean-Christophe Filliatre, Sylvain Conchon
    Short paper on hash-consing with weak tables; the section on memory explains why tinygrad needs weakrefs in its UOp cache.
  • Better Together: Unifying Datalog and Equality Saturation · Yihong Zhang et al.
    egglog: rewrites plus analyses such as intervals in one engine; read after egg to see bounds-aware rewriting done declaratively.

Blogs and articles

  • Testing Dataflow Analyses for Precision and Soundness · John Regehr
    Shows how to fuzz an abstract domain (known bits, ranges) for soundness and precision; apply it directly to your vmin/vmax.
  • Abstract interpretation in the Toy Optimizer · Max Bernstein
    A small runnable abstract interpreter over an SSA IR; the clearest bridge from your bounds pass to the general theory.
  • Adventures with TinyGrad: the Pattern Matcher · xl0
    A second independent walkthrough of UPat and graph_rewrite with runnable examples; focus on how a rule's lambda returns a new UOp and how rules are dispatched.
  • Value numbering · Max Bernstein
    Short 2026 post building local value numbering from hash-consing plus union-find; read it to see why UOp dedup is the same idea as LVN.
  • Hash Consing Absolutism · Justin Jaffray
    Argues about hash-consing every node versus best-effort dedup, using the Simple compiler as the example; useful for deciding what your UOp cache must guarantee.
  • The mask that compiles to nothing: how HotSpot's JIT learned to reason about bits · QuestDB
    Explains why ranges and known bits refine each other (a reduced product), with the [5,41] to [8,40] example; apply the same trick to your bounds analysis.

Code to read

  • Alive2 · AliveToolkit
    The successor tool that checks real LLVM optimizations; browse its bug list to see how often confident rewrites are wrong.
  • LLVM ConstantRange.cpp · LLVM project
    Production interval arithmetic with wrap-around; read add, multiply, udiv and shl to compare with the handout's bounds table.
  • LLVM KnownBits.cpp · LLVM project
    The bit-level domain that complements ranges; its xor/and/shl transfer functions are tighter than intervals for bit ops.
  • Sea of Nodes: Simple · Cliff Click et al.
    A chapter-by-chapter hash-consed graph IR with peephole rewrites and type lattices, the closest relative of a UOp graph in a classic compiler.
  • Souper · Google
    A superoptimizer that synthesizes missing peephole rules; a source of ideas for discovering rules instead of hand-writing them.
  • TVM rewrite_simplify.cc · Apache TVM
    A large production rule set for index-expression simplification; read the div/mod rules and compare them to tinygrad's symbolic.py.
