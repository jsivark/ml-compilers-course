32Triton and tile-based GPU programming

Triton is the code TorchInductor generates for GPUs, and Liger Kernel and many FlashAttention variants are written in it. You program tiles, not threads. You already wrote a CUDA codegen backend; now add a Triton one.

about 45–65 h · difficulty ●●●●○

After this module you can

  • Write and autotune Triton kernels for matmul, reductions and attention.
  • Generate Triton from your own compiler IR.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Tillet, Kung, Cox: Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations (MAPL 2019)

    Sections 3-5: Triton-C, Triton-IR, and Triton-JIT (tile-level passes and the auto-tuner in 5.3). Compare Triton-IR with your own IR.

  2. Implement

    Triton tutorial 01: Vector Addition

    program_id, masks, BLOCK_SIZE as tl.constexpr; run the benchmark and plot GB/s vs. size.

  3. Implement

    Triton tutorial 02: Fused Softmax

    One row per program. The tutorial's plot shows Triton about 4x faster than the unfused Torch JIT version; reproduce that comparison on your GPU.

  4. Implement

    Triton tutorial 03: Matrix Multiplication

    Block tiling, program re-ordering for L2 hit rate (GROUP_SIZE_M), autotune configs. The tutorial claims fp16 performance on par with cuBLAS; measure your ratio at 4096^2.

  5. Implement

    Triton tutorial 04: Low-Memory Dropout

    Seeded dropout using Triton's Philox-based RNG: regenerate the mask from a seed instead of storing it.

  6. Implement

    Triton tutorial 05: Layer Normalization

    Forward and backward. The hard part is the backward's two-stage parallel reduction of dW/db using Lock/Count and tl.atomic_cas.

  7. Implement

    Triton tutorial 06: Fused Attention

    The tutorial implements the FlashAttention-2 algorithm. Read it alongside the FA2 paper below.

  8. Practice

    Triton-Puzzles (Sasha Rush)

    12 puzzles, from Constant Add to Simple FlashAttention (9), 2D convolution (10), matmul (11) and quantized matmul (12). They run in the Triton interpreter, no GPU needed.

  9. Read

    FlashAttention (Dao et al. 2022)

    Sections 2-3: tiling and recomputation (3.1), IO-complexity analysis (3.2). Derive the HBM-access bound yourself.

  10. Read

    FlashAttention-2

    Section 3: algorithm (3.1), parallelism over sequence length (3.2), work partitioning between warps (3.3).

  11. Read

    Horace He, Making Deep Learning Go Brrrr

    Classify each kernel you benchmark as compute-, memory- or overhead-bound.

  12. Test

    Port one of your compiler's kernels to a Triton backend

    Add a Triton codegen target for elementwise+reduce fusions; diff outputs against your CUDA backend.

Build

A Triton backend for your compiler (elementwise and reduction codegen) plus the six tutorials reproduced with benchmark plots.

Portfolio project: Fused kernel library: beat torch.compile on three real ops

In nanoGPT (GPT-2 124M config, block size 1024) write Triton forward and backward kernels for RMSNorm+residual, SwiGLU, and fused linear cross-entropy over the 50,257-token vocab. Autotune them, swap them into the model, and report training step time and peak memory against eager PyTorch and torch.compile.

Deliverables

  • repo with kernels, gradcheck tests and a pip-installable package
  • README with roofline plots (achieved GB/s or TFLOPS vs. peak) across sizes
  • a 600–1200 word write-up explaining each fusion, the bound it hits and what limited further gains

Rubric

Solid
All three kernels pass gradcheck; each is >=1.3x eager and within 10% of torch.compile; roofline plot per kernel
Exceptional
At least one kernel beats torch.compile by >=1.2x end to end, e.g. a chunked fused cross-entropy that cuts peak memory by >2x, with Nsight Compute evidence for why

References: Liger Kernel (fused Triton kernels for LLM training), Triton tutorial 05: Layer Normalization

If you get stuck

  • Wrong results only at odd sizes: you forgot a mask on load or store; test sizes like 1000 and 4097, not just powers of two
  • Autotune 'wins' that vanish: you benchmarked with a cold cache or included compilation; use triton.testing.do_bench
  • Layernorm backward races: re-read the lock/atomic section of tutorial 05 before inventing your own reduction
  • Attention numerically off: check you rescale the running accumulator when the running max changes (FA2 paper, Algorithm 1)
  • Puzzles confusing: print shapes with the interpreter mode (TRITON_INTERPRET=1) on CPU

Ready to move on when

  • Tutorial 03 matmul reaches >=80% of torch.matmul (cuBLAS) fp16 TFLOPS at 4096^2 on your GPU
  • Fused attention matches torch SDPA to 1e-2 (fp16) for causal and non-causal
  • Your compiler emits Triton for a fused LayerNorm and it passes your test suite
  • You can explain grouped program ordering and why it raises L2 hit rate
