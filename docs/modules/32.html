32Triton and tile-based GPU programming

Triton is how most new production kernels get written at OpenAI, Meta and in TorchInductor. Programming whole tiles instead of threads is the mental model the frontier works in; you already wrote a codegen backend, now learn the one industry uses.

about 45–65 h · difficulty ●●●●○

After this module you can

  • After this module you can write, autotune and profile Triton kernels for matmul, reductions and attention
  • After this module you can reason about tile shapes, num_warps and num_stages from roofline numbers instead of guessing
  • After this module you can generate Triton from your own compiler IR
  • After this module you can read and modify FlashAttention-style kernels

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Tillet, Kung, Cox: Triton (MAPL 2019)

    Sections 3-5: Triton-C, Triton-IR, the tile-level optimization passes. Compare with your own IR.

  2. Implement

    Triton tutorial 01: Vector Addition

    Learn program_id, masks, BLOCK_SIZE as constexpr; run the benchmark and plot GB/s vs. size.

  3. Implement

    Triton tutorial 02: Fused Softmax

    Row-per-program reduction; note why fusion makes this memory-bound kernel ~2x faster than eager torch.

  4. Implement

    Triton tutorial 03: Matrix Multiplication

    Block tiling, L2 'grouped ordering' of program ids, autotune configs. Reach >=80% of cuBLAS on fp16.

  5. Implement

    Triton tutorial 04: Low-Memory Dropout

    Counter-based Philox RNG in-kernel: recompute masks instead of storing them.

  6. Implement

    Triton tutorial 05: Layer Normalization

    Forward and backward; the backward's two-stage parallel reduction of dW/db with locks is the hard part.

  7. Implement

    Triton tutorial 06: Fused Attention

    FlashAttention-2 in Triton: online softmax, causal masking stages. Read alongside the papers below.

  8. Practice

    Triton-Puzzles (Sasha Rush)

    Do all puzzles through Flash Attention and the quantized matmul; they force you to reason about shapes and masks without a GPU.

  9. Read

    FlashAttention (Dao et al. 2022)

    Sections 2-3: IO-aware tiling, recomputation. Derive the HBM-access bound yourself.

  10. Read

    FlashAttention-2

    Sections 3.1-3.3: work partitioning across warps and sequence-length parallelism.

  11. Read

    Horace He, Making Deep Learning Go Brrrr

    Compute vs. memory vs. overhead bound: use this lens on every kernel you benchmark.

  12. Test

    Port one of your compiler's kernels to a Triton backend

    Add a Triton codegen target to your compiler for elementwise+reduce fusions; diff results vs. your CUDA backend.

Build

A Triton backend for your compiler (elementwise, reduction and matmul codegen) plus all six tutorials reproduced with benchmark plots.

Portfolio project: Fused kernel library: beat torch.compile on three real ops

Pick three ops that appear in a real model (e.g. RMSNorm+residual, rotary embedding fused into QKV projection, SwiGLU, fused cross-entropy over a large vocab). Write Triton kernels with forward and backward, autotune them, and drop them into a nanoGPT-sized model. Show end-to-end training step speedup against eager and torch.compile.

Deliverables

  • repo with kernels, gradcheck tests and a pip-installable package
  • README with roofline plots (achieved GB/s or TFLOPS vs. peak) across sizes
  • a 600–1200 word write-up explaining each fusion, the bound it hits and what limited further gains

Rubric

Solid
All three kernels pass gradcheck; each is >=1.3x eager and within 10% of torch.compile; roofline plot per kernel
Exceptional
At least one kernel beats torch.compile by >=1.2x end to end, e.g. a chunked fused cross-entropy that cuts peak memory by >2x, with Nsight Compute evidence for why

References: Liger Kernel (fused Triton kernels for LLM training), Triton tutorial 05: Layer Normalization

If you get stuck

  • Wrong results only at odd sizes: you forgot a mask on load or store; test sizes like 1000 and 4097, not just powers of two
  • Autotune 'wins' that vanish: you benchmarked with a cold cache or included compilation; use triton.testing.do_bench
  • Layernorm backward races: re-read the lock/atomic section of tutorial 05 before inventing your own reduction
  • Attention numerically off: check you rescale the running accumulator when the running max changes (FA2 paper, Alg. 1)
  • Puzzles confusing: print shapes with the interpreter mode (TRITON_INTERPRET=1) on CPU

Ready to move on when

  • Tutorial 03 matmul reaches >=80% of cuBLAS fp16 TFLOPS at 4096^2
  • Fused attention matches torch SDPA to 1e-2 (fp16) for causal and non-causal
  • Your compiler emits Triton for a fused LayerNorm and it passes your test suite
  • You can explain grouped program ordering and why it raises L2 hit rate
