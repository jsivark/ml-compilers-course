12IRs, SSA and optimization passes

Real compilers optimize on an intermediate representation, not the AST. CS6120's self-guided course with the Bril IR teaches control-flow graphs, dataflow analysis and SSA through small implementable tasks, which is exactly the machinery tinygrad-style compilers use on their own IRs.

about 40–55 h · difficulty ●●●●○

After this module you can

  • After this module you can build a CFG and convert it to SSA using dominance frontiers or the Braun et al. algorithm.
  • After this module you can implement dataflow analyses (liveness, reaching definitions) as a generic worklist solver.
  • After this module you can write DCE, constant propagation, GVN/CSE and LICM passes and prove they preserve semantics with tests.
  • After this module you can read LLVM IR and MLIR and map their concepts onto your own IR.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    CS6120 Lesson 1: Welcome & Overview

    Watch the video and read the course policies to understand the self-guided format.

  2. Do

    CS6120 Lesson 2: Representing Programs -- video + task

    Install the Bril tools (bril2json, brili), then do the task: write a Bril program and a tool that forms basic blocks and a CFG from Bril JSON in Python.

  3. Do

    CS6120 Lesson 3: Local Analysis & Optimization -- video + task

    Implement trivial dead code elimination (TDCE) and local value numbering (LVN) in Bril; measure dynamic instruction counts with 'brili -p' on the benchmarks.

  4. Do

    CS6120 Lesson 4: Data Flow -- video + task

    Write a generic worklist dataflow solver and instantiate it for at least reaching definitions and constant propagation.

  5. Do

    CS6120 Lesson 5: Global Analysis & SSA -- video + task part 1 (dominators)

    Compute dominators, the dominator tree and dominance frontiers; test against brute-force path enumeration.

  6. Do

    CS6120 Lesson 5 task part 2: into and out of SSA

    Implement into-SSA (phi insertion + renaming) and out-of-SSA; check round-tripped programs produce identical output under brili.

  7. Watch

    CS6120 Lesson 6: LLVM -- video + task

    Write a small LLVM pass (e.g. replace one instruction pattern). Optional if C++ setup is painful; at least watch the video.

  8. Do

    CS6120 Lesson 7: Loop Optimization -- video + task

    Implement natural loop detection and loop-invariant code motion on SSA Bril. Loops are where ML kernels live.

  9. Watch

    CS6120 Lesson 11: Dynamic Compilers

    Watch and read the linked tracing-JIT paper summary; PyTorch/JAX tracing is the same idea applied to tensor programs. Lessons 8-10 (interprocedural, alias analysis, memory management) are optional.

  10. Build

    Lower your Module 11 compiler through a Bril-like IR

    Read the Bril language reference, then add a three-address IR stage to mycc and apply your LVN/DCE passes before codegen.

Build

A Python optimizer for Bril with: CFG construction, generic dataflow framework, dominators, SSA conversion in and out, LVN+TDCE, and LICM; a script runs all bril/benchmarks before and after and reports dynamic instruction count reductions with correctness checks.

Portfolio project: An optimizing middle-end with a measured pass pipeline

Build an SSA middle-end (on Bril or your own IR) with at least SCCP, GVN, LICM and aggressive DCE, then study pass ordering. Report dynamic instruction count reductions on a benchmark suite and run a translation-validation style check (interpreter equivalence on random inputs) after every pass.

Deliverables

  • repo with IR, SSA construction/destruction, 4+ optimization passes and a pass manager
  • README with a table of dynamic instruction counts per benchmark per pass and a pass-ordering heatmap
  • a 600–1200 word write-up explaining SSA construction, why SCCP beats separate const-prop + DCE, and one miscompile you found

Rubric

Solid
All passes preserve semantics on the Bril benchmark set; 20%+ average dynamic instruction reduction over unoptimized.
Exceptional
Pass pipeline competitive with LLVM -O1 on comparable inputs, a fuzzer that found real bugs, and a principled pass-ordering experiment (e.g. search over orders) with insights.

References: Cornell CS 6120: Advanced Compilers (Bril), Simple and Efficient Construction of SSA Form (Braun et al.)

If you get stuck

  • Phi placement errors: compute dominators first and test them on hand-drawn CFGs; a wrong dominator tree breaks everything downstream.
  • Out-of-SSA translation needs parallel copies; naive sequential copies cause the lost-copy and swap problems.
  • Passes that 'work' but miscompile: run every pass in isolation and in random order, checking interpreter output matches (Bril's brili is handy).
  • Dataflow not terminating means your transfer function isn't monotone or lattice isn't finite.
  • Don't optimize before you can print and parse your IR round-trip; debugging without a text format is miserable.

Ready to move on when

  • All Bril benchmarks produce identical output before and after your passes
  • LVN catches 'a = x + y; b = y + x' as a common subexpression (commutativity)
  • Your SSA output has exactly one definition per variable and phis only at dominance frontiers
  • You can draw the dominator tree of a nested loop CFG by hand and it matches your tool

Going deeper (optional)

  • Engineering a Compiler (Cooper & Torczon) ch. 8-9 — Textbook depth on optimization and dataflow.
  • SSA Book (Static Single Assignment Book) — Free reference on SSA construction and destruction.
  • Simple and Efficient Construction of SSA Form (Braun et al.) — Alternative SSA construction used in many modern compilers.
