38Distributed training and inference at scale

Large models do not fit on one GPU. This module covers how training and serving systems shard models, what communication each scheme adds, and how to measure it.

about 50–75 h · difficulty ●●●●●

After this module you can

  • Compute memory and communication volume for data, tensor, pipeline and ZeRO sharding
  • Implement sharded training and a 1F1B schedule on torch.distributed and verify them against single-GPU loss
  • Explain paged KV caches and continuous batching in vLLM

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    How to Scale Your Model (JAX scaling book)

    Part 1 (rooflines), Part 3 (sharded matmuls), Part 4 (transformer math) and Part 5 (training); do the worked problems. Part 12 covers GPUs.

  2. Read

    The Ultra-Scale Playbook (Hugging Face)

    Data, tensor, pipeline, context and expert parallelism, with measured throughput and memory.

  3. Read

    ZeRO: Memory Optimizations Toward Training Trillion Parameter Models

    Section 3 (where memory goes), Section 5 (optimizer, gradient and parameter partitioning) and Section 7 (communication volume).

  4. Implement

    Getting Started with Fully Sharded Data Parallel (FSDP2)

    Run the fully_shard example, then profile how all-gather and reduce-scatter overlap with compute.

  5. Read

    Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism

    Column- and row-parallel MLP and attention; count the all-reduces per layer.

  6. Read

    Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM

    Section 2.2 (pipeline bubbles, 1F1B, interleaved stages) and Section 3 (choosing tensor, pipeline and data parallel sizes). GPipe is arXiv 1811.06965.

  7. Read

    Ring Attention with Blockwise Transformers for Near-Infinite Context

    Blockwise attention across devices with KV blocks passed around a ring, overlapped with compute.

  8. Read

    GShard: Scaling Giant Models with Conditional Computation and Automatic Sharding

    Expert parallelism and all-to-all dispatch; Switch Transformers is arXiv 2101.03961.

  9. Read

    Efficient Memory Management for LLM Serving with PagedAttention (vLLM)

    KV-cache paging and continuous batching.

  10. Read

    NCCL environment variables (NCCL_ALGO, NCCL_PROTO)

    The algorithms (Ring, Tree, NVLS, ...) and protocols (LL, LL128, Simple) NCCL chooses from; force each on an all-reduce and measure bandwidth vs. message size.

  11. Implement

    Mini-parallelism library

    On torch.distributed: ZeRO-3-style parameter sharding, a 1F1B pipeline and a tensor-parallel MLP; test correctness on 2 processes with gloo, then on 2-8 GPUs.

Build

A from-scratch library (FSDP-style sharding, tensor parallelism, 1F1B pipeline) training GPT-2 small (124M) on multiple GPUs, with communication profiled.

Portfolio project: Scale a model and publish an MFU report

Train a GPT-2-style 1.3B model on 8 GPUs (A100/H100 class) using your library with 2D or 3D parallelism, and push MFU as high as you can with an ablation of each change. Optional: ring attention at 32k context, or expert parallelism for an 8-expert MoE variant.

Deliverables

  • repo with the library, configs and launch scripts
  • README with MFU, tokens/s and memory tables across parallelism configs plus profiler traces
  • a 600–1200 word write-up on what limited scaling and how you fixed it

Rubric

Solid
>=35% MFU on 8 GPUs with loss matching a reference run and an ablation table
Exceptional
>=45% MFU, or a working long-context or MoE extension, with a cost model that predicts measured step time within 15%

References: How to Scale Your Model, The Ultra-Scale Playbook

If you get stuck

  • Hang: ranks issued collectives in different orders; log every collective with rank and shape
  • Loss differs from single-GPU: check gradient averaging by world size and per-rank RNG seeding
  • No multi-GPU machine: test correctness on CPU with gloo, then rent 8 GPUs for a few hours for performance runs
  • Bubble larger than expected: compare microbatches m to stages p; the bubble fraction is (p-1)/m

Ready to move on when

  • For each parallelism, the loss over 200 steps matches single-GPU training to within 1% at the same global batch and seed
  • Measured memory per GPU matches your ZeRO math within 10%
  • A profiler trace shows all-gather or reduce-scatter overlapped with compute
  • You report MFU and the pipeline bubble fraction (p-1)/m for each run
