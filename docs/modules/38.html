38Distributed training and inference at scale

Frontier models never fit on one GPU. Labs need people who can reason about sharding, communication overlap and serving systems; it is the single most in-demand systems skill right now.

about 50–75 h · difficulty ●●●●●

After this module you can

  • After this module you can derive memory and communication cost for any parallelism combination
  • After this module you can implement FSDP, TP and pipeline schedules from scratch
  • After this module you can profile and fix communication bottlenecks
  • After this module you can explain serving systems: paged KV, continuous batching, expert parallelism

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    How to Scale Your Model (JAX scaling book)

    Read the rooflines, sharding and transformer-math chapters; do every exercise.

  2. Read

    The Ultra-Scale Playbook (Hugging Face)

    Data, tensor, pipeline, context and expert parallelism with measurements.

  3. Read

    ZeRO (Rajbhandari et al.)

    Stages 1-3 memory math; then the PyTorch FSDP tutorial below.

  4. Implement

    PyTorch FSDP tutorial

    Run it, then profile the all-gather/reduce-scatter overlap.

  5. Read

    Megatron-LM tensor parallelism

    Column/row-parallel MLP and attention; count the all-reduces.

  6. Read

    GPipe and Megatron 1F1B / interleaved schedules

    Section 2: pipeline bubbles, 1F1B, interleaving; GPipe is arXiv 1811.06965.

  7. Read

    Ring Attention

    Blockwise attention across devices with overlapped KV passing.

  8. Read

    GShard and Switch Transformer

    Expert parallelism and all-to-all; Switch is arXiv 2101.03961.

  9. Read

    vLLM / PagedAttention

    KV-cache paging and continuous batching for serving.

  10. Read

    NCCL source and docs

    Ring vs. tree all-reduce algorithms, channels, protocols (LL, LL128, Simple).

  11. Implement

    Mini-parallelism library

    From scratch on torch.distributed: ZeRO-3-style sharding, 1F1B pipeline, tensor-parallel MLP; test on 2-8 GPUs.

Build

A from-scratch distributed library (FSDP-style sharding, TP, 1F1B pipeline) training a GPT-2-size model on multiple GPUs, with communication profiled.

Portfolio project: Scale a model and publish an MFU report

Train a 1B-class model on 8 GPUs using your library combined in 2D/3D parallelism, then optimize to the best MFU you can, with ablations of each choice. Optionally add ring attention for long context or expert parallelism for an MoE variant.

Deliverables

  • repo with the library, configs and launch scripts
  • README with MFU, tokens/s and memory tables across parallelism configs plus profiler traces
  • a 600–1200 word write-up on what limited scaling and how you fixed it

Rubric

Solid
>=35% MFU on 8 GPUs with correct convergence and an ablation table
Exceptional
>=45% MFU, or a working long-context/MoE extension, with a scaling analysis that predicts your measured numbers

References: How to Scale Your Model, The Ultra-Scale Playbook

If you get stuck

  • Hangs: mismatched collective order across ranks; log every collective with rank and shape
  • Losses diverge from single-GPU: check gradient scaling by world size and RNG seeding per rank
  • No multi-GPU box: use torch.distributed with gloo on CPU for correctness, rent 8 GPUs for an afternoon for perf
  • Pipeline bubbles worse than expected: count microbatches vs. stages (bubble ~ (p-1)/m)

Ready to move on when

  • Loss curves match single-GPU training to tolerance for each parallelism
  • Measured memory per GPU matches your ZeRO math within 10%
  • Profiler trace shows communication overlapped with compute
  • You can compute MFU and the pipeline bubble fraction for your runs
