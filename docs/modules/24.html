24CPU memory hierarchy, threads

Correct code is now slow code; this module makes generated C competitive by tiling, reordering, unrolling, vectorizing and threading. These are the same schedule knobs you later reuse on GPU.

about 30–45 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Apply tiling, loop reordering and UPCAST unrolling as rewrites that keep all earlier tests passing.
  • Emit C that the compiler vectorizes, confirmed by reading the assembly or -Rpass=loop-vectorize output.
  • Split GLOBAL axes across pthreads and measure the speedup per core count.
  • Report 1024^3 matmul GFLOPS as a fraction of your machine's computed peak.

Steps

Work through these in order. Each step points at one specific unit.

  1. Measure

    Find your machine's peak

    Compute single-socket peak FLOPS (cores x freq x SIMD width x 2 FMA units x 2) and measure NumPy 1024^3 GFLOPS as a reference.

  2. Read

    siboehm, Fast Multidimensional Matrix Multiplication on CPU from Scratch

    Naive, cache-aware (loop reorder), tiling, tiling on multiple dimensions, multithreaded. Note each step's speedup and the reason the post gives.

  3. Implement

    axis=GLOBAL|LOOP|UPCAST and kernel calls

    Parse the new axis attribute and calls that launch kernels. Pass tests/week07/kernel_fill.uir.

  4. Implement

    Loop reorder + tiling as rewrites

    Split a range into outer/inner (r → r_o*T + r_i) and permute; verify correctness with all earlier tests.

  5. Read

    how-to-optimize-gemm: Optimization_1x4_3 through Optimization_4x4_15

    Follow the register-blocking progression and record GFLOPS at each step on your machine.

  6. Implement

    UPCAST: unroll + register accumulators

    UPCAST axes become unrolled scalars; add a 4x8-ish micro-kernel of accumulators.

  7. Read

    salykova, Advanced Matrix Multiplication Optimization: sections 5, 7 and 8

    Section 5 (Kernel), 7 (Cache Blocking, with packing) and 8 (Kernel Micro-Optimizations).

  8. Implement

    SIMD and pthreads

    Emit vector types (__attribute__((vector_size))) or vectorize pragmas; split GLOBAL axes across pthreads.

  9. Read

    tinygrad hand_coded_optimizations

    hand_coded_optimizations (line 8): which axes it upcasts, makes local or unrolls. Compare with your choices.

  10. Measure

    1024^3 matmul GFLOPS, conv and reduce vs NumPy

    Target >= 50% peak for matmul; conv and reduce within 3x of NumPy. Log each optimization's effect.

  11. Test

    10 own tests

    Non-divisible tile sizes, tiling a range used in an index bound proof, threaded reduce correctness.

Portfolio project: kiln v1.6: Autotuner for your CPU backend

kiln, the main project · v1.6 adds an autotuner for the CPU backend · builds on v1.5 · next: v1.7

Build a search-based autotuner over your schedule space (tile sizes, loop order, unroll, threads) with a measurement cache. Compare random search and beam search on three kernels: 2048^3 fp32 GEMM, a 3x3 conv with 64 in/out channels on 56x56 (a ResNet-18 layer), and row softmax on 4096x4096. Report GFLOPS vs OpenBLAS and trials needed per method.

Deliverables

  • repo with a tuner, a persistent tuning database and a replay command
  • README with best-found GFLOPS vs trials curves per method and kernel
  • perf stat tables (cache misses, IPC) for the best vs default schedule
  • a 600-1200 word write-up on schedules the tuner found that your heuristic did not pick

Rubric

Solid
GEMM reaches 50% of OpenBLAS single-thread and scales with cores; tuner beats your hand heuristic on all three kernels.
Exceptional
GEMM reaches 80% of OpenBLAS; a learned cost model (e.g. gradient-boosted trees on schedule features) reaches the random-search best in 3x fewer trials.

References: Ansor: Generating High-Performance Tensor Programs for Deep Learning, Simon Boehm, Fast Multidimensional Matrix Multiplication on CPU from Scratch

Help

If you get stuck

  • Compiler did not vectorize: check with -Rpass=loop-vectorize or read the asm; aliasing (add restrict) and non-unit strides are the usual causes.
  • Threads slower than one core: work per thread too small, or threads write to adjacent cache lines (false sharing). Pad or block outputs.
  • Tiling helped at one size and hurt at another: tile sizes must fit L1/L2; measure, do not guess.
  • Benchmarks vary 20%: CPU frequency scaling and turbo. Fix the governor or report medians of many runs.

Ready to move on when

  • kernel_fill and all earlier tests pass
  • 1024^3 f32 matmul >= 50% of single-socket peak, GFLOPS reported
  • Conv and reduce within 3x of NumPy
  • 10+ new tests
Reference implementations (5)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • flame/how-to-optimize-gemm source (UPCAST: unroll + register accumulators)
    The C code for each Optimization_* step of the wiki, so you can diff your generated micro-kernel against the matching step.
  • salykova/matmul.c (SIMD and pthreads; Autotuner project baseline)
    The author's code for the matmul-cpu post: packing, cache blocking, an AVX2/FMA micro-kernel and OpenMP threading that matches OpenBLAS.
  • tinygrad search.py (BEAM) (Autotuner project)
    tinygrad's beam search over kernel opts with a timing cache, a working reference for the project's search and tuning database.
  • tinygrad postrange.py (Loop reorder + tiling as rewrites)
    Where tinygrad applies opts (UPCAST, UNROLL, LOCAL) by splitting ranges, the same split-and-permute rewrite you implement.
  • BLIS (UPCAST micro-kernel)
    Production BLAS whose kernels/ directory holds per-architecture micro-kernels in the Goto layout.

Talks, papers, code and writing (15)

Courses

  • Performance-Aware Programming · Casey Muratori
    A course on reasoning from hardware up; the SIMD and cache bandwidth parts map directly onto this module.
  • MIT 6.172 Performance Engineering of Software Systems · Charles Leiserson, Julian Shun
    Lecture 1 walks matmul from Python to 50000x faster; later lectures cover caches, vectorization and multicore.

Talks

  • Cpu Caches and Why You Care · Scott Meyers
    An hour on cache lines, false sharing and prefetching; watch the false sharing part before threading your GLOBAL axes.
  • Data-Oriented Design and C++ · Mike Acton
    Argues layout dictates performance with real cache-miss counts; focus on the worked examples in the second half.
  • Efficiency with Algorithms, Performance with Data Structures · Chandler Carruth
    Explains why contiguous memory wins on modern CPUs; watch the latency numbers section.

Papers

  • Anatomy of High-Performance Matrix Multiplication · Kazushige Goto, Robert van de Geijn
    The source of the packing plus micro-kernel design used by every fast BLAS; focus on the layered cache-blocking argument.
  • Halide: A Language and Compiler for Optimizing Parallelism, Locality, and Recomputation · Jonathan Ragan-Kelley et al.
    The algorithm/schedule split that your axis knobs imitate; read the scheduling section and autotuning results.
  • TVM: An Automated End-to-End Optimizing Compiler for Deep Learning · Tianqi Chen et al.
    Schedule primitives plus a learned cost model for tuning; read the ML-based cost model section for your autotuner project.

Books

  • What Every Programmer Should Know About Memory · Ulrich Drepper
    Deep treatment of caches, TLBs and prefetching; read section 3 (CPU caches) and section 6.2 (cache access, with the matmul example).
  • Software optimization resources · Agner Fog
    Instruction tables and microarchitecture guides; use the instruction tables to compute FMA throughput for your peak estimate.

Blogs and articles

  • Performance Matters · Travis Downs
    Careful microbenchmark posts on store buffers, AVX frequency and memory; read the posts on AVX-512 frequency before choosing SIMD width.
  • Tutorial: Performance Engineering for Machine Learning and Scientific Computing · Davis Blalock
    A compact tour of memory hierarchy, vectorization and threading aimed at ML people; good for the mental model before tuning your CPU backend.

Problem sets

  • uops.info · Andreas Abel, Jan Reineke
    Measured latency, throughput and ports for every x86 instruction; look up your vfmadd variant to size the accumulator count.

More reading

  • Algorithmica: matrix multiplication — Concise kernel-level walkthrough.
  • BLISlab — Packing + micro-kernel homework.
