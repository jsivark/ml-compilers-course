Part III · The Course · 10-411 week 6

24Autodiff, real models

Reverse-mode gradients are just another graph rewrite, one rule per op. With file-backed weights and transcendentals you can train MNIST and run real LLMs and CNNs: your compiler starts doing actual ML.

about 40–60 h · difficulty ●●●●●

StepsBuildProjectHelpGo deeper

After this module you can

  • Implement reverse-mode autodiff as a graph rewrite with one gradient rule per op, verified by finite differences.
  • Implement exp2, log2 and sin with range reduction and a polynomial, and report max ULP error against NumPy.
  • Train an MNIST MLP and run stories15M and ResNet-18 inference with outputs matching the references.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Autodidax (JAX from scratch): Part 1, then Part 4 on gradients

    Part 1 (interpreters, jvp) and Part 4 (linearize, vjp and grad, which build reverse mode from linearize plus transpose). Skip Part 3 (jit) for now.

  2. Read

    Baydin et al., automatic differentiation survey, section 3: forward and reverse mode

    Only §3.1 (Forward Mode) and §3.2 (Reverse Mode); work the paper's reverse-mode example by hand.

  3. Implement

    Parse scopes, external weights and the gradient op

    Value of a scope is its last binding; load .bin weights. Use tests/week06/data/x.bin.

  4. Read

    How tinygrad computes gradients (compute_gradient)

    One rule per op (lines 68-108), then compute_gradient (line 121) for the reverse toposort accumulation.

  5. Implement

    gradient as a rewrite

    Rule per op including reduce/expand/movement (gradient of expand is reduce, of permute is inverse permute). Pass gradient_square; test vs finite differences on 20 random graphs.

  6. Read

    How tinygrad computes exp, log and sin from basic ops

    Read xexp2 (193), xlog2 (219) and xsin (170) with cody_waite_reduction (115).

  7. Implement

    Write exp2, log2, sqrt and sin yourself

    Range reduction plus polynomial; test against NumPy over a wide grid within a few ULP.

  8. Implement

    MNIST MLP training

    Write a 784-128-10 MLP, softmax cross-entropy and SGD in UIR; reach 97% test accuracy in under 5 min on CPU.

  9. Read

    llama2.c: the forward pass and the sampler

    Read forward() (rmsnorm, RoPE, attention, SwiGLU FFN) and sample_argmax(); this is your reference.

  10. Implement

    Run the stories15M model and match llama2.c token for token

    Load stories15M.bin weights, run greedy decoding, compare token ids to run.c for the same prompt.

  11. Read

    ResNet paper, section 3.3 and Table 1 (the architectures)

    Read §3.3 Network Architectures and Table 1 for the 18-layer column. Batchnorm folding for inference is not in the paper; derive it yourself.

  12. Implement

    ResNet-18 on one image

    Export torchvision resnet18 weights outside your compiler, run one 224x224 image, top-1 class matches PyTorch.

  13. Test

    Write 10 tests of your own

    Gradient of max ties, of where, of division, through pad and shrink; compare each to finite differences.

Build

gradient as a rewrite, own transcendentals, and three real models: MNIST training, stories15M, ResNet-18.

Portfolio project: kiln v1.5: MNIST, stories15M and ResNet-18 through kiln vs PyTorch

kiln, the main project · v1.5 adds real models lowered from the kiln front end and run end to end · builds on v1.4 · next: v1.6

Connect the two halves: the kiln front end lowers its graph to UIR and the backend compiles it. On one machine, measure your compiler against PyTorch eager and torch.compile on three workloads: training the 784-128-10 MNIST MLP to 97% test accuracy, greedy decoding 256 tokens with stories15M, and ResNet-18 inference at batch 1 on 224x224 images. Add a ULP-error report for your transcendentals and a finite-difference gradient check for every op.

Deliverables

  • repo with scripts that reproduce every number from a clean checkout
  • README table: MNIST time-to-97%, stories15M tokens/s, ResNet-18 images/s and peak memory, for your compiler, PyTorch eager and torch.compile
  • a max-ULP-error plot for exp2/log2/sin across their input ranges
  • a 600-1200 word write-up on the hardest numerical bug and how you found the first diverging tensor

Rubric

Solid
MNIST reaches 97%; stories15M greedy tokens identical to run.c; ResNet-18 top-1 matches PyTorch on 100 ImageNet validation images; every op passes gradient check.
Exceptional
Within 2x of torch.compile on at least one workload, with a profile explaining the gap; transcendentals within 2 ULP; a GPT-2 124M forward pass matching Hugging Face logits to 1e-4.

References: karpathy/llm.c, Karpathy, A Recipe for Training Neural Networks

Help

If you get stuck

  • Gradient check fails: use float64 finite differences with eps around 1e-6 and relative error, and check one op at a time.
  • Gradients of broadcast/expand must sum over the expanded axes; forgetting this is the most common bug.
  • Loss is NaN: log of 0 or exp overflow in softmax. Use log-sum-exp with max subtraction.
  • Transcendentals inaccurate at large inputs: range reduction is missing or done in float32. Measure max ULP error over a full input sweep.
  • Model output differs from reference: compare layer by layer with the PyTorch weights and find the first diverging tensor.

Ready to move on when

  • Gradients match finite differences on 20 random graphs; gradient_square passes
  • MNIST MLP >= 97% test accuracy in < 5 min on CPU
  • stories15M tokens identical to run.c
  • ResNet-18 top-1 matches PyTorch
Reference implementations (5)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • micrograd's autodiff engine (engine.py) (gradient as a rewrite)
    Scalar reverse-mode autodiff in about 100 lines: per-op _backward closures plus a reverse topological sort, the same shape as your gradient rewrite.
  • tinygrad's MNIST training example (MNIST MLP training)
    A complete MNIST training script on tinygrad's lazy graph and autograd, useful to compare your UIR training loop and accuracy target.
  • teenygrad (gradient as a rewrite)
    A sub-1000-line tinygrad with the same Function-per-op backward rules, easier to read end to end than full tinygrad.
  • GPT-2 training in plain C (llm.c train_gpt2.c) (stories15M / real models build)
    Hand-written forward and backward for every GPT-2 layer in plain C; check your generated backward kernels for layernorm, softmax and matmul against it.
  • SLEEF (Write exp2, log2, sqrt and sin yourself)
    Production vectorized libm with documented ULP bounds; compare its range reduction and polynomial choices with your exp2/log2/sin.

Talks, papers, code and writing (17)

Lectures

  • CS231n: Backpropagation, Intuitions · Stanford CS231n
    Gradient patterns for add, mul, max and matmul with dimension analysis; focus on the vectorized operations section.
  • Lecture 21: on-device training and compile-time backward graphs (PockEngine) · MIT EfficientML, Fall 2024 (Song Han)
    PockEngine derives and prunes the backward graph as a compiler pass, the same idea you build here. Also explains why activations dominate training memory.

Videos

  • The spelled-out intro to neural networks and backpropagation: building micrograd · Andrej Karpathy
    Builds reverse-mode autodiff live; watch the backward-pass and topological-sort sections.
  • Building makemore Part 4: Becoming a Backprop Ninja · Andrej Karpathy
    Derives every gradient of an MLP with batchnorm and cross-entropy by hand, which is exactly the per-op rule table you write.
  • Let's reproduce GPT-2 (124M) · Andrej Karpathy
    Full training of a real model with performance work along the way; watch the speedup section for which optimizations matter when you move past MNIST.

Papers

  • You Only Linearize Once: Tangents Transpose to Gradients · Radul, Paszke, Frostig, Johnson, Maclaurin
    The formal version of JAX's linearize-plus-transpose design; read sections 2-4 to see why reverse mode needs only forward rules plus transposition.
  • SLEEF: A Portable Vectorized Library of C Standard Mathematical Functions · Naoki Shibata, Francesco Petrogalli
    How a real libm does Payne-Hanek and Cody-Waite reduction with error bounds; read the sections on trig reduction and accuracy testing.

Books

  • The Elements of Differentiable Programming (book site and code) · Mathieu Blondel, Vincent Roulet
    Free book from Google DeepMind with accompanying Python code; read the automatic differentiation chapters on JVPs, VJPs and checkpointing.

Blogs and articles

  • Calculus on Computational Graphs: Backpropagation · Christopher Olah
    Short visual argument for why reverse mode costs one backward sweep; read the forward vs reverse factoring section.
  • Evaluating the gradient is as fast as evaluating the function · Tim Vieira
    Explains the cheap gradient principle with code; use it to bound the cost of your generated backward graph.
  • Autodidax2, part 1: JAX from scratch, again · JAX team
    A shorter rewrite of Autodidax that frames JAX as primitives plus interpreters; build its JVP and linearize interpreters and compare with your own tape-based autograd.

Code to read

  • HIPS/autograd · Maclaurin, Duvenaud, Johnson
    The predecessor of JAX autodiff; autograd/numpy/numpy_vjps.py is a complete table of NumPy VJP rules to cross-check yours.
  • diff-zoo: Differentiation for Hackers · Mike Innes
    Notebooks that derive symbolic, forward and reverse differentiation from one tiny expression language; the reverse-mode and Wengert-list notebooks map directly onto this module.

Problem sets

  • CMU Deep Learning Systems assignments (build the Needle library) · Tianqi Chen, Zico Kolter
    Homework 1 has you implement reverse-mode autodiff over tensor ops in the Needle library with local tests; do it after the micrograd step.
  • How much loss varies between identical training runs (CS312 assignment 1, problems 3-4) · Stanford CS312 Deep Learning Alchemy
    Read pages 12-14 (the Stochasticity section); no runs needed. Same handout as the CS312 assignment 1 item in Module 9. Your compiler's loss will not match PyTorch bit for bit, and this shows how big normal run-to-run noise is, so you can tell a real gradient bug from floating-point reordering.

More reading

  • Karpathy, micrograd — Smallest scalar reverse-mode reference.
  • tinygrad's gradient tests — Gradient test cases to port.
