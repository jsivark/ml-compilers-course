34Industrial ML compilers: MLIR, XLA/StableHLO, TorchInductor, TVM

XLA, TorchInductor, TVM and MLIR-based stacks are what production ML compilers look like. You built a toy compiler; here you read how these systems split IR levels, fusion and codegen, and you build a small dialect in MLIR.

about 50–75 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Define an MLIR dialect in TableGen, write canonicalization and conversion passes, and lower it to LLVM
  • Read XLA HLO dumps and Inductor output and say which ops were fused into which kernel
  • Name, for XLA, Inductor and TVM, where fusion and scheduling decisions are made

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    MLIR: A Compiler Infrastructure for the End of Moore's Law (Lattner et al.)

    Sections 2-4: design principles, IR design (ops, regions, dialects), and the pass/rewrite infrastructure.

  2. Implement

    j2kun mlir-tutorial: Getting started

    Build mlir-opt from the tutorial repo with Bazel (CMake also described). The first LLVM build takes hours; start it early.

  3. Implement

    j2kun: Running and testing a lowering

    Write lit tests with FileCheck; every later step in this module is tested this way.

  4. Implement

    j2kun: Writing our first pass

    An affine loop-unroll pass, then the same transform as a rewrite pattern.

  5. Implement

    j2kun: Defining a new dialect

    Define the tutorial's poly (polynomial) dialect with TableGen ops and types.

  6. Implement

    j2kun: Canonicalizers and declarative rewrite patterns

    Canonicalization patterns in C++ and in DRR (TableGen) for the poly dialect.

  7. Implement

    j2kun: Dialect conversion

    TypeConverter and ConversionTarget: lower the poly dialect to standard upstream dialects.

  8. Implement

    j2kun: Lowering through LLVM

    Lower to the LLVM dialect, translate with mlir-translate, and link the result into an executable.

  9. Read

    OpenXLA: XLA architecture

    How XLA takes StableHLO, runs target-independent passes (CSE, fusion, buffer analysis), converts to HLO and hands off to a backend for target-specific fusion and codegen.

  10. Read

    TorchInductor: a PyTorch-native Compiler with Define-by-Run IR and Symbolic Shapes (Jason Ansel, 2022)

    Define-by-run loop IR, scheduling and fusion, Triton codegen for GPUs.

  11. Read

    PyTorch 2: Faster Machine Learning Through Dynamic Python Bytecode Transformation and Graph Compilation (ASPLOS 2024)

    Section 3 TorchDynamo (bytecode capture, guards, graph breaks), Section 4 TorchInductor, Section 5 dynamic shapes.

  12. Read

    TVM: An Automated End-to-End Optimizing Compiler for Deep Learning (OSDI 2018)

    Section 3 graph-level fusion, Section 4 tensor expressions and schedules, Section 5 the ML-based cost model.

Deliverables

  • repo with the dialect, passes, FileCheck tests and an end-to-end example
  • README with performance comparison vs. your original backend and vs. torch.compile

Rubric

Solid
The MLP runs end to end through MLIR and matches PyTorch outputs to 1e-5; 20+ lit tests
Exceptional
The MLP or a single transformer block runs on GPU via the MLIR GPU dialect within 2x of torch.compile, or the Inductor patch is opened upstream with benchmarks

References: j2kun mlir-tutorial, MLIR Toy tutorial

Help

If you get stuck

  • Build too slow: build LLVM once in release mode with ccache, at the commit the tutorial pins
  • TableGen errors: start from the tutorial's poly dialect and change one thing at a time
  • 'failed to legalize operation': check which ops the ConversionTarget marks legal and that the TypeConverter handles block arguments
  • Inductor output too long: start with a two-op function and TORCH_LOGS=output_code,schedule

Ready to move on when

  • The lowered tg matmul, compiled to a binary, matches a numpy matmul on random 64x64 inputs
  • At least 10 FileCheck tests cover canonicalization and each lowering stage
  • A one-page table comparing your compiler, XLA, Inductor and TVM on IR levels, fusion, scheduling and autotuning, with a source citation per cell
  • You can dump Inductor's generated Triton for a two-layer MLP (TORCH_LOGS=output_code) and point to each fused kernel

  • MLIR Toy tutorial code (llvm-project) (Project: emitting a custom tg dialect and lowering to LLVM)
    Complete code for every Toy chapter, from AST to a custom dialect, shape inference, affine lowering and LLVM JIT.
  • torch-mlir (Project: course IR to linalg tiling and fusion)
    A real frontend that imports PyTorch graphs into MLIR and lowers to linalg; shows how to wire a framework IR into upstream dialects.
  • TorchInductor source (Project alternative: TorchInductor fusion study)
    scheduler.py holds the fusion decisions and codegen/triton.py the kernel emitter; read them next to your fusion measurements.

Talks

  • 2019 EuroLLVM Developers' Meeting: T. Shpeisman & C. Lattner "MLIR: Multi-Level Intermediate Repr.." · LLVM (Tatiana Shpeisman, Chris Lattner)
    The designers explain why ops, regions and dialects look the way they do; watch the motivation and dialect sections before writing TableGen.
  • EuroLLVM 2025 program (MLIR to LLVM IR translation deep dive) · LLVM
    Find the talk on MLIR's translation to LLVM IR and the model import tutorial (TOSA, Torch-MLIR, ONNX).

Papers

  • The Deep Learning Compiler: A Comprehensive Survey · Li et al.
    Side-by-side comparison of TVM, XLA, Glow, nGraph and TC frontends, IRs and optimizations; use Sections 3-4 as a map.
  • Composable and Modular Code Generation in MLIR · Vasilache et al.
    Describes structured codegen with linalg, vector and tiling-by-interfaces; the design behind the project's linalg reuse.

Blogs and articles

  • MLIR talks index · MLIR project
    Curated list of open meeting recordings and slides; pick the linalg, transform dialect and bufferization talks.
  • TorchInductor: Deep Dive · Calvin Woo
    Notes that walk through Inductor's lowering, scheduling and codegen stages; read the scheduler and fusion sections next to the source.
  • Introduction to torch.compile and How It Works with vLLM · vLLM team
    A 2025 case study of Dynamo plus Inductor inside a production inference engine; focus on graph splitting, caching and custom fusion passes.
  • BrilIR: an MLIR dialect for Bril · CS 6120 course blog (2025)
    A student project that lowers Bril through MLIR dialects to LLVM; a direct bridge from Module 12 to MLIR.
  • XLA:GPU Architecture Overview · OpenXLA
    How XLA decides between library calls and generated code per HLO op, and how fusion works on GPU; read the fusion section.
  • Democratizing AI Compute, Part 6: What about AI compilers? · Chris Lattner (Modular)
    The creator of LLVM and MLIR on why TVM, XLA and others struggled; read it for the design lessons, then the rest of the series.

Code to read
