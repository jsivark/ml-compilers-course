Part III · The Course · 10-411 week 5

23Movement ops

reshape, permute, pad, shrink and expand never copy: each becomes index arithmetic, plus a validity mask for pad. Simplifying the resulting div/mod with bounds decides whether the generated loops are clean.

about 25-35 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Lower reshape, permute, expand, pad and shrink to index expressions with no copies.
  • Simplify div/mod index expressions using interval bounds until contiguous cases have none.
  • Build matmul and conv2d from movement ops plus mul and reduce.

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    ezyang, PyTorch internals: the strides and views part

    The strides, views and storage part near the start of the essay (before the section on autograd and the codebase tour). Work its slicing example by hand.

  2. Do

    Tensor Puzzles: all 21

    Each puzzle reimplements one NumPy function in one line using only broadcasting, arithmetic, comparison and indexing (no view or sum). This trains the index thinking movement ops need.

  3. Read

    How tinygrad tracks shapes and strides (ShapeTracker notes)

    Shape, strides and mask per view, and the transpose-then-reshape example whose index needs %3 and //3. ShapeTracker has since been removed from tinygrad; the index ideas still apply.

  4. Implement

    Shapes of any rank + shape rules for 5 movement ops

    Validate each op's argument: reshape keeps the element count, permute is a permutation, pad/shrink pairs fit the axis. REJECT rejected_reshape_size.

  5. Implement

    Movement ops as index rewrites

    During rangeify, map output ranges to input indices: permute reorders them, shrink adds the start offset, expand drops the broadcast axis, reshape flattens and splits with div/mod, pad subtracts 'before' and adds a where on validity. Pass transpose_index, pad_zeros.

  6. Read

    How tinygrad applies reshape and other movement ops

    Compare with your version; _apply_reshape is at line 147.

  7. Read

    How tinygrad simplifies division and modulo in indexes

    Rules that use bounds: mod folds when x//y is constant; (x%(k*c))//c becomes (x//c)%k; exact division (q*c+k)//c becomes q+k//c.

  8. Implement

    Bounds-driven div/mod simplification

    Add div/mod rules that use your Week 1 bounds so reshape followed by the inverse reshape gives plain range indices. Check that the generated C for a contiguous reshape has no / or %.

  9. Read

    How tinygrad builds matmul from views (tinygrad notes)

    Matmul as add an axis, permute, expand, multiply, sum over the shared axis.

  10. Implement

    Matmul and conv from movement ops

    Pass matmul_2x2. Then write conv2d (1 channel, 8x8 input, 3x3 kernel, pad 1) using only pad, shrink, reshape, expand, permute, mul and reduce, and match NumPy.

  11. Test

    Write 10 tests of your own

    E.g. permute then reshape (needs div/mod), pad then shrink back to the original, expand after permute, shrink to a single element.

Build

Rank-N shapes and the five movement ops lowered to masked index arithmetic, with bounds-driven div/mod simplification.

Portfolio project: kiln v1.4: Property-tested view algebra with a z3-checked index simplifier

kiln, the main project · v1.4 adds proved index simplification, upgrading the v0.3 views · builds on v1.3 · next: v1.5

Use Hypothesis to generate random chains of movement ops on random shapes, check your lowered index arithmetic against the same chain in NumPy, and prove each div/mod rule with z3 under the bounds you computed. Measure how much the simplifier shrinks index expressions on conv2d and matmul. This upgrades the v0.3 view system.

Deliverables

  • repo with a Hypothesis suite (random chains up to depth 8, shapes up to rank 4) and a z3 proof for each index rule
  • README with index-expression op counts and generated-C line counts before and after simplification for conv2d (3x3, 32x32, pad 1), matmul 64x64 and 20 random chains
  • a diagram or notebook showing how a padded, permuted view maps to memory
  • a 600-1200 word write-up on when two consecutive reshapes can be merged, with a proof sketch

Rubric

Solid
10,000+ random chains pass; every simplification rule is z3-proven; measured reduction in index op count on conv2d and matmul.
Exceptional
Proves a general merge condition for reshape chains with z3, not just test cases; the simplification gives a measured speedup on conv2d in your Module 21 harness.

References: Hypothesis documentation (property-based testing), Z3 theorem prover (Python bindings via z3-solver)

Help

If you get stuck

  • permute then reshape gives wrong values: the reshape must split the flat index of the permuted shape, not the original one.
  • Pad then permute then shrink gives wrong edges: the validity mask is attached to the wrong axis. Test that exact chain.
  • Index expressions keep growing: add the rule (x//a)*a + x%a -> x and apply it with bounds.
  • rejected_reshape_size passes validation: compare the product of all dims, not the rank.

Ready to move on when

  • python3 run_tests.py 1 through 5 all pass
  • conv2d built only from movement ops plus mul/reduce matches NumPy
  • A contiguous reshape and its inverse produce no / or % in the generated C
  • All 21 Tensor Puzzles pass their notebook tests
Reference implementations (5)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • tinygrad's movement ops (MovementMixin) (Shapes of any rank + shape rules for 5 movement ops)
    The user-facing reshape/permute/pad/shrink/expand argument checks and shape rules.
  • tinygrad's movement-op cleanup rules (Movement ops as index rewrites)
    Rules that merge and cancel chains of movement ops before indexing.
  • tinygrad's older view code (v0.9.0 view.py) (Movement ops as index rewrites)
    The older View class with shape, strides, offset and mask, plus reshape merging; the stride-based version of the same problem.
  • tinygrad's indexing tests (Bounds-driven div/mod simplification)
    Indexing tests to port as checks for your index rewrites.
  • teenygrad's shape code (Movement ops as index rewrites)
    A minimal ShapeTracker implementation small enough to read in one sitting.

Go deeper (optional)

Talks, papers, code and writing (16)

Courses

  • Triton Gluon tutorial: tensor layouts · Triton
    Official tutorial where layouts are explicit in user code; shows blocked, sliced and linear layouts you will meet in GPU codegen.

Papers

  • Linear Layouts: Robust Code Generation of Efficient Tensor Computation Using F2 · Keren Zhou et al.
    Triton's layout system as linear maps over bits; read sections 2-3 to see index rewrites made algebraic.
  • A note on the algebra of CuTe Layouts · Jay Shah (Colfax Research)
    Precise definitions and proofs for coalesce, composition and complement; use it when the CUTLASS docs leave a step unexplained.
  • Modeling Layout Abstractions Using Integer Set Relations · arXiv 2511.10374
    Puts CuTe layouts and Triton linear layouts in one integer-set framework; read the section on composition to connect strides, views and layouts.
  • Einops: Clear and Reliable Tensor Manipulations with Einstein-like Notation · Alex Rogozhnikov (ICLR 2022)
    Design rationale for rearrange as a notation over reshape/permute; use its examples as test cases for your movement-op lowering.

Blogs and articles

  • CuTe Layouts · NVIDIA CUTLASS
    Shape:stride layouts with hierarchical modes; the coalesce and composition parts generalize your reshape div/mod.
  • CuTe Layout Algebra · Lei Mao
    Worked proofs of layout composition and complement; focus on when a reshape stays expressible as strides.
  • Stride Visualizer · Edward Z. Yang
    Interactive view of how sizes and strides map indices to storage; test your transpose_index by hand here.
  • NumPy as_strided: make views with custom strides · NumPy
    Build sliding windows (conv) from strides alone; the warnings section shows overlapping views.
  • Adventures with TinyGrad: ShapeTracker · xl0
    Worked examples of views, masks from padding, and when permute plus reshape cannot merge into one view; good drill for the movement-op exercises.
  • Linear Layout in Triton (1): Basic Idea · ita9naiwa
    Gentle 2025 explainer of layouts as maps from (register, lane, warp) bits to logical indices; read before the Linear Layouts paper.
  • Linear layouts, Triton, and linear algebra over F2 · Damek Davis
    A mathematician's walk through the F2 view of layouts; focus on how layout conversion becomes matrix inversion.

Code to read

  • Halide · Halide team
    Its bounds inference and BoundaryConditions show pad as a clamped or masked index, like your where on validity.

Problem sets

  • GPU Puzzles · Sasha Rush
    The follow-on to Tensor Puzzles; puzzles 1-10 practice the same index arithmetic on threads.

More reading

  • tinygrad's tests for division and modulo simplification — Use its div/mod cases as tests for your simplifier.
  • NumPy: Internal organization of NumPy arrays — Strides and views from NumPy's side.

Make 100 percent of reshape-then-inverse-reshape chains compile to div/mod-free code, and report the fraction for general chains.
