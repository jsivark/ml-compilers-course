Part I · Foundations

07Neural networks from scratch

Loss, gradient descent and backpropagation, ending in a tiny autograd engine you wrote yourself. This engine is the seed of the tinygrad-style framework you will compile.

about 20–28 h · difficulty ●●○○○

StepsBuildProjectHelpGo deeper

After this module you can

  • After this module you can implement scalar reverse-mode autodiff with a graph and topological sort from memory.
  • After this module you can train an MLP from scratch and find why its loss does not go down.
  • After this module you can write the four backpropagation equations and point to the code that implements each.
  • After this module you can test your engine against PyTorch gradients.

Steps

Work through these in order. Each step points at one specific unit.

  1. Watch

    3Blue1Brown, Neural Networks ch. 1: But what is a neural network?

    Neurons as numbers, layers as matrix-vector products.

  2. Watch

    3Blue1Brown, ch. 2: Gradient descent, how neural networks learn

    Cost as a function of all weights; the gradient as the direction to step.

  3. Watch

    3Blue1Brown, ch. 3-4: What is backpropagation really doing?; Backpropagation calculus

    Chapter 4 is /lessons/backpropagation-calculus.

  4. Watch

    Karpathy, The spelled-out intro to neural networks and backpropagation: building micrograd (0:00-1:09:02)

    Derivatives, the Value object, and manual backprop through an expression and a neuron. Type the code yourself.

  5. Watch

    Karpathy micrograd video, 1:09:02-end

    Per-op backward, topological sort, the bug when a node is used twice (1:22:28), PyTorch comparison, MLP and training loop. Note where gradients must be zeroed before each step.

  6. Read

    CS231n notes: Backpropagation, Intuitions

    Read "Patterns in backward flow" (add distributes, max routes, multiply swaps) and the vectorized gradients section.

  7. Read

    Michael Nielsen, NNDL ch. 2: How the backpropagation algorithm works

    The four fundamental equations in matrix form. Map each one to a line of your engine.

  8. Do

    Rebuild micrograd from memory

    Close the video. Write engine.py and nn.py from scratch, then diff against the repo.

  9. Build

    Train on moons (micrograd demo.ipynb)

    The demo uses an SVM max-margin loss and reaches 100% training accuracy. Reproduce its decision boundary with your engine.

Build

Your own micrograd written without looking: Value with +, *, **, relu, tanh, exp and topological backward; Neuron, Layer, MLP; SVM or BCE loss; trained to above 95% accuracy on sklearn make_moons with a decision-boundary plot. Add a test that compares every gradient to PyTorch.

Portfolio project: kiln v0.4: a graph IR with your first compiler passes

kiln, the main project · v0.4 adds a recorded graph IR with your first compiler passes · builds on v0.3 · next: v0.5

Make kiln record an explicit graph IR of the ops it runs, then write three passes over it: dead-code elimination, common-subexpression elimination, and a codegen pass that emits a straight-line Python (or C) function computing the forward and backward pass with no Tensor objects. Benchmark the generated code against the interpreted engine on an MLP. This is your first compiler.

Deliverables

  • repo with the IR, the three passes, and tests that the generated code matches the interpreted gradients exactly
  • README with Graphviz renders before and after optimization and a speedup table vs the interpreted engine
  • a 600–1200 word write-up explaining tracing vs interpretation and what each pass removed, with node counts

Rubric

Solid
Generated code matches interpreted gradients bit-for-bit on random MLPs; reports node counts before/after each pass and a measured speedup.
Exceptional
Generated C version gives a speedup of 100x or more over the interpreter, adds constant folding, and the write-up connects the design to torch.fx or jax.make_jaxpr.

References: karpathy/micrograd

Help

If you get stuck

  • Wrong gradient when a node is used twice: you used = instead of +=. Karpathy hits this bug at 1:22:28 in the video.
  • Training diverges or oscillates: gradients were not zeroed before backward.
  • Loss not decreasing: sweep the learning rate over 3 orders of magnitude and plot loss per step.
  • Recursion limit on deep graphs: make the topological sort iterative.

Ready to move on when

  • Explain why backward must visit nodes in reverse topological order.
  • Explain why gradients accumulate with += and what goes wrong with = when a node is used twice.
  • Backprop by hand through f = tanh(a*b + c) and match your engine.
  • Your engine's gradients match PyTorch to 1e-6 on a random expression.
  • make_moons accuracy above 95%.
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • micrograd engine.py and nn.py (Rebuild micrograd from memory)
    Karpathy's reference Neuron, Layer, MLP; diff against your rebuild after closing the video.
  • teenygrad mlops.py (Project: graph IR and per-op backward)
    Each op as a Function with forward and backward, the tensor-level successor to micrograd's closures.
  • JAX Autodidax (Project: graph IR, passes and codegen)
    Part 3 (jaxprs) shows tracing a Python function into a typed graph IR, the same move your project makes before DCE, CSE and codegen.
  • nn-zero-to-hero notebooks (Karpathy micrograd video)
    Karpathy's own notebooks for the micrograd lecture, with the exact code at each point of the video.
