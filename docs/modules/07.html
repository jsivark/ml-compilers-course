07Neural networks from scratch

Loss, gradient descent and backpropagation, ending in a tiny autograd engine you wrote yourself. This engine is the seed of the tinygrad-style framework you will compile.

about 20–30 h · difficulty ●●○○○

After this module you can

  • After this module you can implement scalar reverse-mode autodiff with a computation graph and topological sort from memory.
  • After this module you can build and train an MLP from scratch and debug it when the loss does not decrease.
  • After this module you can derive the four backpropagation equations and connect them to the code.
  • After this module you can verify gradients of your engine against PyTorch.

Build

Your own micrograd written without looking: Value with +,*,**,relu,tanh,exp, topological backward; Neuron/Layer/MLP; SVM or BCE loss; trained to >95% accuracy on sklearn make_moons with a decision-boundary plot. Add a test that compares every gradient to PyTorch.

Portfolio project: A tiny graph IR for your autograd: visualize, optimize, codegen

Make your micrograd record an explicit graph IR, then write three passes over it: dead-code elimination, common-subexpression elimination, and a codegen pass that emits a straight-line Python (or C) function computing the forward and backward pass with no Value objects. Benchmark the generated code against the interpreted engine on an MLP. This is your first compiler.

Deliverables

  • repo with the IR, the three passes, and tests that the generated code matches the interpreted gradients exactly
  • README with Graphviz renders before and after optimization and a speedup table vs the interpreted engine
  • a 600–1200 word write-up explaining tracing vs interpretation and what each pass removed, with node counts

Rubric

Solid
Generated code matches interpreted gradients bit-for-bit on random MLPs; reports node counts before/after each pass and a measured speedup.
Exceptional
Generated C version gives a speedup of 100x or more over the interpreter, adds constant folding, and the write-up connects the design to torch.fx or jax.make_jaxpr.

References: karpathy/micrograd

If you get stuck

  • Gradients wrong when a node is used twice: you used = instead of +=; Karpathy shows this bug in the micrograd video.
  • Forgetting to zero gradients between steps makes training diverge.
  • Loss stuck: learning rate too high or too low; plot loss vs step and try a sweep over 3 orders of magnitude.
  • Recursion limit hit on big graphs: make the topological sort iterative.

Ready to move on when

  • Explain why backward must visit nodes in reverse topological order.
  • Explain why gradients use += and what breaks if a node is used twice with =.
  • Backprop by hand through f = (a*b + c).tanh() and match your engine.
  • Your engine's gradients match PyTorch to 1e-6 on a random expression.
  • Moons accuracy >95%.
