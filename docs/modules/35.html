Part IV · Frontier

35Scheduling theory: polyhedral model and auto-schedulers

Your BEAM search picked schedules by trial. Two other approaches exist: polyhedral compilers prove which transforms are legal from dependences, and learned auto-schedulers predict runtime with a cost model. This module covers both.

about 45–65 h · difficulty ●●●●●

StepsBuildProjectHelpGo deeper

After this module you can

  • Write loop nests as isl sets and maps and check transform legality from dependences
  • Train and evaluate a learned cost model for schedule search, split by program

Steps

Work through these in order. Each step points at one specific unit.

  1. Read

    Halide: A Language and Compiler for Optimizing Parallelism, Locality, and Recomputation (PLDI 2013)

    The algorithm/schedule split and the tradeoff between locality, parallelism and redundant recomputation.

  2. Read

    Learning to Optimize Halide with Tree Search and Random Programs (SIGGRAPH 2019)

    Beam search over a large schedule space with a cost model trained on random programs; compare with your BEAM.

  3. Read

    Ansor: Generating High-Performance Tensor Programs for Deep Learning (OSDI 2020)

    Section 4 program sampling (sketch generation, random annotation), Section 5 evolutionary fine-tuning with a learned cost model, Section 6 the task scheduler.

  4. Read

    Presburger Formulas and Polyhedral Compilation (Verdoolaege, isl tutorial)

    Chapters 2-3 (sets, relations), Chapter 5 (instance sets, access relations, dependences, schedules) and Chapter 6 (dependence analysis). Run the examples with isl's Python interface or islpy.

  5. Practice

    Pluto: polyhedral source-to-source

    Run Pluto on a 2D stencil and a matmul and read the tiling hyperplanes it reports.

  6. Read

    Tiramisu: A Polyhedral Compiler for Expressing Fast and Portable Code (CGO 2019)

    A Halide-like scheduling language built on a polyhedral representation.

  7. Implement

    Dependence analysis in your compiler

    Using islpy, compute dependences for your loop IR and reject tile or interchange transforms that violate them.

  8. Implement

    Learned cost model for your BEAM search

    Collect (schedule features, measured runtime) pairs, train a gradient-boosted tree, and use its ranking to prune BEAM candidates before measuring.

Build

islpy-based legality checks for your loop transforms, and a learned cost model that reduces how many schedules BEAM has to measure.

Portfolio project: Reproduce a cost-model result on your own compiler

Optional project

Reproduce the core claim of the Halide 2019 autoscheduler, Ansor or TenSet inside your compiler: a learned cost model makes search more sample-efficient. Use their feature ideas on your search space, measure on at least 10 matmul/conv/reduction shapes, and report sample-efficiency curves and transfer from one GPU to another or from one op type to another.

Deliverables

  • repo with the dataset of measured schedules (released), training code and integration
  • README with search-time vs. achieved-performance curves against random and plain BEAM
  • a 600–1200 word write-up on what transferred, what didn't and why

Rubric

Solid
Dataset of >=20k measured schedules, cost model with reported rank correlation, clear sample-efficiency plot
Exceptional
Shows cross-hardware transfer or a novel feature that measurably helps; written like a workshop paper

References: TenSet (NeurIPS 2021 Datasets and Benchmarks), code and dataset, Ansor

Help

If you get stuck

  • isl notation unfamiliar: write each tutorial example by hand first, then check it with isl
  • Cost model looks too good: split train/test by program, not by schedule, or schedules of the same program leak
  • Measurements noisy: lock GPU clocks, warm up, take the median of repeated runs
  • Pluto fails to build: use a container; the tiling hyperplanes are what you need from it

Ready to move on when

  • Your compiler rejects interchanging the loops of a[i][j] = a[i-1][j+1] and accepts interchange on a matmul
  • Cost-model-guided search reaches within 10% of plain BEAM's best runtime using at most 25% of its measurements, on 5 kernels
  • You can write the iteration domain and the tiled schedule of a matmul as isl sets and maps
  • A one-page comparison of the Halide 2019 autoscheduler, Ansor and Pluto: search space, cost model, legality handling
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • islpy (Dependence analysis in your compiler)
    Python bindings for isl with examples of sets, maps and dependence computation, the exact API the dependence lab uses.
  • Halide Adams2019 autoscheduler (Learned cost model for your BEAM search)
    The paper's actual code: featurization, the small neural cost model and the beam search with retraining.
  • Pluto source (Dependence analysis; Pluto practice step)
    Reference implementation of the Pluto tiling algorithm; compare its legality constraints with your islpy checks.
  • Tiramisu (Build: legal loop transforms)
    Polyhedral scheduling language with full implementation and benchmarks for comparison with your transforms.

Talks, papers, code and writing (17)

Lectures

  • Polyhedral Compilation Foundations (888.11) · Louis-Noel Pouchet
    Full lecture slides and notes on iteration domains, dependences and scheduling; work through the dependence and tiling hyperplane lectures.
  • Affine scheduling lecture slides (CSE 888) · Louis-Noël Pouchet
    The three stages of polyhedral optimization and affine schedule construction, from a leading researcher in the area.

Courses

  • CR10 Advanced Compilation · Christophe Alias (ENS Lyon)
    Graduate course page on polyhedral models and scheduling with slides; use it as a second explanation of affine scheduling.

Papers

  • Decoupling Algorithms from Schedules for Easy Optimization of Image Processing Pipelines (thesis) · Jonathan Ragan-Kelley
    The long-form Halide argument with the schedule space formalized; read the chapter on the scheduling model.
  • TVM: An Automated End-to-End Optimizing Compiler for Deep Learning · Tianqi Chen et al.
    Section 5 introduces the XGBoost cost model that Ansor and TenSet build on.
  • Learning to Optimize Tensor Programs (AutoTVM) · Tianqi Chen et al.
    The original learned-cost-model search paper; compare its features and transfer learning with your gradient-boosted model.
  • TenSet: A Large-scale Program Performance Dataset for Learned Tensor Compilers · Lianmin Zheng et al.
    Shows how much data a cost model needs and how it transfers across hardware; mirror the project's transfer experiment.
  • Tensor Comprehensions · Vasilache et al.
    Polyhedral compilation applied to ML ops with autotuning; read the polyhedral mapping section.
  • Tensor Program Optimization with Probabilistic Programs (MetaSchedule) · Shao et al.
    TVM's successor to Ansor, which makes the search space a program; compare with how you encode BEAM's space.
  • Value Function Based Performance Optimization of Deep Learning Workloads · Steiner et al.
    A Halide follow-up that learns a value function for scheduling; read for a reinforcement-style view of BEAM.

Blogs and articles

  • An Autoscheduler for Halide · Cornell CS 6120 students
    Student write-up summarizing the Halide autoscheduler design and its search and cost model; a short on-ramp before the Adams 2019 paper.
  • Polyhedral Compilation Basics: Hands-on with ISLPy · Kabilan Mahathevan
    Build iteration domains, schedules and generated code with islpy; pair it with the iscc post on the same blog.
  • Polyhedral compilation: part 1 · Emil Vatai
    A gentle written introduction to iteration domains and dependences.
  • Introducing TVM Auto-scheduler (a.k.a. Ansor) · Apache TVM
    How Ansor builds a search space without templates and uses a learned cost model; read before implementing your own search.

Problem sets

  • PolyBench/C · Louis-Noel Pouchet
    Standard kernels used by every polyhedral paper; run your legality checker and Pluto on several of them.
