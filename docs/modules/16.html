Part II · Bridge

16Deep learning systems

Before compiling tensor programs you need a tensor library: strides, broadcasting, autograd on tensors, and fast kernels. MiniTorch and CMU DLSys (10-414/714) build each piece with tests.

about 55–80 h · difficulty ●●●●○

StepsBuildProjectHelpGo deeper

After this module you can

  • Implement strided views (reshape, permute, expand) that share storage with the original tensor.
  • Implement tensor broadcasting and tensor-level autograd that pass the MiniTorch Module 2 tests.
  • Write a tiled CPU matmul and a CUDA matmul for an NDArray backend.
  • Train LeNet on MNIST with your own framework.

Steps

Work through these in order. Each step points at one specific unit.

  1. Do

    MiniTorch Module 0: Fundamentals, Tasks 0.1-0.5

    Operators, Testing and Debugging (hypothesis), Functional Python, Modules, Visualization. Set up the repo and get the test harness green.

  2. Do

    MiniTorch Module 1: Autodiff, Tasks 1.1-1.5

    Numerical derivatives, scalars, chain rule, backpropagation, training. Compare with your Module 15 code.

  3. Do

    MiniTorch Module 2: Tensors, Tasks 2.1-2.5

    2.1 Tensor Data - Indexing, 2.2 Tensor Broadcasting, 2.3 Tensor Operations, 2.4 Gradients and Autograd, 2.5 Training. Strides here are the same idea as tinygrad's views.

  4. Do

    MiniTorch Module 3: Efficiency, Tasks 3.1-3.5

    3.1 Parallelization (Numba), 3.2 Matrix Multiplication, 3.3 CUDA Operations, 3.4 CUDA Matrix Multiplication, 3.5 Training. Time the naive and parallel versions.

  5. Do

    MiniTorch Module 4: Networks, Tasks 4.1-4.5

    4.1 1D Convolution, 4.2 2D Convolution, 4.3 Pooling, 4.4 Softmax and Dropout, 4.5 Training an Image Classifier (LeNet on MNIST).

  6. Watch

    CMU DLSys Lectures 3-5: Manual Neural Networks / Backprop, Automatic Differentiation, Automatic Differentiation Implementation

    Compare needle's computational-graph design with MiniTorch's.

  7. Do

    DLSys Homework 1: needle autodiff

    Implement forward and backward for needle ops and reverse-mode AD with a topological sort (hw1.ipynb).

  8. Watch

    DLSys Lectures 10, 12, 13: Hardware Acceleration for Linear Algebra, Hardware Acceleration + GPUs, Hardware Acceleration Implementation

    Focus on the strided NDArray backend design and tiling.

  9. Do

    DLSys Homework 3: NDArray backend (CPU + CUDA)

    Implement compact/setitem, elementwise ops, reductions and tiled matmul in C++ and CUDA (hw3.ipynb). The C++ you need (classes, templates, RAII) is covered in Module 2.

Build

A tinygrad-like tensor library in Python: strided Tensor with views (reshape/permute/expand without copy), broadcasting, reverse-mode autograd, a CPU backend in C via ctypes with tiled matmul, and an MNIST MLP training to >97% accuracy.

Portfolio project: kiln v0.8: lazy evaluation, fusion, and a benchmark against PyTorch CPU

kiln, the main project · v0.8 adds lazy evaluation, elementwise fusion and generated C kernels · builds on v0.7 · next: v1.0

Make kiln lazy: build an op graph, fuse elementwise chains and their following reduction into single generated C kernels, and reuse buffers. Train a 2-layer, 128-dim character-level transformer on Tiny Shakespeare (about 1 MB of text) for 2000 steps and compare speed and memory against your eager mode and PyTorch CPU.

Deliverables

  • repo with lazy graph, fusion pass, codegen backend, memory planner, and a char-level transformer training script
  • README with kernel-count, peak-memory and tokens/sec comparisons (eager vs fused vs PyTorch CPU) and loss curves
  • a 600–1200 word write-up explaining the fusion rules, where fusion is illegal, and the memory planner design

Rubric

Solid
Fused mode launches at least 3x fewer kernels than eager, matches eager outputs to 1e-5, and validation loss falls below 2.0 nats/char.
Exceptional
Within 2x of PyTorch CPU tokens/sec, a liveness-based memory planner with measured savings, and a visualization of the scheduled graph.

References: CMU 10-414/714 Deep Learning Systems, tinygrad

Help

If you get stuck

  • Stride bugs: compare your view ops to NumPy on random shapes before building on them.
  • Non-contiguous tensors break naive kernels; decide where you call compact()/contiguous() and test both paths.
  • Softmax and log-softmax overflow unless you subtract the row max.
  • If training does not learn, overfit a single batch first; failure there means a gradient bug.

Ready to move on when

  • permute/expand/reshape produce views (no data copy) verified by shared storage
  • All MiniTorch Module 2 tests pass
  • Your tiled matmul is at least 5x faster than the naive triple loop at 1024x1024
  • MNIST trains to >97% test accuracy with your library
Reference implementations (4)

Make a real attempt first. When you are stuck, or after you finish, compare your work with these.

  • teenygrad (Build and the lazy mini-framework project)
    A roughly 1000-line lazy tensor framework from the tinygrad authors with views, a lazy graph and an autograd Function layer; the closest small reference for the lazy-fusion project.
  • MiniTorch official repo and tests (MiniTorch Modules 0-4)
    The official MiniTorch repo with the task tests and the reference operator signatures each Module must satisfy.
  • tinygrad codegen/memory.py at the pinned commit (Project memory planner)
    tinygrad's buffer-reuse planner, a compact reference for the liveness-based memory planner in the project rubric.
  • nanoGPT (Project char-level transformer training)
    A reference char-level Shakespeare transformer config and training loop whose loss curve you can match with your framework.

Courses

  • TinyTorch · Vijay Janapa Reddi et al. (Harvard)
    A free 20-module curriculum building a PyTorch-style framework from tensors to transformers in pure Python with memory and performance profiling built in; a good alternative track to minitorch/needle.
  • CMU 15-779: Advanced Topics in Machine Learning Systems (LLM Edition) · Zhihao Jia (CMU)
    Fall 2025 slides on how models are lowered to kernels, ML compilers, parallelization and serving; use it as the step after dlsys.

Videos

  • Let's build GPT: from scratch, in code, spelled out. · Andrej Karpathy
    Builds the exact char-level Shakespeare transformer the project trains; watch for the op list your framework must support.

Papers

  • PyTorch: An Imperative Style, High-Performance Deep Learning Library · Paszke et al.
    The design rationale for eager execution, the caching allocator and the autograd engine; read Sections 4-5.
  • TensorFlow: A system for large-scale machine learning · Abadi et al.
    The dataflow-graph alternative to eager mode; compare its graph model with your lazy mode.
  • LazyTensor: combining eager execution with domain-specific compilers · Alex Suhan et al.
    How PyTorch/XLA traces eager code into graphs for a compiler, the same idea as your lazy project at production scale.
  • Array programming with NumPy · Harris et al. (Nature 2020)
    Figure 1 is the best one-page explanation of strides, views and broadcasting.
  • TinyTorch: Building Machine Learning Systems from First Principles · Vijay Janapa Reddi et al.
    The 2026 paper describing TinyTorch's pedagogy (progressive disclosure, systems-first milestones); read it for how to sequence framework-building assignments.

Books

  • Build a Simple Deep Learning Library · zekcrates
    Free online book building a PyTorch-like library in NumPy (autograd, dataloaders, CNNs, ResNets); a gentler path for learners who stall on needle.
